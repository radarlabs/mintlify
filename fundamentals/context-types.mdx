Each time Radar processes a location update, it works out where the user is in several different terms and writes the answer to the user. Each of those is a context type. When a context type's value changes from one update to the next, Radar generates an event, such as `user.entered_geofence`.

Context is the user's current state. Events are the transitions between states. Read context to decide what to show now, and use events to trigger something once.

| Context type | What it represents | How you turn it on | User fields |
| --- | --- | --- | --- |
| [Geofences](#geofences) | Locations you define, such as stores, venues, or delivery zones. | Create geofences. | `geofences` |
| [Places](#places) | Points of interest from Radar's place dataset, grouped by chain and category. | Turn on Places and choose chains and categories. | `place` |
| [Regions](#regions) | The country, state, DMA, and postal code that contain the user. | Turn on Regions and the region event types you need. | `country`, `state`, `dma`, `postalCode` |
| [Beacons](#beacons) | Bluetooth beacons you registered that the device can hear. | Register beacons and turn on beacon ranging in a tracking call. | `beacons` |
| [Fraud](#fraud) | Whether the location and device can be trusted. | Turn on Fraud and request a verified location check. | `fraud` |
| [Trips](#trips) | One journey to a destination, with a status and a live ETA. | Start a trip. | `trip` |
| [User insights](#user-insights) | Whether the user is at home, at work, traveling, or commuting. | Enabled for your project by Radar. | `locationInsights` |

A field appears on the user only when its context type is turned on for the project and has a value for that location. You turn event types on or off on the [Settings](https://dashboard.radar.com/settings) page. Places, Regions, and Beacons depend on your plan.

## Geofences

A geofence is a location you define: a store, a venue, a delivery zone, or a job site. It is a circle, a polygon, or an isochrone, which is the area within a given travel time of a point. You identify each geofence with a `tag` (a group, such as `store`) and an `externalId` (your own ID, such as `store-42`).

The user's `geofences` field lists every geofence that contains the user's current location:

```json
{
  "geofences": [
    {
      "_id": "56db1f4613012711002229f5",
      "tag": "store",
      "externalId": "store-42",
      "description": "Store 42",
      "metadata": {
        "curbside": true
      }
    }
  ]
}
```

Events: `user.entered_geofence`, `user.exited_geofence`, and `user.dwelled_in_geofence` when you turn it on for the project and set a `dwellThreshold` on the geofence.

See [Create geofences](/geofencing/geofences-and-places#create-geofences).

## Places

A place is a point of interest from Radar's place dataset, such as a coffee shop, an airport, or a stadium. A place has one or more categories, and it can belong to a chain. Use geofences for locations you operate, and Places for locations you don't. For the supported values, see the lists of [place chains](/places/chains) and [place categories](/places/categories).

The user's `place` field is the one place the user is at, or is absent when there is none:

```json
{
  "place": {
    "name": "Example Coffee",
    "chain": {
      "name": "Example Coffee",
      "slug": "example-coffee",
      "externalId": "123",
      "metadata": {
        "segment": "partner"
      }
    },
    "categories": ["food-beverage", "coffee-shop"],
    "location": {
      "type": "Point",
      "coordinates": [-73.977797, 40.783826]
    }
  }
}
```

`chain.externalId` and `chain.metadata` are values you map to a chain in settings.

Events: `user.entered_place`, when the user stops at a place that matches your chains and categories, `user.exited_place`, and `user.nearby_place_chain`, only when nearby place chains are enabled for your project by Radar.

See [Enable Places](/geofencing/geofences-and-places#enable-places).

## Regions

A region is an administrative area from Radar's boundary dataset. You don't create anything.

| Region | Coverage | User field | Supported values |
| --- | --- | --- | --- |
| Country | Global | `country` | [Countries](/regions/countries) |
| State | United States and Canada | `state` | [States](/regions/states) |
| DMA | United States | `dma` | [DMAs](/regions/dmas) |
| Postal code | United States | `postalCode` | US ZIP codes |

Each region field has a `code` and a `name`:

```json
{
  "country": {
    "code": "US",
    "name": "United States"
  },
  "state": {
    "code": "MD",
    "name": "Maryland"
  },
  "dma": {
    "code": "26",
    "name": "Baltimore"
  },
  "postalCode": {
    "code": "21014",
    "name": "21014"
  }
}
```

Events: `user.entered_region_country` and `user.exited_region_country`, and the same pair for `state`, `dma`, and `postal_code`.

On a verified location check, `country` and `state` also carry the jurisdiction result for that check. See [Country and state fields](/api/geolocation-tokens#country-and-state-fields).

## Beacons

A beacon is a Bluetooth device you install and register with Radar. Beacons work like small geofences for areas that GPS can't resolve: a floor, a counter, a drive-thru lane, or a parking space. Your app turns on beacon ranging in a tracking call on iOS or Android. The web SDK doesn't range beacons.

The user's `beacons` field lists the registered beacons the device heard during the most recent update:

```json
{
  "beacons": [
    {
      "_id": "64f0a1b2c3d4e5f6a7b8cc01",
      "type": "ibeacon",
      "uuid": "b9407f30-f5f8-466e-aff9-25556b57fe6d",
      "major": "100",
      "minor": "1",
      "description": "Store 42 - Register 1",
      "tag": "store-register",
      "externalId": "store-42-register-1",
      "enabled": true
    }
  ]
}
```

Events: `user.entered_beacon` and `user.exited_beacon`.

See [Track indoor location with beacons](/geofencing/beacons).

## Fraud

Fraud context reports whether Radar can trust the location and the device behind it. Radar checks for a mocked or spoofed location, movement that is too far too fast, a known proxy or VPN, screen sharing or remote control, a compromised device or app, and a location that is too inaccurate to rely on. Your app requests the checks with `Radar.trackVerified()`.

<Info>
  Fraud is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

The user's `fraud` field has one boolean flag for each check, the overall result in `passed`, and the last time each flag was raised:

```json
{
  "fraud": {
    "verified": true,
    "passed": false,
    "bypassed": false,
    "blocked": false,
    "mocked": true,
    "jumped": false,
    "compromised": false,
    "inaccurate": false,
    "proxy": false,
    "sharing": false,
    "lastMockedAt": "2026-07-27T17:18:28.536Z",
    "lastJumpedAt": null,
    "lastCompromisedAt": null,
    "lastInaccurateAt": null,
    "lastProxyAt": null,
    "lastSharingAt": null
  }
}
```

`verified` is `true` when the update came from a verified location check. `passed` is `true` when all fraud checks passed. `blocked` and `bypassed` report that a block or bypass rule matched, and they override the other flags.

Events: none. Read `passed` and `failureReasons` in the geolocation token, and make eligibility decisions on your backend from a validated token, not from flags read in the app.

See [Fraud fields](/api/geolocation-tokens#fraud-fields).

## Trips

A trip is one journey by a user to a destination, such as a customer driving to pick up an order. While a trip is active, Radar calculates an ETA from each location update and moves the trip through its statuses.

The user's `trip` field is the active trip. It is present while the trip's `status` is `started`, `approaching`, or `arrived`:

```json
{
  "trip": {
    "_id": "5f3e50491c2b7d005c81f5d9",
    "status": "approaching",
    "externalId": "order-789",
    "mode": "car",
    "destinationGeofenceTag": "store",
    "destinationGeofenceExternalId": "store-42",
    "eta": {
      "duration": 2.9,
      "distance": 840
    }
  }
}
```

`eta.duration` is in minutes and `eta.distance` is in meters.

Events: `user.started_trip`, `user.updated_trip`, `user.approaching_trip_destination`, `user.arrived_at_trip_destination`, `user.stopped_trip`, and `user.arrived_at_wrong_trip_destination` when you turn it on for the project.

See [Track pickups, deliveries, and workers](/geofencing/trips).

## User insights

User insights use a user's recurring stopped locations to infer likely home and work areas, then report whether the user is at home, at work, traveling, or commuting.

<Info>
  User insights must be enabled for your project. Contact your Radar account team.
</Info>

The user's `locationInsights` field has one boolean for each state. Radar omits the field until it has enough location history to infer a home or work area:

```json
{
  "locationInsights": {
    "atHome": true,
    "atWork": false,
    "traveling": false,
    "commuting": false
  }
}
```

Events: `user.entered_home` and `user.exited_home`, `user.entered_work` and `user.exited_work`, `user.started_traveling` and `user.stopped_traveling`, and `user.started_commuting` and `user.stopped_commuting`.

See [Location insights](/api/users#location-insights).

## How context reaches you

Every context type is written to the same user object, so you read all of them in the same places.

| Where | What you get |
| --- | --- |
| `Radar.trackOnce()` and `Radar.startTracking()` | The updated user and the events from that update. |
| `Radar.trackVerified()` | The user with `fraud`, and a signed token that your backend validates. See [Geolocation token schema](/api/geolocation-tokens). |
| `Radar.getContext()` and `GET /v1/context` | Geofences, places, and regions for a coordinate, without creating or updating a user and without generating events. |
| `POST /v1/track` | The updated user and the events generated, for a location you send. See [Track](/api/tracking#track). |
| `GET /v1/users/:id` | The user's most recent context, read from your backend. See [User object](/api/users#user-object). |
| [Webhooks](/integrations/webhooks) and event integrations | The events from one update and the user's state after that update. See [Event object](/api/events#event-object). |
