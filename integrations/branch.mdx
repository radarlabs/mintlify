<Info>
  The Branch integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar's servers send each Radar event to Branch as a custom event on the matching device, so that you can attribute offline actions, such as store visits, to the campaigns that Branch tracks.

## Prerequisites

- A Radar project that generates events.
- A Branch app and its Branch key.
- The Branch SDK in the same app or site as the Radar SDK, so that Branch already knows the devices that Radar reports.

## Configuration

1. In Branch, open **Account Settings**, select **Profile**, and copy your Branch key. Branch provides a live key and a test key.
2. On the [Integrations](https://dashboard.radar.com/integrations) page, find the **Branch** section, select **Yes** for **Enabled**, enter the keys in **Live branch key** and **Test branch key**, and click **Save**.

## Identity mapping

Branch matches events to devices, not to your user IDs. Radar doesn't send the Radar `userId`. It sends these identifiers in the `user_data` of each event:

| Radar user field | Branch `user_data` field | Sent when |
| --- | --- | --- |
| `deviceType` | `os` | The device type is `iOS`, `Android`, or `Web`. |
| `deviceId` | `idfv` | The device type is iOS. |
| `deviceId` | `android_id` | The device type is Android. |
| Advertising ID | `idfa` (iOS) or `aaid` (Android) | Radar has an advertising ID for the device and the user hasn't opted out. |
| `metadata.branchFingerprintId` | `browser_fingerprint_id` | The device type is Web. |
| `ip` | `ip` | Radar has an IP address for the user. |
| `locationAuthorization` | `radar_location_authorization` | Always. `"(null)"` when unknown. |
| `locationAccuracyAuthorization` | `radar_location_accuracy_authorization` | Always. `"(null)"` when unknown. |

iOS and Android need no extra code. On the web, pass the Branch browser fingerprint ID to Radar after both SDKs are initialized:

```javascript
// Assumes the Branch web SDK and the Radar web SDK are already initialized.
branch.getBrowserFingerprintId(function (err, fingerprintId) {
  if (err || !fingerprintId) {
    return;
  }
  Radar.setMetadata({ branchFingerprintId: fingerprintId });
});
```

Until `metadata.branchFingerprintId` is set, Radar skips events from web users and logs `Identifier missing.` The same applies to any user whose device type isn't iOS, Android, or Web.

Besides the shared [filters](/integrations/integrations#filters), Branch has **Chain blocklist**, which skips place events for the listed chain slugs and logs `Chain '...' is blocklisted.`

Radar sends one request per event to Branch's HTTP API for custom events. Events from one update are sent in parallel, so Branch can receive them in any order. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Create a geofence in the Radar Test environment. Run a test build of your app that has the Branch SDK with the Branch test key and the Radar SDK with your Test publishable key, and enter the geofence or simulate a location inside it.

In the **Branch** section, **View integration logs** shows the request with a success response and the Branch key redacted. In the request, `name` is `entered_geofence` and `user_data` has the `idfv` or `android_id` of your test device. In Branch's test environment, the `entered_geofence` custom event has your geofence's `geofence_external_id` in its custom data.

You can also generate the event with the [Tracking API](/api/tracking) by sending `deviceType=iOS` or `deviceType=Android`. Branch attributes the event only if the `deviceId` you send is an identifier that Branch has already seen. For skipped and rejected requests, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

- Radar sends events to Branch, not user properties. It doesn't create or update Branch user profiles beyond the device identifiers on each event.
- Region context is included on geofence and place events only.
- Radar doesn't send a deduplication ID to Branch.
