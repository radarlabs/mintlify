<Info>
  The Branch integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

By the end of this page, each Radar event for your project arrives in Branch as a custom event on the matching device, so that you can attribute location activity to the campaigns that Branch tracks.

Use the integration to attribute offline actions, such as store visits, to online campaigns. It is a server-side integration: Radar's servers call Branch. Radar sends events only. It doesn't create or update Branch user profiles beyond the device identifiers on each event.

## Prerequisites

- A Radar project on the Enterprise plan that generates events. See [Geofencing overview and quickstart](/geofencing/overview).
- Access to the [Integrations](https://dashboard.radar.com/integrations) page in the Radar dashboard.
- A Branch app and permission to view its Branch key.
- The Branch SDK in the same app or site as the Radar SDK, so that Branch already knows the devices that Radar reports. For web, you also need the code in [User mapping](#user-mapping).

## Configuration

<Steps>
  <Step title="Copy your Branch key">
    In Branch, open **Account Settings**, select **Profile**, and copy your Branch key. Branch provides a live key and a test key. Copy both if you use both environments.
  </Step>
  <Step title="Enable the integration in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, find the **Branch** section and select **Yes** for **Enabled**. Credential fields appear.
  </Step>
  <Step title="Enter your keys">
    Enter the Branch live key in **Live branch key** and the Branch test key in **Test branch key**. Radar uses the Live key for events from the Radar Live environment and the Test key for events from the Radar Test environment. If you leave a field empty, Radar sends nothing for that environment.
  </Step>
  <Step title="Save">
    Click **Save**. From now on, Radar sends each new event to Branch. Events generated before you saved aren't sent.
  </Step>
</Steps>

## User mapping

Branch matches events to devices, not to your user IDs. Radar sends these identifiers in the `user_data` of each event:

| Radar user field | Branch `user_data` field | Sent when |
| --- | --- | --- |
| `deviceType` | `os` | The device type is `iOS`, `Android`, or `Web`. |
| `deviceId` | `idfv` | The device type is iOS. |
| `deviceId` | `android_id` | The device type is Android. |
| Advertising ID | `idfa` (iOS) or `aaid` (Android) | Radar has an advertising ID for the device and the user hasn't opted out. |
| `metadata.branchFingerprintId` | `browser_fingerprint_id` | The device type is Web. |
| `ip` | `ip` | Radar has an IP address for the user. |
| `locationAuthorization` | `radar_location_authorization` | Always. `"(null)"` when unknown. |
| `locationAccuracyAuthorization` | `radar_location_accuracy_authorization` | Always. `"(null)"` when unknown. |

Radar doesn't send the Radar `userId` to Branch.

On iOS and Android, no extra code is needed. On the web, Radar has no device identifier that Branch recognizes, so you must pass the Branch browser fingerprint ID to Radar. Do this after both SDKs are initialized:

```javascript
// Assumes the Branch web SDK and the Radar web SDK are already initialized.
branch.getBrowserFingerprintId(function (err, fingerprintId) {
  if (err || !fingerprintId) {
    return;
  }
  Radar.setMetadata({ branchFingerprintId: fingerprintId });
});
```

Until `metadata.branchFingerprintId` is set, Radar skips events from web users for Branch and logs `Identifier missing.` The same applies to any user whose device type isn't iOS, Android, or Web.

## Filtering

On the [Integrations](https://dashboard.radar.com/integrations) page, click **Show advanced** in the **Branch** section.

| Field | Effect |
| --- | --- |
| **Event type allowlist** | When you select one or more event types, Radar sends only those types to Branch. With nothing selected, Radar sends every event type. |
| **Request key blocklist (comma-separated)** | Removes the listed keys from the request at any depth. For example, `ip,geofence_id` removes the IP address from `user_data` and the geofence ID from the custom data. |
| **Geofence tag blocklist (comma-separated)** | Skips events for geofences that have one of the listed tags. |
| **Chain blocklist** | Skips place events for the listed chain slugs. |

Radar forwards every event type that passes the filters, including types that aren't in the [event mapping](#event-mapping) table. To keep unmapped event types out of Branch, select only the types you want in **Event type allowlist**.

## Delivery behavior

- **Requests**: Radar sends one request to Branch per event, using Branch's HTTP API for custom events. When one Radar update generates several events, the requests are sent in parallel, so Branch can receive them in any order.
- **Timing**: Radar sends events from its servers shortly after it generates them.
- **Attempts**: Radar makes one delivery attempt per event and waits up to 5 seconds for Branch to respond. It doesn't retry a failed request. Use the [integration logs](#troubleshoot-delivery) to find failures, and the [Events API](/api/events) if you need to backfill.
- **Deduplication**: Radar doesn't send a deduplication ID to Branch.
- **Environment**: The event's environment selects the key. Radar doesn't send a Test event with the Live key or the reverse.

## Test the integration

<Steps>
  <Step title="Use the Test environment">
    Confirm that **Test branch key** holds your Branch test key and that the integration is saved with **Enabled** set to **Yes**.
  </Step>
  <Step title="Generate an event from a device that Branch knows">
    Create a geofence in the Radar Test environment. Then run a test build of your app that includes both the Branch SDK, using the Branch test key, and the Radar SDK, using your Radar Test publishable key. Enter the geofence, or simulate a location inside it, so that Radar generates a `user.entered_geofence` event. Confirm the event on the Events page of the Radar dashboard.
  </Step>
  <Step title="Check Radar's log">
    In the **Branch** section, click **View integration logs**. Find a row for the event with the request that Radar sent and a success response from Branch. In the request, confirm that `name` is `entered_geofence` and that `user_data` has the `idfv` or `android_id` of your test device.
  </Step>
  <Step title="Check Branch">
    In Branch, switch to the test environment and look for the `entered_geofence` custom event from your test device, with the `geofence_external_id` of your geofence in its custom data.
  </Step>
</Steps>

You can also generate the Radar event with the [Tracking API](/api/tracking) by sending `deviceType=iOS` or `deviceType=Android`. Branch attributes the event only if the `deviceId` you send is an identifier that Branch has already seen.

## Troubleshoot delivery

On the [Integrations](https://dashboard.radar.com/integrations) page, click **View integration logs** in the **Branch** section. Each row shows the request and Branch's response. Radar redacts the Branch key in the logged request.

| What you see | Likely cause | What to do |
| --- | --- | --- |
| No rows | No events were generated in that environment, or the integration isn't saved as enabled. | Check the Events page for the environment and the **Enabled** setting. |
| `skipped`: `Integration key(s) missing.` | The Branch key for the event's environment is empty. | Enter the **Test branch key** or **Live branch key**. |
| `skipped`: `Identifier missing.` | The user is a web user without `metadata.branchFingerprintId`, or has no device type. | Set the fingerprint ID as described in [User mapping](#user-mapping). For API-created users, send `deviceType`. |
| `skipped`: `Event type ... is not allowed.` | The event type isn't selected in **Event type allowlist**. | Select the type or clear the allowlist. |
| `skipped`: `Geofence tag '...' is blocklisted.` or `Chain '...' is blocklisted.` | A blocklist excluded the event. | Remove the tag or chain from the blocklist. |
| A `4xx` response | Branch rejected the request. | Read the response body in the log, and check that the Branch key matches the environment. |
| A success response but no attributed event in Branch | Branch doesn't recognize the device identifier. | Confirm that the Branch SDK has run on the same device, and compare the identifiers in the logged request with the device in Branch. |

## Limitations

- Radar sends events to Branch, not user properties.
- Events are matched by device identifiers. The Radar `userId` isn't sent.
- Web users need `metadata.branchFingerprintId`, and users with no device type are skipped.
- Region context is included on geofence and place events only.
- Radar doesn't retry failed deliveries to Branch and doesn't send a deduplication ID.
- You can't rename events or custom data keys. Use the request key blocklist to drop keys you don't want.
- Events generated before you enabled the integration aren't sent.
