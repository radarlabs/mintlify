<Info>
  The Segment integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar is a source in Segment: each Radar update that generates events produces an `identify` call with location traits and a `track` call per event.

## Prerequisites

- A Radar project that generates events.
- A Segment workspace where you can add a source.
- A user ID shared by both systems.

## Configuration

1. In Segment, add Radar as a source and copy its write key. Repeat for a development source to keep Test events out of production destinations.
2. On the [Integrations](https://dashboard.radar.com/integrations) page, find the **Segment** section, select **Yes** for **Enabled**, enter the keys in **Live write key** and **Test write key**, and click **Save**.
3. In Segment, connect the Radar source to your warehouse and destinations.

## Identity mapping

| Segment field | Value Radar sends |
| --- | --- |
| `userId` | `metadata.segmentUserId` when set. Otherwise the Radar `userId`. Omitted when the user has neither. |
| `anonymousId` | `metadata.segmentAnonymousId` when set. Otherwise the Radar `deviceId`. |

The Radar device ID isn't the anonymous ID that the Segment SDK generates. To join logged-out Radar events to that anonymous user, or to send a Segment user ID that differs from the Radar `userId`, set the metadata keys:

<CodeGroup>

```swift Swift
import RadarSDK

// Logged-out users: anonymousId is the Segment SDK's anonymous ID.
Radar.setMetadata(["segmentAnonymousId": anonymousId])

// Logged-in users whose Segment userId differs from the Radar userId.
Radar.setMetadata(["segmentUserId": userId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// Logged-out users: anonymousId is the Segment SDK's anonymous ID.
Radar.setMetadata(JSONObject().put("segmentAnonymousId", anonymousId))

// Logged-in users whose Segment userId differs from the Radar userId.
Radar.setMetadata(JSONObject().put("segmentUserId", userId))
```

</CodeGroup>

Radar also fills the batch `context`:

| Radar user field | Segment context field | Sent when |
| --- | --- | --- |
| `deviceId` | `context.device.id` | The user has a `deviceId`. |
| `deviceType` | `context.device.type` | The user has a device type. Lowercased, for example `ios`. |
| Advertising ID | `context.device.advertisingId`, with `context.device.adTrackingEnabled` set to `true` | The device is iOS or Android, Radar has an advertising ID, and the user hasn't opted out. |
| `location.coordinates` | `context.location.latitude`, `context.location.longitude` | Always. |

For each update, Radar sends one request to `https://api.segment.io/v1/batch` with the `identify` call first, then one `track` call per event. Events that have no location aren't sent, except trip events. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Create a geofence in the Test environment, then send a location inside it:

```bash
curl "https://api.radar.io/v1/track" \
  -H "Authorization: prj_test_pk_..." \
  -X POST \
  -d "deviceId=test-device-1" \
  -d "userId=user-123" \
  -d "latitude=40.78382" \
  -d "longitude=-73.97536" \
  -d "accuracy=10"
```

The response includes a `user.entered_geofence` event. In the **Segment** section, **View integration logs** shows the batch with a `200` response. The debugger for your Test source in Segment shows an `identify` call for `user-123` with `radar_geofence_external_ids`, then a `Geofence Entered` track call with your geofence's `geofence_external_id`.

If events land on the wrong Segment user, compare `userId` and `anonymousId` in the logged request with your app's Segment calls. Otherwise, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

The integration has no setting for the Segment ingestion endpoint.
