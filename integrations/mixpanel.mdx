---
title: "Mixpanel"
description: "Send Radar events and user profile properties to Mixpanel, map Radar users to Mixpanel distinct IDs, and verify that events arrive."
---

<Info>
  The Mixpanel integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar's servers send each Radar event for an identified user to Mixpanel as a `Radar` event on that user's profile, with [location context](/fundamentals/context-types) as profile properties.

## Prerequisites

- A Radar project that generates events.
- A Mixpanel project and its project token. Use a separate project for testing if you have one.
- A Mixpanel distinct ID for each user. Radar skips events for users that have none.

## Configuration

1. In Mixpanel, open **Project Settings** and copy the project token from the access keys section.
2. On the [Integrations](https://dashboard.radar.com/integrations) page, find the **Mixpanel** section, select **Yes** for **Enabled**, enter the production token in **Live token** and the development token in **Test token**, and click **Save**.

## Identity mapping

The Mixpanel distinct ID is `metadata.mixpanelDistinctId` when it is set on the Radar user, and otherwise the Radar `userId`. If the user has neither, Radar skips the user's events and logs `Identifier missing.` It doesn't fall back to the device ID.

If your Mixpanel distinct ID differs from the Radar `userId`, set it after you initialize the SDK and whenever it changes:

<CodeGroup>

```swift Swift
import RadarSDK

// distinctId is the value your app uses as the Mixpanel distinct ID.
Radar.setMetadata(["mixpanelDistinctId": distinctId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// distinctId is the value your app uses as the Mixpanel distinct ID.
Radar.setMetadata(JSONObject().put("mixpanelDistinctId", distinctId))
```

</CodeGroup>

## Test the integration

Create a geofence in the Test environment, then send a location inside it with a `userId`:

```bash
curl "https://api.radar.io/v1/track" \
  -H "Authorization: prj_test_pk_..." \
  -X POST \
  -d "deviceId=test-device-1" \
  -d "userId=user-123" \
  -d "latitude=40.78382" \
  -d "longitude=-73.97536" \
  -d "accuracy=10"
```

The response includes a `user.entered_geofence` event. In the **Mixpanel** section, **View integration logs** shows an `/engage/` row and a `/track/` row, each with a `200` response and the token redacted. In Mixpanel, the profile with distinct ID `user-123` has a `Radar Geofence Entered` event with your geofence's `Geofence External ID`, and `Radar Geofence External IDs` among the profile properties.

If the event is on the wrong profile, compare `distinct_id` in the logged request with the profile, and check the token. Otherwise, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

- Radar doesn't send events that have no location, and doesn't send a deduplication ID.
- The integration has no setting for the Mixpanel ingestion endpoint.
