<Info>
  The Iterable integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar sends a custom event to [Iterable](https://iterable.com) for each location event it generates, and updates the user's Radar data fields.

## Prerequisites

- A Radar project on the Enterprise plan that is [generating events](/geofencing/geofences-and-places).
- An Iterable project where you can create API keys.
- Users identified in Iterable by `userId`. Radar sends a `userId`, not an email address.

## Configuration

<Steps>
  <Step title="Create an Iterable API key">
    In Iterable, open the **API Keys** page and create a Mobile API key. Create a second key in your test project if you keep test data separate.
  </Step>
  <Step title="Enter the keys in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, select **Yes** for **Enabled** in the **Iterable** section, enter the keys in **Live API key** and **Test API key**, and click **Save**.
  </Step>
</Steps>

## Identity mapping

Radar uses the first of these values that is set. If neither is, it skips the event with `Identifier missing.`

| Radar value | Sent to Iterable as |
| --- | --- |
| `metadata["iterable:user_id"]` | `userId` |
| `userId` | `userId` |

The simplest setup uses the same ID in both SDKs:

<CodeGroup>

```swift Swift
import RadarSDK

// The Iterable call depends on your Iterable SDK version.
IterableAPI.userId = userId
Radar.setUserId(userId)
```

```kotlin Kotlin
import io.radar.sdk.Radar

// The Iterable call depends on your Iterable SDK version.
IterableApi.getInstance().setUserId(userId)
Radar.setUserId(userId)
```

</CodeGroup>

If the IDs differ, set the Iterable user ID in Radar metadata:

<CodeGroup>

```swift Swift
import RadarSDK

Radar.setMetadata(["iterable:user_id": iterableUserId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

Radar.setMetadata(JSONObject().put("iterable:user_id", iterableUserId))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object. Update the user ID or metadata when the user logs out or changes.

For example, to send a push when a user enters a store geofence, trigger an Iterable journey from `radarGeofenceEntered`, filter on `radarGeofenceEntered.geofenceTag`, and put `{{radarGeofenceEntered.geofenceDescription}}` in the template.

To limit what Radar sends, see [Filters](/integrations/integrations#filters).

Radar sends one `users/update` request and one `events/track` request per event, in parallel, so an event can reach Iterable before the user update does. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Move a user whose `userId`, or `iterable:user_id` metadata, matches an Iterable user into a geofence with the [Simulator](https://dashboard.radar.com/geofencing/simulate), then click **View** on the new event on the **Events** page. Its **Logs** section shows requests to `users/update` and `events/track`, each with a `2xx` response, and the Iterable user shows the `radarGeofenceEntered` event and the `radarGeofenceTags` data field. If not, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

Radar sends to `https://api.iterable.com/api`. There is no setting for another Iterable API host.
