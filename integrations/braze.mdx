<Info>
  The Braze integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

By the end of this page, Radar sends a custom event and updated user attributes to [Braze](https://www.braze.com) each time it generates a location event for a user, and you have confirmed delivery for one test user.

Radar sends this data from its servers to the Braze `/users/track` endpoint. Your app doesn't need extra code unless you change the default identity mapping or want [in-app messaging](#in-app-messaging).

## Prerequisites

- A Radar project on the Enterprise plan, with the Radar SDK generating events. See [Detect geofence events and place visits](/geofencing/geofences-and-places).
- A Braze workspace, with permission to create REST API keys.
- The Braze SDK in your app, so the users Radar updates also exist in Braze.
- A user identifier shared by both systems. See [Identity mapping](#identity-mapping).

## Configuration

<Steps>
  <Step title="Create a Braze API key">
    In Braze, open the **API Keys** page. Under **Rest API Keys**, create a workspace API key with the `users.track` permission and copy it. Under **Identification** on the same page, copy the app identifiers for your iOS and Android apps.
  </Step>
  <Step title="Enter the keys in Radar">
    In the Radar dashboard, open the [Integrations](https://dashboard.radar.com/integrations) page, find the **Braze** section, and select **Yes** for **Enabled**. Enter these values:

    | Field | Value |
    | --- | --- |
    | **API endpoint** | Your Braze REST endpoint. The default is `https://rest.iad-01.braze.com`. Select another endpoint if your Braze account is on a different instance. |
    | **Live app group API key** | The REST API key for the Live environment. |
    | **Live iOS app identifier**, **Live Android app identifier** | The Braze app identifiers for your production apps. |
    | **Test app group API key**, **Test iOS app identifier**, **Test Android app identifier** | The same values for the Braze workspace that receives data from the Test environment. If you leave the Test API key empty, Radar uses the Live API key for events from the Test environment. |

    Click **Save**.
  </Step>
  <Step title="Set the identity mapping in your app">
    If your Radar `userId` isn't the Braze `external_id`, or you need to reach logged-out users, set the metadata described in [Identity mapping](#identity-mapping).
  </Step>
</Steps>

Radar chooses the app identifier from the device that generated the event: iOS devices use the iOS app identifier and Android devices use the Android app identifier. Both an API key and an app identifier for the device's platform and environment must be present, or Radar skips the event.

## Identity mapping

Radar picks the Braze identifier for each user in this order:

| Priority | Radar value | Sent to Braze as |
| --- | --- | --- |
| 1 | `metadata.brazeExternalId` | `external_id` |
| 2 | `metadata.brazeAlias` | A user alias with `alias_label` `radarAlias` and `alias_name` set to the value |
| 3 | `userId` | `external_id` |

If none of these is set, Radar skips the event and logs `Identifier missing.`

- **Logged-in users, same ID in both systems**: Call `Radar.setUserId()` with the ID you pass to Braze as the external ID. Nothing else is needed.
- **Logged-in users, different IDs**: Set `metadata.brazeExternalId` to the Braze external ID.
- **Logged-out users**: Set `metadata.brazeAlias` to a stable value such as a device ID, and add an alias with the same name and the label `radarAlias` to the user through the Braze SDK. Without the matching alias in Braze, the data doesn't attach to the user you expect.

These examples set the alias and the external ID in Radar metadata:

<CodeGroup>

```swift Swift
import RadarSDK

// Logged-out user: alias. Also add the alias in Braze with the label "radarAlias".
Radar.setMetadata(["brazeAlias": deviceId])

// Logged-in user whose Braze external ID differs from the Radar user ID.
Radar.setMetadata(["brazeExternalId": brazeExternalId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// Logged-out user: alias. Also add the alias in Braze with the label "radarAlias".
Radar.setMetadata(JSONObject().put("brazeAlias", deviceId))

// Logged-in user whose Braze external ID differs from the Radar user ID.
Radar.setMetadata(JSONObject().put("brazeExternalId", brazeExternalId))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object, so include any other metadata keys you use in the same call. When a user logs in or out, update the metadata so events stop going to the previous identity.

## Filtering

On the [Integrations](https://dashboard.radar.com/integrations) page, click **Show advanced** in the **Braze** section.

| Setting | Effect |
| --- | --- |
| **Event type allowlist** | Radar sends only the selected event types. Check this list first when an event you expect is missing. |
| **Request key blocklist** | Comma-separated keys to remove from the request, for example `radar_geofence_ids,geofence_id`. Applies to user attributes and event properties. |
| **Geofence tag blocklist** | Comma-separated geofence tags. Radar skips events for geofences with these tags. |
| **Place chain blocklist**, **Place category blocklist** | Radar skips place events for these chains and categories. |
| **Update existing users only** | When **Yes**, Radar asks Braze to update only users that already exist, instead of creating new user profiles. |

For the filters that every event integration shares, see [Filters](/integrations/integrations#filters).

## Delivery behavior

- Radar sends to Braze only when it generates an event for the user. A location update that produces no event doesn't update Braze user attributes.
- Events generated by one location update are sent together in one request, with the user attributes.
- Delivery is asynchronous. It follows the Radar event by a short delay and doesn't block the SDK.
- Radar sends each request once. It doesn't retry a request that Braze rejects or that times out. The outcome is recorded in the integration logs.
- Events without a location aren't sent.
- Events from the Test environment use the Test keys, and events from the Live environment use the Live keys.

## Troubleshoot delivery

Click **View integration logs** in the **Braze** section of the [Integrations](https://dashboard.radar.com/integrations) page. Each row shows the timestamp, the request URL, and the response code, and expands to the request and response bodies. API keys are redacted. New rows can take a few minutes to appear.

| Log response | Meaning |
| --- | --- |
| `skipped`: `Integration key(s) missing.` | No API key or no app identifier for this device platform and environment. |
| `skipped`: `Identifier missing.` | The user has no `userId`, `metadata.brazeExternalId`, or `metadata.brazeAlias`. |
| `skipped`, "Event type ... isn't allowed." | The event type isn't selected in the allowlist. |
| `skipped`: `Geofence tag '...' is blocklisted.` | The geofence tag is in the blocklist. |
| A `4xx` response | Braze rejected the request. The response body in the log gives the reason. Check that the API key belongs to the selected API endpoint and has the `users.track` permission. |
| `2xx`, but no data on the user in Braze | The identifier doesn't match a Braze user. Check the external ID or alias, and the **Update existing users only** setting. |

## Example use cases

### Send a personalized push notification when a user arrives at a store

1. Create [geofences](/geofencing/geofences-and-places) in Radar with the tag `store`.
2. In Braze, create a campaign triggered by the `entered_geofence` custom event, with a property filter where `geofence_tag` is `store`. The same event works as a [Canvas](https://www.braze.com/docs/user_guide/engagement_tools/canvas) entry, and the event properties are available for personalization with [Liquid](https://www.braze.com/docs/user_guide/personalization_and_dynamic_content/liquid).

### Message all users nearby a store

1. Create geofences in Radar that cover the area around each store, with the tag `nearby-store`.
2. In Braze, create a campaign that targets users whose `radar_geofence_tags` attribute includes `nearby-store`. This attribute lists the tags of every geofence the user is in. To avoid stale audiences, also filter on `radar_updated_at`, for example to users updated in the last hour.

### Send on-trip messages for pickups

Trigger a campaign or Canvas from `approaching_trip_destination` or `arrived_at_trip_destination`, and filter on `trip_destination_geofence_tag` or a `trip_metadata_{key}` property. If you use Olo, the mapped order fields arrive as trip metadata. See [Olo pickup and order firing](/integrations/olo).

If Radar events reach Braze through mParticle instead of this integration, the attribute and event names come from the [mParticle integration](/integrations/mparticle), not from this page.

### In-app messaging

Braze evaluates in-app message triggers on the device, so a custom event sent from Radar's servers can't trigger an in-app message at app open. To trigger one from the user's location, log the event through the Braze SDK from Radar's location listener.

The examples below assume you call `Radar.trackOnce()` at app launch. They build the event name and properties and hand them to a function you implement with your version of the Braze SDK. The Braze call isn't shown because it differs between Braze SDK versions.

<CodeGroup>

```swift Swift
import CoreLocation
import RadarSDK

// Set this object as the Radar delegate.
class LocationEventForwarder: NSObject, RadarDelegate {
    // Implement with your Braze SDK's custom event call.
    var logBrazeEvent: (String, [String: Any]) -> Void = { _, _ in }

    func didUpdateLocation(_ location: CLLocation, user: RadarUser) {
        guard user.foreground, user.source == .foregroundLocation else { return }

        if let geofences = user.geofences, !geofences.isEmpty {
            logBrazeEvent("radar_fg_geofences_entered", [
                "radar_geofence_descriptions": geofences.map { $0.__description },
                "radar_geofence_tags": geofences.compactMap { $0.tag },
                "radar_geofence_external_ids": geofences.compactMap { $0.externalId }
            ])
        }
    }
}
```

```kotlin Kotlin
import android.content.Context
import android.location.Location
import io.radar.sdk.Radar
import io.radar.sdk.RadarReceiver
import io.radar.sdk.model.RadarEvent
import io.radar.sdk.model.RadarUser

// Register this receiver with the Radar SDK.
class LocationEventForwarder(
    // Implement with your Braze SDK's custom event call.
    private val logBrazeEvent: (name: String, properties: Map<String, Any>) -> Unit
) : RadarReceiver() {

    override fun onLocationUpdated(context: Context, location: Location, user: RadarUser) {
        if (!user.foreground || user.source != Radar.RadarLocationSource.FOREGROUND_LOCATION) return

        val geofences = user.geofences
        if (!geofences.isNullOrEmpty()) {
            logBrazeEvent(
                "radar_fg_geofences_entered",
                mapOf(
                    "radar_geofence_descriptions" to geofences.map { it.description },
                    "radar_geofence_tags" to geofences.mapNotNull { it.tag },
                    "radar_geofence_external_ids" to geofences.mapNotNull { it.externalId }
                )
            )
        }
    }

    override fun onEventsReceived(context: Context, events: Array<RadarEvent>, user: RadarUser?) {}
    override fun onClientLocationUpdated(context: Context, location: Location, stopped: Boolean, source: Radar.RadarLocationSource) {}
    override fun onError(context: Context, status: Radar.RadarStatus) {}
    override fun onLog(context: Context, message: String) {}
}
```

</CodeGroup>

`radar_fg_geofences_entered` is a name you choose. It is separate from the events Radar sends server-side.

## Limitations

- User attributes are updated only when an event is generated, so `radar_updated_at` can be older than the user's last location update.
- There is no automatic retry. A request that fails during a Braze outage isn't resent.
- The integration has app identifier fields for iOS and Android only.
- Radar doesn't create the `radarAlias` alias in Braze for you. Alias-only users must have the alias added through the Braze SDK.
- Events without a location, and event types not listed under [Event mapping](#event-mapping), aren't sent.
