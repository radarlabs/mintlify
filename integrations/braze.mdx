<Info>
  The Braze integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar sends a custom event and updated user attributes to [Braze](https://www.braze.com) each time it generates a location event.

## Prerequisites

- A Radar project on the Enterprise plan that is [generating events](/geofencing/geofences-and-places).
- A Braze workspace where you can create REST API keys, and the Braze SDK in your app.

## Configuration

<Steps>
  <Step title="Create a Braze API key">
    In Braze, open the **API Keys** page. Under **Rest API Keys**, create a workspace API key with the `users.track` permission. Under **Identification**, copy the iOS and Android app identifiers.
  </Step>
  <Step title="Enter the keys in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, select **Yes** for **Enabled** in the **Braze** section, enter these values, and click **Save**.

    | Field | Value |
    | --- | --- |
    | **API endpoint** | Your Braze REST endpoint. The default is `https://rest.iad-01.braze.com`. |
    | **Live app group API key** | REST API key for the Live environment. |
    | **Live iOS app identifier**, **Live Android app identifier** | App identifiers for your production apps. |
    | **Test app group API key**, **Test iOS app identifier**, **Test Android app identifier** | The same for the Test environment. With no Test API key, Radar uses the Live API key. |
  </Step>
</Steps>

## Identity mapping

Radar uses the first of these values that is set. If none is, it skips the event with `Identifier missing.`

| Radar value | Sent to Braze as | Use for |
| --- | --- | --- |
| `metadata.brazeExternalId` | `external_id` | A Braze external ID that differs from the Radar `userId`. |
| `metadata.brazeAlias` | A user alias with `alias_label` `radarAlias` and `alias_name` set to the value | Logged-out users. Also add the alias, labeled `radarAlias`, through the Braze SDK. |
| `userId` | `external_id` | Same ID in both, set with `Radar.setUserId()`. |

<CodeGroup>

```swift Swift
import RadarSDK

// Logged-out user: alias. Also add the alias in Braze with the label "radarAlias".
Radar.setMetadata(["brazeAlias": deviceId])

// Logged-in user whose Braze external ID differs from the Radar user ID.
Radar.setMetadata(["brazeExternalId": brazeExternalId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// Logged-out user: alias. Also add the alias in Braze with the label "radarAlias".
Radar.setMetadata(JSONObject().put("brazeAlias", deviceId))

// Logged-in user whose Braze external ID differs from the Radar user ID.
Radar.setMetadata(JSONObject().put("brazeExternalId", brazeExternalId))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object. Update it when a user logs in or out.

Events from one location update go in one request with the user attributes, and events without a location aren't sent. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Move a test user into a geofence with the [Simulator](https://dashboard.radar.com/geofencing/simulate), then click **View** on the new event on the **Events** page. Its **Logs** section shows a request to `/users/track` with a `2xx` response, and the Braze profile shows the `entered_geofence` event and the `radar_geofence_tags` attribute. If not, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

An event sent from Radar's servers can't trigger a Braze in-app message at app open. Log it through the Braze SDK from Radar's location listener.
