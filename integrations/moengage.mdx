---

<Info>
  The MoEngage integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar sends an event to [MoEngage](https://www.moengage.com/) for each location event it generates, and updates the user's Radar attributes.

## Prerequisites

- A Radar project on the Enterprise plan that is [generating events](/geofencing/geofences-and-places).
- A MoEngage workspace, with access to its **APIs** settings page.
- The MoEngage customer ID of each logged-in user, available in your app.

## Configuration

<Steps>
  <Step title="Copy your MoEngage credentials">
    In MoEngage, open the **APIs** page and copy your Workspace ID and Data API key. If you use a separate MoEngage test environment, copy its Data API key as well.
  </Step>
  <Step title="Enter the settings in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, select **Yes** for **Enabled** in the **MoEngage** section, enter these values, and click **Save**.

    | Field | Value |
    | --- | --- |
    | **API endpoint** | The Data API host for your MoEngage data center. The default is `https://api-01.moengage.com/v1`. |
    | **Test Data API key** | Required. Used for Test events. |
    | **Live Data API key** | Required. Used for Live events. |
    | **Workspace ID** | Required. Your MoEngage Workspace ID. For Test events, Radar appends `_DEBUG` to it in the request, so Test and Live events go to different MoEngage workspaces. |
    | **Update existing only** | When **Yes**, Radar asks MoEngage to update only users that already exist. |
  </Step>
</Steps>

## Identity mapping

Radar doesn't use the Radar `userId`. Set the metadata to the unique ID you pass to the MoEngage SDK when the user logs in.

| Radar value | Sent to MoEngage as | Required |
| --- | --- | --- |
| `metadata["moengage:customer_id"]` | `customer_id` on the event and customer requests | Yes. Without it, Radar skips the event and logs `Identifier missing.` |
| `deviceId` | `device_id` on the event request | Sent automatically |

<CodeGroup>

```swift Swift
import RadarSDK

Radar.setMetadata(["moengage:customer_id": "user-123"])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

Radar.setMetadata(JSONObject().put("moengage:customer_id", "user-123"))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object. Update it when the user logs out or changes.

## Test the integration

Set `moengage:customer_id` to the ID of a user that exists in MoEngage, move that user into a geofence with the [Simulator](https://dashboard.radar.com/geofencing/simulate), then click **View** on the new event on the **Events** page. Its **Logs** section shows two MoEngage requests, each with a `2xx` response, and the MoEngage profile, in the environment that matches the Radar environment, shows the `[Radar] Geofence Entered` event and the `radar_geofence_tags` attribute. If not, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

Top chain attributes aren't sent to MoEngage.
