<Info>
  The Salesforce Marketing Cloud integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>
Radar sends each location event to a data extension in [Salesforce Marketing Cloud](https://www.salesforce.com/products/marketing-cloud/overview/) as an API event, where it can trigger a journey in Journey Builder. Radar sends events only. It doesn't write Radar user attributes to Salesforce contacts.

## Prerequisites

- A Radar project on the Enterprise plan that is [generating events](/geofencing/geofences-and-places).
- A Salesforce Marketing Cloud account where you can create installed packages and edit the data model in Contact Builder.
- The Marketing Cloud contact key for each user, available in your app.

## Configuration

<Steps>
  <Step title="Create an installed package in Salesforce Marketing Cloud">
    In the Marketing Cloud **Setup** menu, open **Installed Packages** and click **New**. Enter `Radar` as the package name. Add an **API Integration** component with the **Server-to-Server** integration type, and grant all permissions for the **Automation**, **Contacts**, **Cross Cloud Platform**, and **Data** scopes. Copy the client ID, client secret, **Authentication Base URI**, and **REST Base URI**.
  </Step>
  <Step title="Enter the credentials in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, select **Yes** for **Enabled** in the **Salesforce Marketing Cloud** section, enter these values, and click **Save**.

    | Field | Value |
    | --- | --- |
    | **Client ID**, **Client secret** | From the installed package. |
    | **Auth base URI** | The **Authentication Base URI**, exactly as Salesforce shows it, including the trailing slash. |
    | **REST base URI** | The **REST Base URI**, exactly as Salesforce shows it, including the trailing slash. |
    | **Event definition key** | Optional. The key for the event definition Radar creates. The default is `radar-event`. |

    If authentication fails, the save fails with a message that starts with `Error authenticating to Salesforce Marketing Cloud`. If it succeeds, Radar creates an API event definition named **Radar Event** and its data extension.
  </Step>
  <Step title="Link the data extension to your contacts">
    In **Contact Builder**, open **Data Designer**. Link the **Contact Key** field of your customer data to the `contactKey` field of the Radar data extension, in a one-to-many relationship.
  </Step>
</Steps>

## Identity mapping

Radar doesn't use the Radar `userId` as the contact key. Set `salesforceContactKey` in Radar user metadata.

| Radar value | Sent to Salesforce as | Required |
| --- | --- | --- |
| `metadata.salesforceContactKey` | `ContactKey` on the API event, and `contactKey` in the event data | Yes. Without it, Radar skips the event and logs `Identifier missing.` |
| `userId` | `userUserId` in the event data | No |
| `deviceId` | `userDeviceId` in the event data | No |

<CodeGroup>

```swift Swift
import RadarSDK

// The Salesforce call depends on your Marketing Cloud SDK version.
let contactKey = SFMCSdk.mp.contactKey()
Radar.setMetadata(["salesforceContactKey": contactKey])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// The Salesforce calls depend on your Marketing Cloud SDK version.
SFMCSdk.requestSdk { sdk ->
    sdk.mp {
        val contactKey = it.moduleIdentity.profileId
        Radar.setMetadata(JSONObject().put("salesforceContactKey", contactKey))
    }
}
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object. Update it when the user logs out or changes.

## Event mapping

Every Radar event becomes one row in the Radar data extension, with the Radar event type in the `type` attribute. Other event types that pass your filters are sent with the common attributes only.

| Radar event, sent unchanged as `type` | Context |
| --- | --- |
| `user.entered_geofence` | [Geofences](/fundamentals/context-types#geofences) |
| `user.exited_geofence` | Geofences |
| `user.dwelled_in_geofence` | Geofences |
| `user.entered_place` | [Places](/fundamentals/context-types#places) |
| `user.exited_place` | Places |
| `user.nearby_place_chain` | Places |
| `user.entered_region_country` | [Regions](/fundamentals/context-types#regions) |
| `user.exited_region_country` | Regions |
| `user.entered_region_state` | Regions |
| `user.exited_region_state` | Regions |
| `user.entered_region_dma` | Regions |
| `user.exited_region_dma` | Regions |
| `user.entered_region_postal_code` | Regions |
| `user.exited_region_postal_code` | Regions |
| `user.started_trip` | [Trips](/fundamentals/context-types#trips) |

For example, to send a push when a user arrives at a store, create a journey whose entry source is the Radar API event, filtered on `type` equal to `user.entered_geofence` and `geofenceTag` equal to `store`.

To limit what Radar sends, see [Filters](/integrations/integrations#filters). Don't add `contactKey`, `id`, or `type` to the request key blocklist.

Radar requests an access token from your authentication base URI, then posts each event separately to `interaction/v1/events` on your REST base URI. If the token request fails, no events from that batch are sent. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Set `salesforceContactKey` to the key of a contact that exists in Marketing Cloud, move that user into a geofence with the [Simulator](https://dashboard.radar.com/geofencing/simulate), then click **View** on the new event on the **Events** page. Its **Logs** section shows a request to `interaction/v1/events` with a `2xx` response, and the Radar data extension in **Contact Builder** shows a new row with your contact key and the event `type`. If not, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery). If the token request to `v2/token` fails, check the client ID and secret, and that the auth base URI ends with a slash.

## Limitations

One set of credentials and one event definition key serve both the Test and Live environments.
