---
title: "Amplitude"
description: "Send Radar events and user properties to Amplitude, map Radar identifiers to Amplitude users, and verify that events arrive."
---

<Info>
  The Amplitude integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar's servers send each Radar event to Amplitude as a `[Radar]` event on the matching user, with [location context](/fundamentals/context-types) as user properties.

## Prerequisites

- A Radar project that generates events.
- An Amplitude project and its API key. Use a separate project for testing if you have one.
- A user ID shared by both systems.

## Configuration

1. In Amplitude, open your project's settings and copy its API key.
2. On the [Integrations](https://dashboard.radar.com/integrations) page, find the **Amplitude** section, select **Yes** for **Enabled**, enter the production key in **Live API key** and the development key in **Test API key**, and click **Save**.

**Show advanced** has two optional settings:

- **Use identify API**: When **Yes**, Radar also calls Amplitude's Identify API on each delivery to update the user's properties, including when every event in the delivery was filtered out. When **No**, user properties are sent only as part of each event.
- **Use cohort API for Segments**: Applies Radar segments to the user through Amplitude's cohort API. More fields appear when you select **Yes**.

## Identity mapping

Set the Radar `userId` to your Amplitude user ID with `Radar.setUserId()` after login. Without a `userId`, events carry the device identifiers only.

| Radar user field | Amplitude field | Sent when |
| --- | --- | --- |
| `userId` | `user_id` | The Radar user has a `userId`. |
| `deviceId` | `device_id` | The Radar user has a `deviceId`. |
| `deviceId` | `idfv` | The device type is iOS. |
| `deviceId` | `android_id` | The device type is Android. |
| `ip` | `ip` | Radar has an IP address for the user. |

On every event that has region context, Radar also sends each region user property from [User mapping](#user-mapping) as an event property, named without the `[Radar] Region` prefix: `Country Code`, `Country Name`, `Country ID`, `State Code`, `State Name`, `State ID`, `DMA Code`, `DMA Name`, `DMA ID`, `City Code`, `City Name`, `City ID`, `Postal Code`, and `Postal Code ID`.

To limit what Radar sends, see [Filters](/integrations/integrations#filters).

Radar sends the events from one update in one request to `https://api.amplitude.com/httpapi`, and Identify calls to `https://api2.amplitude.com/identify`. See [Delivery behavior](/integrations/integrations#delivery-behavior).

## Test the integration

Create a geofence in the Test environment, then send a location inside it:

```bash
curl "https://api.radar.io/v1/track" \
  -H "Authorization: prj_test_pk_..." \
  -X POST \
  -d "deviceId=test-device-1" \
  -d "userId=user-123" \
  -d "deviceType=iOS" \
  -d "latitude=40.78382" \
  -d "longitude=-73.97536" \
  -d "accuracy=10"
```

The response includes a `user.entered_geofence` event. In the **Amplitude** section, **View integration logs** shows the request with a `200` response and the API key redacted. In Amplitude, user `user-123` has a `[Radar] Geofence Entered` event with your geofence's `Geofence External ID`.

If the event is on the wrong user, compare `user_id` and `device_id` in the logged request with the Amplitude user. Otherwise, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

The integration has no setting for the Amplitude ingestion endpoint.
