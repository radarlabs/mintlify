<Info>
  The Airship integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

By the end of this page, Radar sends a custom event to [Airship](https://www.airship.com/) for each location event it generates and updates the device's Radar tag groups, and you have confirmed delivery for one test device.

Radar sends this data from its servers to the Airship API. Your app supplies the Airship channel ID so Radar knows which device to update.

## Prerequisites

- A Radar project on the Enterprise plan, with the Radar SDK generating events. See [Detect geofence events and place visits](/geofencing/geofences-and-places).
- An Airship project, with permission to create tokens and tag groups.
- The Airship SDK in your iOS or Android app.

## Configuration

<Steps>
  <Step title="Create an Airship token">
    In Airship, open **Settings**, then the **Tokens** page. Create a token with the **All Access** role and copy the app key and the access token. Repeat for each Airship project you use, for example separate iOS and Android or test and live projects.
  </Step>
  <Step title="Enable Radar as a partner in Airship">
    Under **Partner Integrations**, enable Radar. This makes Radar's custom event names and properties available in the Airship Automation composer.
  </Step>
  <Step title="Create the tag groups in Airship">
    Radar writes user state to Airship as tags in named tag groups. Airship doesn't create tag groups on demand, so create a [tag group](https://docs.airship.com/guides/messaging/user-guide/audience/segmentation/tags/) for each row of the [User mapping](#user-mapping) table that you plan to use, with the group key exactly as listed there, for example `radar_geofence_tags`.
  </Step>
  <Step title="Enter the keys in Radar">
    In the Radar dashboard, open the [Integrations](https://dashboard.radar.com/integrations) page, find the **Airship** section, and select **Yes** for **Enabled**. Enter these values:

    | Field | Value |
    | --- | --- |
    | **API endpoint** | `https://go.urbanairship.com`, or `https://go.airship.eu` for an Airship EU project. |
    | **Live iOS app key**, **Live iOS access token** | The app key and token for Live environment events from iOS devices. |
    | **Live Android app key**, **Live Android access token** | The app key and token for Live environment events from Android devices. |
    | Test iOS and Test Android app keys and access tokens | The same values for the Airship project that receives data from the Test environment. |

    Click **Save**.
  </Step>
  <Step title="Send the Airship channel ID to Radar">
    Set the channel ID and session ID in Radar user metadata. See [Identity mapping](#identity-mapping).
  </Step>
</Steps>

Radar selects the app key and access token from the device type (iOS or Android) and the environment of the event. If that pair is empty, Radar skips the event.

## Identity mapping

Airship identifies a device by its channel ID. Radar needs it for every request.

| Radar value | Sent to Airship as | Required |
| --- | --- | --- |
| `metadata.airshipChannelId` | `ios_channel` for iOS devices, `android_channel` for other devices | Yes. Without it, Radar skips the event and logs `Identifier missing.` |
| `metadata.airshipSessionId` | `session_id` on the custom event | No. Radar sends an all-zero session ID when it is absent. |

Set both values in Radar user metadata as soon as the Airship channel exists. The channel ID isn't available immediately on first launch, so set the metadata from a channel listener in your [Airship SDK](https://www.airship.com/docs/developer/sdk-integration), not only at startup.

<CodeGroup>

```swift Swift
import AirshipKit
import RadarSDK

// The Airship property names depend on your Airship SDK version.
Radar.setMetadata([
  "airshipChannelId": Airship.channel.identifier,
  "airshipSessionId": Airship.analytics.sessionID
])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// The Airship property names depend on your Airship SDK version.
val channelId = UAirship.shared().channel.id
val sessionId = UAirship.shared().analytics.sessionId
Radar.setMetadata(JSONObject().put("airshipChannelId", channelId).put("airshipSessionId", sessionId))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object, so include any other metadata keys you use in the same call.

With Radar iOS SDK 3.0.5 or later, Radar Android SDK 3.0.7 or later, or Airship SDK 14.0 or later, you must set the metadata yourself. Radar iOS SDK 3.0.4 and earlier and Radar Android SDK 3.0.6 and earlier collect the channel ID and session ID automatically when used with Airship SDK 13.x or earlier.

## Filtering

On the [Integrations](https://dashboard.radar.com/integrations) page, click **Show advanced** in the **Airship** section.

| Setting | Effect |
| --- | --- |
| **Event type allowlist** | Radar sends only the selected event types. Check this list first when an event you expect is missing. |
| **Request key blocklist** | Comma-separated keys to remove from the request, for example `radar_geofence_ids,radar_geofence_id`. Applies to tag groups and event properties. |
| **Geofence tag blocklist** | Comma-separated geofence tags. Radar skips events for geofences with these tags. |

For the filters that every event integration shares, see [Filters](/integrations/integrations#filters).

## Delivery behavior

- Radar sends to Airship only when it generates an event for the user. A location update that produces no event doesn't update tags.
- Each Radar event produces two Airship requests: one to `/api/custom-events` and one to `/api/channels/tags`. Events from the same location update are sent separately.
- Delivery is asynchronous and doesn't block the SDK.
- Radar sends each request once. It doesn't retry a request that Airship rejects or that times out. Both outcomes are recorded in the integration logs.
- Events from the Test environment use the Test keys, and events from the Live environment use the Live keys.

## Troubleshoot delivery

Click **View integration logs** in the **Airship** section of the [Integrations](https://dashboard.radar.com/integrations) page. Each row shows the timestamp, the request URL, and the response code, and expands to the request and response bodies. New rows can take a few minutes to appear.

| Log response | Meaning |
| --- | --- |
| `skipped`: `Integration key(s) missing.` | No app key or access token for this device type and environment. |
| `skipped`: `Identifier missing.` | The user has no `metadata.airshipChannelId`. |
| `skipped`, "Event type ... isn't allowed." | The event type isn't selected in the allowlist. |
| `skipped`: `Geofence tag '...' is blocklisted.` | The geofence tag is in the blocklist. |
| The custom event succeeds but the tags request fails | Check that the tag groups exist in Airship. The response body in the log gives the reason. |
| A `4xx` response on both requests | Airship rejected the credentials or the channel. Check the app key, the access token, the API endpoint, and that the channel ID belongs to that Airship project. |

## Example use cases

### Send a personalized push notification when a user arrives at a store

1. Create [geofences](/geofencing/geofences-and-places) in Radar with the tag `store`.
2. In Airship, create an automation triggered by the `radar_geofence_entered` custom event, with a property filter where `radar_geofence_tag` is `store`. Event properties are available for message personalization with [Handlebars](https://handlebarsjs.com/).

### Message all users nearby a store

1. Create geofences in Radar that cover the area around each store, with the tag `nearby-store`.
2. In Airship, target the audience whose `radar_geofence_tags` tag group contains the tag `nearby-store`. This tag group lists the tags of every geofence the user is in. Combine it with the region tag groups for regional targeting.

### In-app messaging

A custom event sent from Radar's servers can't trigger an Airship in-app message at app open. To trigger one from the user's location, track the custom event through the Airship SDK from Radar's location listener.

The examples below assume you call `Radar.trackOnce()` at app launch. They build the event name and properties and hand them to a function you implement with your version of the Airship SDK. The Airship call isn't shown because it differs between Airship SDK versions.

<CodeGroup>

```swift Swift
import CoreLocation
import RadarSDK

// Set this object as the Radar delegate.
class LocationEventForwarder: NSObject, RadarDelegate {
    // Implement with your Airship SDK's custom event call.
    var trackAirshipEvent: (String, [String: Any]) -> Void = { _, _ in }

    func didUpdateLocation(_ location: CLLocation, user: RadarUser) {
        guard user.foreground, user.source == .foregroundLocation else { return }

        if let geofences = user.geofences, !geofences.isEmpty {
            trackAirshipEvent("radar_fg_geofences_detected", [
                "radar_geofence_descriptions": geofences.map { $0.__description },
                "radar_geofence_tags": geofences.compactMap { $0.tag },
                "radar_geofence_external_ids": geofences.compactMap { $0.externalId }
            ])
        }
    }
}
```

```kotlin Kotlin
import android.content.Context
import android.location.Location
import io.radar.sdk.Radar
import io.radar.sdk.RadarReceiver
import io.radar.sdk.model.RadarEvent
import io.radar.sdk.model.RadarUser

// Register this receiver with the Radar SDK.
class LocationEventForwarder(
    // Implement with your Airship SDK's custom event call.
    private val trackAirshipEvent: (name: String, properties: Map<String, String>) -> Unit
) : RadarReceiver() {

    override fun onLocationUpdated(context: Context, location: Location, user: RadarUser) {
        if (!user.foreground || user.source != Radar.RadarLocationSource.FOREGROUND_LOCATION) return

        val geofences = user.geofences
        if (!geofences.isNullOrEmpty()) {
            trackAirshipEvent(
                "radar_fg_geofences_detected",
                mapOf(
                    "radar_geofence_descriptions" to geofences.joinToString { it.description },
                    "radar_geofence_tags" to geofences.mapNotNull { it.tag }.joinToString(),
                    "radar_geofence_external_ids" to geofences.mapNotNull { it.externalId }.joinToString()
                )
            )
        }
    }

    override fun onEventsReceived(context: Context, events: Array<RadarEvent>, user: RadarUser?) {}
    override fun onClientLocationUpdated(context: Context, location: Location, stopped: Boolean, source: Radar.RadarLocationSource) {}
    override fun onError(context: Context, status: Radar.RadarStatus) {}
    override fun onLog(context: Context, message: String) {}
}
```

</CodeGroup>

`radar_fg_geofences_detected` is a name you choose. It is separate from the events Radar sends server-side.

## Limitations

- Radar updates Airship only for users with a channel ID. Devices that haven't registered an Airship channel are skipped.
- Tags are updated only when an event is generated, so `radar_updated_at` can be older than the user's last location update.
- Tag groups must exist in Airship before Radar can set them.
- The integration has key fields for iOS and Android only.
- There is no automatic retry. A request that fails during an Airship outage isn't resent.
