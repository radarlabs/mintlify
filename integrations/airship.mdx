title: "Airship"
description: "Send Radar location events and tags to Airship to trigger location-based messages and build location-based audiences."
---

<Info>
  The Airship integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar sends a custom event to [Airship](https://www.airship.com/) for each location event it generates, and updates the device's Radar tag groups.

## Prerequisites

- A Radar project on the Enterprise plan that is [generating events](/geofencing/geofences-and-places).
- An Airship project where you can create tokens and tag groups, and the Airship SDK in your iOS or Android app.

## Configuration

<Steps>
  <Step title="Create an Airship token">
    In Airship, open **Settings**, then **Tokens**. Create a token with the **All Access** role and copy the app key and access token. Repeat for each Airship project you use.
  </Step>
  <Step title="Enable Radar as a partner in Airship">
    Under **Partner Integrations**, enable Radar so its event names and properties appear in the Automation composer.
  </Step>
  <Step title="Create the tag groups in Airship">
    Airship doesn't create tag groups on demand. Create a [tag group](https://docs.airship.com/guides/messaging/user-guide/audience/segmentation/tags/) for each row of [User mapping](#user-mapping) that you plan to use, with the group key exactly as listed, for example `radar_geofence_tags`.
  </Step>
  <Step title="Enter the keys in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, select **Yes** for **Enabled** in the **Airship** section, enter these values, and click **Save**.

    | Field | Value |
    | --- | --- |
    | **API endpoint** | `https://go.urbanairship.com`, or `https://go.airship.eu` for an Airship EU project. |
    | **Live iOS app key**, **Live iOS access token** | For Live events from iOS devices. |
    | **Live Android app key**, **Live Android access token** | For Live events from Android devices. |
    | Test iOS and Test Android app keys and access tokens | The same for the Test environment. |
  </Step>
</Steps>

## Identity mapping

| Radar value | Sent to Airship as | Required |
| --- | --- | --- |
| `metadata.airshipChannelId` | `ios_channel` for iOS devices, `android_channel` for other devices | Yes. Without it, Radar skips the event and logs `Identifier missing.` |
| `metadata.airshipSessionId` | `session_id` on the custom event | No. Radar sends an all-zero session ID when it is absent. |

The channel ID isn't available immediately on first launch, so set the metadata from a channel listener in your Airship SDK, not only at startup.

<CodeGroup>

```swift Swift
import AirshipKit
import RadarSDK

// The Airship property names depend on your Airship SDK version.
Radar.setMetadata([
  "airshipChannelId": Airship.channel.identifier,
  "airshipSessionId": Airship.analytics.sessionID
])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// The Airship property names depend on your Airship SDK version.
val channelId = UAirship.shared().channel.id
val sessionId = UAirship.shared().analytics.sessionId
Radar.setMetadata(JSONObject().put("airshipChannelId", channelId).put("airshipSessionId", sessionId))
```

</CodeGroup>

`Radar.setMetadata()` replaces the whole metadata object.

## Test the integration

Move a test user that has `airshipChannelId` in its metadata into a geofence with the [Simulator](https://dashboard.radar.com/geofencing/simulate), then click **View** on the new event on the **Events** page. Its **Logs** section shows two Airship requests, each with a `2xx` response, and the Airship channel shows the `radar_geofence_entered` event and the tags in the `radar_geofence_tags` group. If not, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

An event sent from Radar's servers can't trigger an Airship in-app message at app open. Track it through the Airship SDK from Radar's location listener.
