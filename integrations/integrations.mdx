Pick the integration that matches where your Radar data needs to go. The event integrations share the [filters](#filters), [delivery behavior](#delivery-behavior), and [troubleshooting](#troubleshoot-delivery) described at the end of this page.

- **Event integrations**: When Radar generates an event, such as a geofence entry or a trip update, its servers forward the event and the current user state to the destinations you enable. Webhooks, the analytics platforms, and the messaging platforms work this way.
- **Data export**: AWS S3 receives events and locations in bulk.
- **Operational and AI integrations**: Olo for order firing, and the MCP server for querying Radar data from an AI assistant.

## Filters

Click **Show advanced** in an integration's section on the [Integrations](https://dashboard.radar.com/integrations) page to show its filters. For webhooks, the same fields are in the **New webhook** and **Edit webhook** dialogs.

| Field | Effect |
| --- | --- |
| **Event type allowlist** | When you select one or more event types, Radar sends only those types. With nothing selected, Radar sends every event type. |
| **Request key blocklist** | Removes the listed keys from the request body, at any depth. Enter keys comma-separated. For example, `radar_geofence_ids,geofence_id` removes `radar_geofence_ids` from the Segment `identify` call and `geofence_id` from the Segment `track` call. |
| **Geofence tag blocklist** | Skips events for geofences that have one of the listed tags. Enter tags comma-separated. For example, `gas-station,cafe` skips every event for geofences tagged `gas-station` or `cafe`. |

A filtered event is skipped for that integration only. Other integrations still receive it, and the event still appears in the dashboard and the [Events API](/api/events).

You can't rename events or properties. Use the request key blocklist to drop the ones you don't want.

## Delivery behavior

This applies to webhooks and to the analytics and messaging integrations. Each integration page lists its own exceptions.

- **Setup**: Each integration has its own section on the Integrations page, with an **Enabled** selector, credential fields, and a **Save** button. Settings belong to the project that is selected in the dashboard. Many native integrations require the [Enterprise plan](https://radar.com/pricing).
- **Trigger**: Radar generates events when it processes a location update, a trip change, or another server-side state change. Each delivery carries the events from one update with the user's state after that update, including the [context types](/fundamentals/context-types) that are turned on for your project. A location update that generates no event produces no delivery, and events generated before you enabled the integration aren't sent.
- **Timing**: Radar sends events from its servers shortly after it generates them. The destination's own processing time applies after that.
- **Attempts**: Radar sends each request once. It doesn't retry a request that the destination rejects or that times out. Webhooks and the analytics integrations wait up to 5 seconds for a response, and [webhooks](/integrations/webhooks#retries) retry only when retries are enabled for your project. Find failures in the integration logs, and backfill from the [Events API](/api/events).
- **Environments**: Most integrations take separate Test and Live credentials. Events from the Test environment use the Test credential, and events from the Live environment use the Live credential. If the credential for an environment is empty, Radar skips events from that environment and logs the reason. See [Set up organizations, projects, accounts, and authentication](/fundamentals/authentication-and-access).
- **Payload**: Geofence geometry is removed before delivery.

## Troubleshoot delivery

Each integration's section has a **View integration logs** button. The logs list one row per delivery attempt with the **Timestamp**, **Integration**, **Request**, and **Response**, and you can filter by date range, response, and integration.

Check these first:

| What you see | Likely cause | What to do |
| --- | --- | --- |
| No rows | No events were generated in that environment, or the integration isn't saved as enabled. | Check the Events page for the environment and the **Enabled** setting. |
| A `4xx` response | The destination rejected the request. | Read the response body in the log, and check that the credential belongs to the intended destination and environment. |
| A success response, but nothing on the expected user | The identifiers differ between Radar and the destination. | Compare the identifiers in the logged request with the user in the destination. |

Skipped events have a response of `skipped` and one of these reasons:

| Reason | Meaning |
| --- | --- |
| `Integration disabled.` | **Enabled** is **No**, or the webhook is disabled. |
| `Integration key(s) missing.` | No credential is saved for the event's environment or device type. |
| `Identifier missing.` | The user has no identifier that the destination requires. The integration page says which one. |
| `Event type ... is not allowed.` | The event type isn't selected in **Event type allowlist**. |
| `Geofence tag '...' is blocklisted.` | The geofence's tag is in **Geofence tag blocklist**. |
