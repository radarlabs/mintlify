Pick the integration that matches where your Radar data needs to go, then learn the settings and delivery behavior that the server-side event integrations share.

Radar integrations fall into three kinds:

- **Event integrations**: Run on Radar's servers. When Radar generates an event, such as a geofence entry or a trip update, it forwards the event and the current user state to the destinations you enable. Webhooks, the analytics platforms, and the messaging platforms work this way.
- **Data export**: Delivers events and locations in bulk to storage that you own. AWS S3 works this way.
- **Operational and AI integrations**: Connect Radar to another product's workflow: Olo for order firing, and the MCP server for querying Radar data from an AI assistant.

## How event integrations work

The following applies to webhooks and to the analytics and messaging integrations. Each integration page lists its own exceptions.

### Where you configure them

You configure event integrations on the [Integrations](https://dashboard.radar.com/integrations) page of the Radar dashboard. Each integration has its own section with an **Enabled** selector, credential fields, and a **Save** button. Settings belong to the project that is selected in the dashboard.

Most integrations take separate Test and Live credentials. Events from the Test environment use the Test credential and events from the Live environment use the Live credential. If the credential for an environment is empty, Radar skips events from that environment and records the reason in the integration logs. For how environments and keys work, see [Set up organizations, projects, accounts, and authentication](/fundamentals/authentication-and-access).

Many native integrations require the [Enterprise plan](https://radar.com/pricing), and each integration page states its requirement. When your plan doesn't include an integration, its section shows an upgrade prompt in place of the form.

### What triggers a delivery

Radar generates events when it processes a location update, a trip change, or another server-side state change. Each delivery carries the events from one update together with the user's state after that update, including the [context types](/fundamentals/context-types) that are turned on for your project. An integration that is enabled receives nothing until an event is generated, so a location update that produces no event produces no delivery.

Geofence geometry is removed from payloads before delivery.

### Filters

Click **Show advanced** in an integration's section to show its filters. For webhooks, the same fields are in the **New webhook** and **Edit webhook** dialogs.

| Field | Effect |
| --- | --- |
| **Event type allowlist** | When you select one or more event types, Radar sends only those types. With nothing selected, Radar sends every event type. |
| **Request key blocklist** | Removes the listed keys from the request body, at any depth. Enter keys comma-separated. For example, `radar_geofence_ids,geofence_id` removes `radar_geofence_ids` from the Segment `identify` call and `geofence_id` from the Segment `track` call. |
| **Geofence tag blocklist** | Skips events for geofences that have one of the listed tags. Enter tags comma-separated. For example, `gas-station,cafe` skips every event for geofences tagged `gas-station` or `cafe`. |

A filtered event is skipped for that integration only. Other integrations still receive it, and the event still appears in the dashboard and the [Events API](/api/events).

### Inspect deliveries and failures

Each integration's section has a **View integration logs** button. The logs page lists one row per delivery attempt with the **Timestamp**, **Integration**, **Request**, and **Response**, and you can filter by date range, response, and integration.

Skipped events appear in the logs with a response of `skipped` and one of these reasons:

| Reason | Meaning |
| --- | --- |
| `Integration disabled.` | **Enabled** is **No**, or the webhook is disabled. |
| `Integration key(s) missing.` | No credential is saved for the event's environment or device type. |
| `Identifier missing.` | The user has no identifier that the destination requires. The integration page says which one. |
| `Event type ... is not allowed.` | The event type isn't selected in **Event type allowlist**. |
| `Geofence tag '...' is blocklisted.` | The geofence's tag is in **Geofence tag blocklist**. |

### Events without a native integration

To send Radar data to a platform that isn't listed on this page, use one of these routes:

- **Server-side**: Create a [webhook](/integrations/webhooks) and forward the payload from your own endpoint.
- **Client-side**: Receive events in your app from the [Radar SDK](/sdk/sdk) and pass them to the other platform's SDK.

To load geofences into Radar from a CSV file on a schedule, including a CSV stored in S3, see geofence sync in [Detect geofence events and place visits](/geofencing/geofences-and-places).
