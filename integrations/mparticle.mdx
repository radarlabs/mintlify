<Info>
  The mParticle integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

Radar's servers send each Radar event to an mParticle input feed as a custom event on the matching user, with [location context](/fundamentals/context-types) as user attributes. Separately, the mParticle kit installs the Radar SDK in your app. Events and user attributes reach mParticle only through the feed.

## Prerequisites

- A Radar project that generates events.
- An mParticle workspace where you can add input feeds.
- An identity shared by both systems for each user.

## Configuration

### Feed

1. In mParticle, add a Radar input feed for each platform that your app supports, and copy each feed's API key and secret.
2. On the [Integrations](https://dashboard.radar.com/integrations) page, find the **mParticle** section, select **Yes** for **Enabled**, enter the credentials in **iOS API key** and **iOS API secret**, **Android API key** and **Android API secret**, or **Web API key** and **Web API secret**, and click **Save**.

Radar routes each event to the feed for the user's device type. If that platform's key or secret is empty, or the user has no device type, Radar skips the event and logs `Integration key(s) missing.`

Test and Live share each platform's credentials. Radar sends Test events with the mParticle `development` environment and Live events with `production`.

### Kit

To install and initialize the Radar SDK through mParticle, add and enable Radar outputs for iOS and Android in mParticle, enter your Radar Test and Live publishable keys, and choose whether the kit runs automatically. Then install the kit with CocoaPods or Carthage on iOS and with Gradle on Android. See the [iOS kit](https://github.com/mparticle-integrations/mparticle-apple-integration-radar), the [Android kit](https://github.com/mparticle-integrations/mparticle-android-integration-radar), and the [mParticle documentation](https://docs.mparticle.com/integrations/radar/event/).

The kit identifies the user with the mParticle customer ID. From version 8.0.2 of the iOS kit and 5.15.1 of the Android kit, it also sets Radar `metadata.mParticleId` to the MPID. If it runs automatically and the user has granted location permissions, the kit tracks location in the foreground on app open, in the background, or both.

## Identity mapping

Radar sends these identities with each request:

| Radar user field | mParticle field | Sent when |
| --- | --- | --- |
| `deviceId` | `device_info.ios_idfv` | The device type is iOS. |
| `deviceId` | `device_info.android_uuid` | The device type is Android. |
| Advertising ID | `device_info.ios_advertising_id` or `device_info.android_advertising_id` | Radar has an advertising ID for the device and the user hasn't opted out. |
| `metadata.mParticleCustomerId`, otherwise `userId` | `user_identities.customer_id` | Either value is set. |
| `metadata.mParticleOtherId` | `user_identities.other` | The metadata key is set. |
| `metadata.mParticleId` | `mpid` | The metadata key is set. |

If your mParticle customer ID differs from the Radar `userId`, set `metadata.mParticleCustomerId`:

<CodeGroup>

```swift Swift
import RadarSDK

// customerId is the value your app sends to mParticle as the customer ID.
Radar.setMetadata(["mParticleCustomerId": customerId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// customerId is the value your app sends to mParticle as the customer ID.
Radar.setMetadata(JSONObject().put("mParticleCustomerId", customerId))
```

</CodeGroup>

If you don't use a customer ID, or you want an exact match on the mParticle user, set `metadata.mParticleId` to the MPID. Without the kit, read the MPID when mParticle finishes identifying the user:

<CodeGroup>

```swift Swift
import mParticle_Apple_SDK
import RadarSDK

let options = MParticleOptions(key: "YOUR_MPARTICLE_KEY", secret: "YOUR_MPARTICLE_SECRET")
options.onIdentifyComplete = { (result: MPIdentityApiResult?, error: Error?) in
    if let user = result?.user {
        Radar.setMetadata(["mParticleId": user.userId])
    } else {
        // Identification failed. Radar falls back to the device and customer IDs.
    }
}

MParticle.sharedInstance().start(with: options)
```

```kotlin Kotlin
import com.mparticle.MParticle
import io.radar.sdk.Radar
import org.json.JSONObject

MParticle.getInstance()?.Identity()?.addIdentityStateListener { user, _ ->
    Radar.setMetadata(JSONObject().put("mParticleId", user.id))
}
```

</CodeGroup>

A messaging platform connected to mParticle as an output receives the names on this page, not the names on Radar's page for that platform. Enable one route per platform, or the platform can receive each event twice under different names.

## Test the integration

Create a geofence in the Test environment, then send a location inside it. Set `deviceType` to the platform whose feed you configured:

```bash
curl "https://api.radar.io/v1/track" \
  -H "Authorization: prj_test_pk_..." \
  -X POST \
  -d "deviceId=test-device-1" \
  -d "userId=user-123" \
  -d "deviceType=iOS" \
  -d "latitude=40.78382" \
  -d "longitude=-73.97536" \
  -d "accuracy=10"
```

The response includes a `user.entered_geofence` event. In the **mParticle** section, **View integration logs** shows the request with a success response, `environment` set to `development`, and `user_identities.customer_id` set to `user-123`. mParticle's live stream for the development environment shows a `user.entered_geofence` custom event with your geofence's `geofence_external_id`, and `radar_geofence_external_ids` among the user attributes.

If the event is on the wrong mParticle user, compare `device_info`, `user_identities`, and `mpid` in the logged request with that user. Otherwise, see [Troubleshoot delivery](/integrations/integrations#troubleshoot-delivery).

## Limitations

Events without a location aren't sent.
