<Info>
  The mParticle integration is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

By the end of this page, each Radar event arrives in mParticle as a custom event on the matching mParticle user, with Radar's location context as user attributes that you can use in audiences and forward to outputs.

Radar connects to mParticle in two ways, and you can use either or both:

| | Feed | Kit |
| --- | --- | --- |
| Direction | Radar's servers send events and user attributes to mParticle. | The mParticle SDK installs and initializes the Radar SDK in your app. |
| Use it to | Build location-based audiences and forward Radar events to mParticle outputs, including messaging platforms connected to mParticle. | Manage the Radar SDK through mParticle instead of initializing it yourself. |
| Configured in | The **mParticle** section of Radar's Integrations page, plus input feeds in mParticle. | Radar outputs in mParticle, plus the kit dependency in your app. |

The kit sets up the Radar SDK in your app. To get Radar events and user attributes into mParticle, configure the feed.

## Prerequisites

- A Radar project on the Enterprise plan that generates events. See [Geofencing overview and quickstart](/geofencing/overview).
- Access to the [Integrations](https://dashboard.radar.com/integrations) page in the Radar dashboard.
- An mParticle workspace where you can add input feeds and read their keys and secrets.
- An identity that both systems share for each user. See [User mapping](#user-mapping).

## Configuration

### Feed

<Steps>
  <Step title="Add Radar input feeds in mParticle">
    In mParticle, add a Radar input feed for each platform that your app supports, for example one for iOS and one for Android. Copy the API key and secret of each feed.
  </Step>
  <Step title="Enable the integration in Radar">
    On the [Integrations](https://dashboard.radar.com/integrations) page, find the **mParticle** section and select **Yes** for **Enabled**. Credential fields appear.
  </Step>
  <Step title="Enter the feed credentials">
    Enter each feed's credentials in the fields for its platform: **iOS API key** and **iOS API secret**, **Android API key** and **Android API secret**, and **Web API key** and **Web API secret**. Enter values only for the platforms you use.
  </Step>
  <Step title="Save">
    Click **Save**. From now on, Radar sends each new event to mParticle. Events generated before you saved aren't sent.
  </Step>
</Steps>

Radar routes by the device type of the user: events from iOS devices go to the iOS feed, events from Android devices go to the Android feed, and events from web devices go to the web feed. If the platform's key or secret is empty, or the user has no device type, Radar skips the event.

The **mParticle** section has no separate Test and Live credentials. Radar sets the mParticle environment on each request: the Radar Test environment maps to the mParticle development environment, and the Radar Live environment maps to the mParticle production environment.

### Kit

To configure the kit:

1. On the [Settings](https://dashboard.radar.com/settings) page, copy your Test and Live publishable keys.
2. In mParticle, add and enable Radar outputs for iOS and Android, enter your keys, and choose whether the kit runs automatically.
3. Install the kit with CocoaPods or Carthage on iOS and with Gradle on Android. See the [iOS kit code and readme](https://github.com/mparticle-integrations/mparticle-apple-integration-radar), the [Android kit code and readme](https://github.com/mparticle-integrations/mparticle-android-integration-radar), and the [mParticle kit documentation for Radar](https://docs.mparticle.com/integrations/radar/event/).

The kit initializes the [Radar SDK](/sdk/sdk) and identifies the user with the mParticle customer ID. From version 8.0.2 of the iOS kit and 5.15.1 of the Android kit, the kit also sets Radar `metadata.mParticleId` to the [MPID](https://docs.mparticle.com/developers/sdk/web/users/#mparticle-id). If you chose to run automatically and the user has granted location permissions, the kit tracks the user's location in the foreground on app open, in the background, or both.

Automatic tracking starts only after the user has granted location permissions. See [Understand foreground and background location permissions](/fundamentals/location-permissions).

## User mapping

### Identities

Radar sends these identities with each request to the feed. mParticle uses them to resolve the mParticle user.

| Radar user field | mParticle field | Sent when |
| --- | --- | --- |
| `deviceId` | `device_info.ios_idfv` | The device type is iOS. |
| `deviceId` | `device_info.android_uuid` | The device type is Android. |
| Advertising ID | `device_info.ios_advertising_id` or `device_info.android_advertising_id` | Radar has an advertising ID for the device and the user hasn't opted out. |
| `metadata.mParticleCustomerId`, otherwise `userId` | `user_identities.customer_id` | Either value is set. |
| `metadata.mParticleOtherId` | `user_identities.other` | The metadata key is set. |
| `metadata.mParticleId` | `mpid` | The metadata key is set. |

Choose the mapping that matches how your app identifies users in mParticle:

- If your mParticle customer ID equals the Radar `userId`, you need no extra code. Radar sends `userId` as `customer_id`.
- If your mParticle customer ID is a different value, set `metadata.mParticleCustomerId` to it.
- If you don't use a customer ID in mParticle, or you want an exact match on the mParticle user, set `metadata.mParticleId` to the MPID. The kit does this for you from the versions listed above.

To map by customer ID:

<CodeGroup>

```swift Swift
import RadarSDK

// customerId is the value your app sends to mParticle as the customer ID.
Radar.setMetadata(["mParticleCustomerId": customerId])
```

```kotlin Kotlin
import io.radar.sdk.Radar
import org.json.JSONObject

// customerId is the value your app sends to mParticle as the customer ID.
Radar.setMetadata(JSONObject().put("mParticleCustomerId", customerId))
```

</CodeGroup>

To map by MPID without the kit, read the MPID when mParticle finishes identifying the user and store it in Radar metadata:

<CodeGroup>

```swift Swift
import mParticle_Apple_SDK
import RadarSDK

let options = MParticleOptions(key: "YOUR_MPARTICLE_KEY", secret: "YOUR_MPARTICLE_SECRET")
options.onIdentifyComplete = { (result: MPIdentityApiResult?, error: Error?) in
    if let user = result?.user {
        Radar.setMetadata(["mParticleId": user.userId])
    } else {
        // Identification failed. Radar falls back to the device and customer IDs.
    }
}

MParticle.sharedInstance().start(with: options)
```

```kotlin Kotlin
import com.mparticle.MParticle
import io.radar.sdk.Radar
import org.json.JSONObject

MParticle.getInstance()?.Identity()?.addIdentityStateListener { user, _ ->
    Radar.setMetadata(JSONObject().put("mParticleId", user.id))
}
```

</CodeGroup>

Check the identity callbacks against the mParticle SDK version that you use.

An attribute has a value only when the matching Radar feature is enabled for your project and applies to the user.

## Filtering

On the [Integrations](https://dashboard.radar.com/integrations) page, click **Show advanced** in the **mParticle** section.

| Field | Effect |
| --- | --- |
| **Event type allowlist** | When you select one or more event types, Radar sends only those types to mParticle. With nothing selected, Radar sends every event type. |
| **Request key blocklist (comma-separated)** | Removes the listed keys from the request at any depth. For example, `radar_geofence_ids,geofence_id` removes one user attribute and one event attribute. |
| **Geofence tag blocklist (comma-separated)** | Skips events for geofences that have one of the listed tags. |

Radar forwards every event type that passes the filters. An event type that isn't in the [event mapping](#event-mapping) table arrives with its name and no type-specific custom attributes. To keep unmapped event types out of mParticle, select only the types you want in **Event type allowlist**. You can also filter per output in mParticle.

## Delivery behavior

- **Requests**: For each Radar update that generates events, Radar sends one request to mParticle's server-to-server events endpoint, `https://inbound.mparticle.com/s2s/v2/events`, with the events, the user attributes, and the identities together. If your mParticle workspace ingests through a different endpoint, ask your Radar account team whether it is supported before you enable the integration.
- **Events without a location**: Radar doesn't send an event that has no location to mParticle.
- **Timing**: Radar sends events from its servers shortly after it generates them. mParticle's own processing and output delivery times apply after that.
- **Attempts**: Radar makes one delivery attempt and waits up to 5 seconds for mParticle to respond. It doesn't retry a failed request. Use the [integration logs](#troubleshoot-delivery) to find failures, and the [Events API](/api/events) if you need to backfill.
- **Deduplication**: `source_message_id` is the Radar event `_id`.
- **Environment**: Test events are sent with the mParticle `development` environment and Live events with `production`.

### Send Radar events through mParticle to a messaging platform

If you message users from a platform that is connected to mParticle as an output, you can route Radar events through mParticle instead of enabling Radar's direct integration with that platform. In that setup, the names in this page's mapping tables are what the messaging platform receives, subject to how mParticle forwards custom events and user attributes to that output. Use these names, not the ones on Radar's page for the messaging platform, when you build campaign triggers.

Enable one route per platform. If Radar's direct integration and the mParticle route both deliver to the same messaging platform, that platform can receive each event twice under different names.

## Troubleshoot delivery

On the [Integrations](https://dashboard.radar.com/integrations) page, click **View integration logs** in the **mParticle** section. Each row shows the request and mParticle's response.

| What you see | Likely cause | What to do |
| --- | --- | --- |
| No rows | No events were generated, or the integration isn't saved as enabled. | Check the Events page and the **Enabled** setting. |
| `skipped`: `Integration key(s) missing.` | The key or secret for the user's device type is empty, or the user has no device type. | Enter both the key and the secret for that platform. For API-created users, send `deviceType`. |
| `skipped`: `Event type ... is not allowed.` | The event type isn't selected in **Event type allowlist**. | Select the type or clear the allowlist. |
| `skipped`: `Geofence tag '...' is blocklisted.` | The geofence's tag is in **Geofence tag blocklist**. | Remove the tag from the blocklist. |
| A `4xx` response | mParticle rejected the request. | Read the response body in the log. If it reports invalid credentials, copy the key and secret again from the feed for that platform. |
| A success response but the event is on a different mParticle user, or creates a new one | The identities that Radar sent don't match the identities your app sends. | Compare `device_info`, `user_identities`, and `mpid` in the logged request with the user in mParticle, then adjust the [identity mapping](#identities). |
| Events in mParticle but not in an output | The Radar feed isn't connected to the output, or an mParticle filter dropped the event. | Check the connection and its filters in mParticle. |

## Limitations

- Radar doesn't retry failed deliveries to mParticle.
- The feed has one set of credentials per platform, shared by the Test and Live environments.
- Events without a location aren't sent.
- You can't rename events or attributes in Radar. Use the request key blocklist to drop fields.
- Events generated before you enabled the integration aren't sent.
- User attributes reflect the user's state when the event was generated. Radar doesn't update mParticle when a user's state changes without generating an event.
- Events and user attributes reach mParticle through the feed. Configure it even when you use the kit.
