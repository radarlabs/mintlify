</Info>

Connect your AI assistant to one Radar project and environment through Radar's Model Context Protocol (MCP) server, then ask questions about your own data. The assistant retrieves the relevant records, analyzes them, and can display locations on a map.

## What this server is and is not

- It lets an assistant query your project's locations, events, and SDK logs after you sign in with your Radar account.
- It is read-only. The assistant can't change project settings, create geofences, delete users, or otherwise modify your Radar data.
- It isn't documentation search. The documentation search MCP, provided by the documentation platform, searches these pages and has no access to your Radar data.

## Before you connect

You need:

- A Radar account with access to a project that has the MCP server enabled.
- Permission in Radar to view location data in the Test or Live environment that you want to query.
- Permission to add a custom connection in your AI provider's account or workspace.

Use this hosted server URL for every provider:

```text
https://mcp.radar.com/mcp
```

Radar uses OAuth to authorize the connection. Don't paste a Radar secret key into the chat or into the connector configuration. Before you start, select the intended project and the Test or Live environment in the [Radar dashboard](https://dashboard.radar.com).

## Connect Claude

1. In Claude, open **Customize** > **Connectors**.
2. Click **+**, then select **Add custom connector**.
3. Enter `Radar` as the name and `https://mcp.radar.com/mcp` as the remote MCP server URL. Leave the optional OAuth client credentials empty.
4. Add the connector, then click **Connect** to sign in to Radar.
5. Review the project, environment, and requested access on Radar's consent screen. Click **Allow access**.
6. Start a conversation. In the **+** menu, select **Connectors** and turn on Radar.

For Team and Enterprise workspaces, an owner must first add the connector in **Organization settings** > **Connectors**. See [Claude's custom connector guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## Connect ChatGPT

1. In ChatGPT, open **Settings** > **Security and login** and turn on **Developer mode**. Availability depends on your account and workspace policy.
2. Open [ChatGPT Plugins](https://chatgpt.com/plugins) and click **+**.
3. Enter `Radar` as the name and a description such as `Query Radar location data`.
4. Under **Connection**, enter `https://mcp.radar.com/mcp` as the public MCP server URL and create the connection. Use OAuth if you are prompted for an authentication method.
5. Complete the Radar sign-in flow. Review the project, environment, and requested access, then click **Allow access**.
6. Review the discovered tools and turn on the Radar connection in a conversation.

See OpenAI's [connection guide](https://developers.openai.com/plugins/deploy/connect-chatgpt) if a label doesn't match. For another client that supports remote MCP servers with OAuth, add the same URL as a remote server and complete the Radar sign-in.

## Review Radar access

The Radar consent screen shows the project, the Test or Live environment, and the requested permissions. If the project or environment is wrong, cancel, select the correct context in the Radar dashboard, and restart the connection. A prompt can't switch an existing connection to another project or environment.

## What you can do

Query historical locations, events such as [geofence](/fundamentals/context-types#geofences) entries, [place](/fundamentals/context-types#places) visits, and [trip](/fundamentals/context-types#trips) updates, and SDK logs, by user, device, time range, geography, or other supported filters.

### Available tools

The assistant selects these tools for you. Every tool is read-only, and the tools that your assistant lists depend on the permissions you grant and on what is enabled for your account.

| Tool | What it does |
| --- | --- |
| `query_data` | Runs a query against one dataset and returns a completed query ID, up to three preview records, and a temporary JSON download link. The datasets are locations (permission `locations:read`, with fraud detail on request), events and conversions (`events:read`), and SDK device logs (`logs:read`). A logs query must name a user, device, installation, or session. |
| `get_query_page` | Reads another page of records from a completed query. |
| `render_locations_map` | Displays the results of a completed locations query on an interactive map in a client that supports MCP apps, such as Claude and ChatGPT. |
| `geocode` | Converts an address to coordinates, or coordinates to an address. |
| `get_dashboard_urls` | Formats links to users, devices, events, locations, geofences, and trips in the Radar dashboard from IDs in query results. |

## Run a first query

1. Pick a user that has recent locations in the environment you authorized, for example `user-123`.
2. Ask the assistant: `Show the five most recent locations for user user-123 from the last 7 days.`
3. Approve the tool call if your client asks. The assistant calls `query_data`, reports how many records matched, and summarizes up to three preview records.
4. Open the same user in the Radar dashboard and compare the latest location's time and coordinates with the assistant's answer.

The connection works when the records match. If something goes wrong:

| Symptom | What to do |
| --- | --- |
| The assistant has no Radar tools, or answers without calling one. | Turn on Radar in the conversation's connector menu, or ask a workspace administrator whether custom connections are blocked. |
| A query requires a permission such as `events:read`. | Disconnect, reconnect, and allow the permission on the consent screen. |
| A query returns no records. | Check the authorized project and environment, the user or device ID, and the time range. |
| A query times out. | Narrow the time range and add a user, device, or geography filter. |

## Limitations

- A connection covers one project and one environment. To query another, disconnect and reconnect.
- A query returns at most 1,000 records, and the inline preview holds at most three. Ask the assistant to read more pages, or use the JSON download, before you draw conclusions about the full query.
- Queries can take up to several minutes for large ranges, and return only data within your project's retention period.
- Download links expire at the `expiresAt` time returned with each result. Until then, anyone who has the link can download its results.

## FAQ

### What data does the AI provider receive?

The provider receives the tool results used in your conversation. These can include coordinates, timestamps, user or device identifiers, device information, and fraud details. Radar doesn't send your project's secret key to the assistant. Once results are in a conversation or downloaded, they fall under your AI provider's retention policies and your own storage practices, and Radar can't delete those copies. See [Radar's privacy notice](https://radar.com/privacy).

### Will my data be used to train AI models?

That depends on your AI provider's terms and your account or workspace settings, not on Radar. Review your provider's data controls before you connect customer data.

### How do I disconnect?

Turn off or remove Radar in your AI provider's connector or plugin settings. If you need help revoking Radar authorization, contact [Radar support](https://radar.com/support).
