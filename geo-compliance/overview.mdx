Geo-compliance verifies that a user is in a location where your product is allowed, and that the location can be trusted. At the end of this quickstart, your app runs one verified location check, your backend verifies the returned geolocation token and reads `passed`, and you have seen both a passed and a failed check.

<Info>
  Fraud is available on the [Enterprise plan](https://radar.com/pricing).
</Info>

## Quickstart

This is the whole implementation at a glance: the client runs one check on each platform, and the sections below explain each part.

<CodeGroup>

```swift Swift
import CoreLocation
import RadarSDK

final class LocationCheck: NSObject, CLLocationManagerDelegate {
  private let locationManager = CLLocationManager()

  func start() {
    Radar.initialize(publishableKey: "prj_test_pk_...")
    Radar.setUserId("user-123")
    Radar.setProduct("sportsbook")

    locationManager.delegate = self
    locationManager.requestWhenInUseAuthorization()
  }

  func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
    let status = manager.authorizationStatus
    if status == .authorizedWhenInUse || status == .authorizedAlways {
      check(reason: "login")
    }
  }

  func check(reason: String) {
    Radar.trackVerified(
      beacons: false,
      desiredAccuracy: .medium,
      reason: reason,
      transactionId: nil
    ) { (status, token) in
      guard status == .success, let token = token, let jwt = token.token else {
        showCheckError(status)
        return
      }

      if token.passed {
        sendTokenToBackend(jwt)
      } else {
        showFailure(token.failureReasons ?? [])
      }
    }
  }
}
```

```kotlin Kotlin
import android.Manifest
import android.os.Bundle
import androidx.activity.result.contract.ActivityResultContracts
import androidx.appcompat.app.AppCompatActivity
import io.radar.sdk.Radar
import io.radar.sdk.RadarInitializeOptions

class MainActivity : AppCompatActivity() {
  private val requestLocation =
    registerForActivityResult(ActivityResultContracts.RequestMultiplePermissions()) { grants ->
      if (grants.values.any { it }) check("login")
    }

  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)

    Radar.initialize(
      context = this,
      publishableKey = "prj_test_pk_...",
      options = RadarInitializeOptions(fraud = true)
    )
    Radar.setUserId("user-123")
    Radar.setProduct("sportsbook")

    requestLocation.launch(
      arrayOf(
        Manifest.permission.ACCESS_FINE_LOCATION,
        Manifest.permission.ACCESS_COARSE_LOCATION
      )
    )
  }

  private fun check(reason: String) {
    Radar.trackVerified(reason = reason) { status, token ->
      if (status != Radar.RadarStatus.SUCCESS || token == null) {
        showCheckError(status)
        return@trackVerified
      }

      if (token.passed) {
        sendTokenToBackend(token.token)
      } else {
        showFailure(token.failureReasons)
      }
    }
  }
}
```

The backend verifies the token and reads `passed`:

<CodeGroup>

```javascript Node.js
import express from 'express';
import { jwtVerify } from 'jose';
import { requireSession } from './auth.js';

const secret = new TextEncoder().encode(process.env.RADAR_JWT_SECRET_KEY);
const app = express();
app.use(express.json());

app.post('/api/wagers', requireSession, async (req, res) => {
  let payload;
  try {
    ({ payload } = await jwtVerify(req.body.geolocationToken, secret, {
      algorithms: ['HS256'],
    }));
  } catch (err) {
    return res.status(401).json({ error: 'invalid_geolocation_token' });
  }

  if (payload.user?.userId !== req.session.userId || payload.product !== 'sportsbook') {
    return res.status(401).json({ error: 'invalid_geolocation_token' });
  }

  if (payload.passed !== true) {
    return res.status(403).json({ passed: false, failureReasons: payload.failureReasons });
  }

  // Place the wager.
  res.status(201).json({ placed: true });
});
```

```python Python
import os

import jwt  # PyJWT
from flask import Flask, jsonify, request, session

app = Flask(__name__)
app.secret_key = os.environ["SESSION_SECRET_KEY"]
SECRET = os.environ["RADAR_JWT_SECRET_KEY"]


@app.post("/api/wagers")
def place_wager():
    if "user_id" not in session:
        return jsonify(error="not_signed_in"), 401

    body = request.get_json(silent=True) or {}
    try:
        payload = jwt.decode(body.get("geolocationToken", ""), SECRET, algorithms=["HS256"])
    except jwt.InvalidTokenError:
        return jsonify(error="invalid_geolocation_token"), 401

    user_id = (payload.get("user") or {}).get("userId")
    if user_id != session["user_id"] or payload.get("product") != "sportsbook":
        return jsonify(error="invalid_geolocation_token"), 401

    if payload.get("passed") is not True:
        return jsonify(passed=False, failureReasons=payload.get("failureReasons", [])), 403

    # Place the wager.
    return jsonify(placed=True), 201
```

The rest of the quickstart has four parts: configure where your product is allowed, run a check in your app, validate the token on your backend, and produce both results.

### Before you start

- Enable Fraud for your project: under **Fraud** on the [Settings](https://dashboard.radar.com/settings#fraud-settings) page of the Radar dashboard, select **Yes** for **Enabled**.
- Have a backend route that knows which user is signed in.
- For a native macOS or Windows app, ask your Radar account team for the Mac or Windows SDK. See [Verify from a native desktop app](/geo-compliance/gaming#verify-from-a-native-desktop-app).

Your backend also needs your project's JWT secret key, which is a different value from the API keys in the table. [Validate the token on your backend](#validate-the-token-on-your-backend) shows where to find it.

## Configure where your product is allowed

In the **Fraud** section of the [Settings](https://dashboard.radar.com/settings#fraud-settings) page, set the country list and state list for your project. Each list is an allowlist or a blocklist, and an empty list allows every country or state. For this quickstart, allow the state you are testing from, so that the first check passes.

Whether you can edit these lists yourself is account-specific. If the controls are read-only, ask your Radar account team to set them.

## See a passed and a failed result

Run the flow twice, once for each result.

For the passed result, sign in as `user-123` from an allowed state and trigger the action. After signature verification, the decoded payload includes these fields:

```json
{
  "_id": "66f1c2a9e4b0a1b2c3d4e5f6",
  "passed": true,
  "failureReasons": [],
  "warningReasons": [],
  "product": "sportsbook",
  "reason": "login",
  "expiresIn": 1200,
  "user": {
    "userId": "user-123",
    "live": false,
    "state": {
      "code": "NJ",
      "allowed": true,
      "passed": true
    },
    "fraud": {
      "passed": true,
      "verified": true
    }
  }
}
```

`passed` is `true`, so your backend performs the action.

For the failed result, produce a failed check without changing location. On the **Block rules** page in the dashboard, create a rule that blocks the user ID `user-123`, then trigger the action again. The request succeeds, and the token now carries a failed result:

```json
{
  "_id": "66f1c2a9e4b0a1b2c3d4e5f7",
  "passed": false,
  "failureReasons": ["fraud_blocked_user_id"],
  "warningReasons": [],
  "product": "sportsbook",
  "reason": "login",
  "expiresIn": 1200,
  "user": {
    "userId": "user-123",
    "live": false,
    "state": {
      "code": "NJ",
      "allowed": true,
      "passed": true
    },
    "fraud": {
      "passed": false,
      "verified": true,
      "blocked": true
    }
  }
}
```

`passed` is `false`, so your backend rejects the action and returns `failureReasons`.

The payloads are synthetic and omit most fields, and your `expiresIn` differs because Radar sets the expiry for each check. For the full payload, see [Geolocation token schema](/api/geolocation-tokens).

Now confirm that your backend reads `passed` from the token and from nowhere else. With the block rule in place, send the protected request to your backend directly, with `"passed": true` in the request body and the failed token. Your backend must still reject it.

Remove the block rule when you finish. For the full test procedure, including bypass rules for internal testing, see [Test the integration](/geo-compliance/gaming#test-the-integration).

## How it works

Every Geo-compliance integration follows the same eight steps. The two guides add the details for each kind of product.

| Step | Where it happens | What you do |
| --- | --- | --- |
| 1. Configure the product and footprint | The dashboard | Enable Fraud, define products if you have more than one, and set the countries and states where each is allowed. |
| 2. Initialize the SDK | Your app | Install the Radar SDK and the fraud plugin, and initialize with a publishable key. |
| 3. Identify the user | Your app | Call `Radar.setUserId()` with the ID of the signed-in user. |
| 4. Run a verified location check | Your app | Call `Radar.trackVerified()` with a reason. Radar returns a signed geolocation token. |
| 5. Send the token to your backend | Your app to your backend | Send it on an authenticated request. |
| 6. Validate the token | Your backend | Verify the signature and expiry, then check the user and product. |
| 7. Enforce the result | Your backend | Read `passed`. Perform the action when it is `true`, and reject it when it is `false`. |
| 8. Recheck | Your app | Run a new check before the token expires, when the product or user changes, and before sensitive actions. |

A backend can't produce a verified location result by itself. The check has to run on the user's device, because that is where the location and integrity signals come from.
