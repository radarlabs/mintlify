At the end of this page you have the Radar Cordova plugin installed, the native iOS and Android projects configured, and a reference for every method and listener the plugin exposes.

This page documents `@radarlabs/cordova-plugin-radar` 3.9.1. The source is on [GitHub](https://github.com/radarlabs/cordova-plugin-radar) and the package is on [npm](https://www.npmjs.com/package/@radarlabs/cordova-plugin-radar).

## Versions and feature availability

| Item | `@radarlabs/cordova-plugin-radar` 3.9.1 |
| --- | --- |
| Platforms | iOS and Android. |
| iOS SDK | `RadarSDK` 3.9.14, added by the plugin as a CocoaPods dependency. |
| Android SDK | `io.radar:sdk:3.9.8`, added by the plugin as a Gradle dependency. |
| Latest release | 3.9.1, published in April 2024. |

The plugin pairs with the 3.9 native SDKs. Methods and options added to the native SDKs after those versions aren't available through the plugin. If your hybrid app needs them, the [Capacitor SDK](/sdk/capacitor) pairs with newer native SDKs.

| Feature | Available | Notes |
| --- | --- | --- |
| Foreground and background tracking | Yes | Presets, custom options, mock tracking, listeners. |
| Trips | Yes | `startTrip()`, `updateTrip()`, `completeTrip()`, `cancelTrip()`. No multi-leg methods. |
| Verified location (Geo-compliance and Fraud) | Partial | `trackVerified()`, `trackVerifiedToken()`, and `startTrackingVerified()` from the 3.9 SDKs are exposed. See [Verified location](#verified-location). |
| Beacons | Yes | `beacons` option on `trackOnce()`, `trackVerified()`, and tracking options. |
| Maps and address UI | No | The plugin has no map or autocomplete component. |
| In-app messages | No | Not exposed in 3.9.1. |

The plugin doesn't expose user tags, product, or initialization options. For how the wrappers compare, see [SDK overview and compatibility](/sdk/sdk).

## Install

Install the Cordova plugin:

```bash
cordova plugin add @radarlabs/cordova-plugin-radar
```

The plugin adds the Radar iOS and Android SDKs to the native projects. Finish the native configuration below before you write any JavaScript.

### iOS

The plugin writes three location usage descriptions to `Info.plist` with a generic default string. Set your own text when you add the plugin. These strings appear in the permission prompts.

```bash
cordova plugin add @radarlabs/cordova-plugin-radar \
  --variable NS_LOCATION_WHEN_IN_USE_USAGE_DESCRIPTION="Your foreground location usage description." \
  --variable NS_LOCATION_ALWAYS_AND_WHEN_IN_USE_USAGE_DESCRIPTION="Your background location usage description." \
  --variable NS_LOCATION_ALWAYS_USAGE_DESCRIPTION="Your background location usage description."
```

For background tracking with the responsive or continuous preset, open the app target in Xcode, select **Signing & Capabilities**, add **Background Modes**, and select **Location updates** and **Background fetch**.

Then initialize the SDK in `application:didFinishLaunchingWithOptions:` in `AppDelegate.m` with your publishable key:

```objc
#import <RadarSDK/RadarSDK.h>

@implementation AppDelegate

- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
  [Radar initializeWithPublishableKey:@"prj_test_pk_..."];
  // Keep the rest of the generated method.
  return [super application:application didFinishLaunchingWithOptions:launchOptions];
}

@end
```

### Android

Add Google Play Services Location to your app. The plugin adds `io.radar:sdk` itself.

Initialize the SDK in `onCreate()` in `MainActivity.java` with your publishable key. Keep the rest of the generated method as it is.

```java
import android.os.Bundle;

import org.apache.cordova.CordovaActivity;

import io.radar.sdk.Radar;

public class MainActivity extends CordovaActivity {

  @Override
  public void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    Radar.initialize(this, "prj_test_pk_...");
    loadUrl(launchUrl);
  }

}
```

The plugin changes your `AndroidManifest.xml` in two ways:

- It adds the `FOREGROUND_SERVICE` permission.
- It adds a `tools:node="remove"` rule for `ACCESS_BACKGROUND_LOCATION`, which strips that permission from the merged manifest.

<Warning>
  Android grants only permissions that are declared in the merged manifest, so the remove rule can leave your app without background location permission.
</Warning>

Inspect the merged manifest of your build before you rely on background location permission on Android. If `ACCESS_BACKGROUND_LOCATION` isn't in the merged manifest, `requestPermissions(true)` can't obtain background permission, and on Android 10 and later the app receives location in the background only while a foreground service is running. For [background tracking](#background-tracking), that means:

- **Continuous preset**: Runs a foreground service with a notification (`foregroundServiceEnabled` is `true`), so it keeps tracking in the background with foreground permission.
- **Efficient and responsive presets**: Don't run a foreground service, so they track only while the app is in the foreground.
- **Custom options**: Set `foregroundServiceEnabled: true` in `startTrackingCustom()` to track in the background with foreground permission.

## Integrate

The plugin is available as `cordova.plugins.radar` after the `deviceready` event.

Methods that return data take a callback as the last argument. They don't return promises. If the native call fails before it reaches the Radar API, for example because a required argument is missing, the plugin logs the error with `console.error` and doesn't call your callback.

### Initialize

Initialize natively as described in [iOS](#ios) and [Android](#android), so the SDK is ready when the operating system relaunches the app in the background. You can also initialize from JavaScript:

```javascript
cordova.plugins.radar.initialize('prj_test_pk_...');
```

Use your test publishable key (`prj_test_pk_...`) in development and your live publishable key (`prj_live_pk_...`) in production.

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

### Identify user

Identify the user with an ID, metadata, and a description:

```javascript
cordova.plugins.radar.setUserId('user-123');
cordova.plugins.radar.setMetadata({ tier: 'gold', orders: 12, optedIn: true });
cordova.plugins.radar.setDescription('Example user');
```

| Method | Argument |
| --- | --- |
| `setUserId(userId)` | A stable unique ID for the user. |
| `setMetadata(metadata)` | An object with string, number, or boolean values. Radar accepts up to 16 keys. |
| `setDescription(description)` | A string shown in the Radar dashboard. |

These values persist across app sessions, so call each setter once, for example after login. `getUserId(callback)`, `getMetadata(callback)`, and `getDescription(callback)` pass the stored value to the callback.

`cordova.plugins.radar.setAnonymousTrackingEnabled(enabled)` turns anonymous tracking on or off.

### Debug logging

By default, only critical errors are logged to the console. To change the level, call:

```javascript
cordova.plugins.radar.setLogLevel('debug');
```

Valid levels are `'error'`, `'warning'`, `'info'`, and `'debug'`.

`logBackgrounding()` and `logResigningActive()` record app lifecycle events. `logTermination()` does the same on iOS only.

### Request permissions

The user must grant location permission before you track. To read the current status, call:

```javascript
cordova.plugins.radar.getPermissionsStatus((status) => {
  // do something with status
});
```

`status` is a string, one of:

- `GRANTED_BACKGROUND`
- `GRANTED_FOREGROUND`
- `DENIED`
- `UNKNOWN`

`UNKNOWN` is reported on iOS only, when the user hasn't been asked yet. On Android versions below API level 29, the plugin reports `GRANTED_BACKGROUND` when location permission is granted.

To request permission, call:

```javascript
cordova.plugins.radar.requestPermissions(false); // foreground
cordova.plugins.radar.requestPermissions(true);  // background
```

The argument is a boolean: `true` requests background permission and `false` requests foreground permission. Request foreground permission first. The call doesn't report the result, so call `getPermissionsStatus()` afterward.

To verify, build and run the app on a device and confirm the prompts appear. For when to ask for each level, see [Understand foreground and background location permissions](/fundamentals/location-permissions).

### Foreground tracking

After the SDK is initialized and the user grants permission, track the user's location once:

```javascript
cordova.plugins.radar.trackOnce((result) => {
  if (result.status === 'SUCCESS') {
    // do something with result.location, result.events, result.user
  }
});
```

To set accuracy or range beacons, pass an options object first:

```javascript
cordova.plugins.radar.trackOnce({ desiredAccuracy: 'high', beacons: false }, (result) => {
  // do something with result.status
});
```

`desiredAccuracy` is `'high'`, `'medium'`, `'low'`, or `'none'` and defaults to `'medium'`.

The callback always receives a `status`. It is a string, one of:

- **`SUCCESS`**: success
- **`ERROR_PUBLISHABLE_KEY`**: SDK not initialized
- **`ERROR_PERMISSIONS`**: location permissions not granted
- **`ERROR_LOCATION`**: location services error or timeout
- **`ERROR_BLUETOOTH`**: beacon ranging error or timeout
- **`ERROR_NETWORK`**: network error or timeout
- **`ERROR_BAD_REQUEST`**: bad request (missing or invalid params)
- **`ERROR_UNAUTHORIZED`**: unauthorized (invalid API key)
- **`ERROR_PAYMENT_REQUIRED`**: payment required (organization disabled or usage exceeded)
- **`ERROR_FORBIDDEN`**: forbidden (insufficient permissions or no beta access)
- **`ERROR_NOT_FOUND`**: not found
- **`ERROR_RATE_LIMIT`**: too many requests (rate limit exceeded)
- **`ERROR_SERVER`**: internal server error
- **`ERROR_UNKNOWN`**: unknown error

`cordova.plugins.radar.getLocation(desiredAccuracy, callback)` reads the device location without sending it to Radar. `desiredAccuracy` is `'high'`, `'medium'`, or `'low'`. The callback receives `{ status, location, stopped }`.

### Background tracking

After the SDK is initialized and the user grants permission, start tracking in the background. The SDK supports custom tracking options and three presets:

- **`EFFICIENT`**: A low frequency of location updates and the lowest battery usage. On Android, avoids Android vitals bad behavior thresholds.
- **`RESPONSIVE`**: A medium frequency of location updates and low battery usage. Suitable for most consumer use cases.
- **`CONTINUOUS`**: A high frequency of location updates and higher battery usage. Suitable for on-demand use cases such as delivery tracking.

Start tracking with one of the presets:

```javascript
cordova.plugins.radar.startTrackingEfficient();

cordova.plugins.radar.startTrackingResponsive();

cordova.plugins.radar.startTrackingContinuous();
```

Call one of these once. Tracking options persist across app sessions.

Presets cover most use cases. To customize, pass tracking options to `startTrackingCustom()`. For field meanings, units, and defaults, see the [tracking options reference](/sdk/tracking). This plugin pairs with the 3.9 SDKs, so options added later aren't recognized.

```javascript
// Android only: configure the foreground service notification
cordova.plugins.radar.setForegroundServiceOptions({
  text: 'Location tracking started',
  title: 'Location updates',
  updatesOnly: false,
  importance: 2,
  activity: 'com.example.app.MainActivity'
});

cordova.plugins.radar.startTrackingCustom({
  desiredStoppedUpdateInterval: 180,
  desiredMovingUpdateInterval: 60,
  desiredSyncInterval: 50,
  desiredAccuracy: 'high',
  stopDuration: 140,
  stopDistance: 70,
  sync: 'all',
  replay: 'none',
  showBlueBar: true,
  foregroundServiceEnabled: true
});
```

`setForegroundServiceOptions()` takes the options object directly and does nothing on iOS.

To check and stop tracking:

```javascript
cordova.plugins.radar.isTracking((tracking) => {
  // tracking is a boolean
});

cordova.plugins.radar.stopTracking();
```

`cordova.plugins.radar.getTrackingOptions(callback)` passes the options in use to the callback.

#### Listen for events

Register a callback for each update you want:

```javascript
cordova.plugins.radar.onClientLocation((location, stopped, source) => {
  // do something with location, stopped, source
});

cordova.plugins.radar.onLocation((location, user) => {
  // do something with location, user
});

cordova.plugins.radar.onEvents((events, user) => {
  // do something with events, user
});

cordova.plugins.radar.onError((status) => {
  // do something with status
});
```

| Listener | Callback arguments |
| --- | --- |
| `onClientLocation` | `location`, `stopped`, `source` |
| `onLocation` | `location`, `user` |
| `onEvents` | `events`, `user` |
| `onError` | `status` |
| `onToken` | `token`. See [Verified location](#verified-location). |

Register listeners once, before tracking begins. Listeners fire while the Cordova web view is running. Register them outside your view lifecycle if you want them to keep firing while the app is in the background. To act on events when your app isn't running, use the native delegate or receiver described in the [iOS SDK reference](/sdk/ios) and [Android SDK reference](/sdk/android), or send events to your backend with [webhooks](/integrations/webhooks).

To remove listeners:

```javascript
cordova.plugins.radar.offClientLocation();

cordova.plugins.radar.offLocation();

cordova.plugins.radar.offEvents();

cordova.plugins.radar.offToken();
```

<Note>
  In version 3.9.1, `offError()` removes the events listener, not the error listener.
</Note>

If you still need `onEvents()`, don't call `offError()`.

### Mock tracking

To simulate a sequence of location updates for testing, call `mockTracking()`. This example simulates 10 updates, 3 seconds apart, by car. The optional callback receives the result of each update.

```javascript
cordova.plugins.radar.mockTracking({
  origin: { latitude: 40.714708, longitude: -74.035807 },
  destination: { latitude: 40.717410, longitude: -74.053334 },
  mode: 'car',
  steps: 10,
  interval: 3
}, (result) => {
  // do something with result.status, result.location, result.events, result.user
});
```

### Trip tracking

Start a trip to a destination geofence. Pass `tripOptions` and optional `trackingOptions`. `trackingOptions` applies while the trip is active.

```javascript
cordova.plugins.radar.startTrip({
  tripOptions: {
    externalId: 'order-299',
    destinationGeofenceTag: 'store',
    destinationGeofenceExternalId: 'store-42',
    mode: 'car'
  },
  trackingOptions: {
    desiredStoppedUpdateInterval: 30,
    desiredMovingUpdateInterval: 30,
    desiredSyncInterval: 20,
    desiredAccuracy: 'high',
    stopDuration: 140,
    stopDistance: 70,
    sync: 'all',
    replay: 'none',
    showBlueBar: true,
    foregroundServiceEnabled: true
  }
}, (result) => {
  // do something with result.status, result.trip, result.events
});
```

The plugin also accepts the older form, where you pass the trip options object directly and start tracking yourself:

```javascript
cordova.plugins.radar.startTrip({
  externalId: 'order-299',
  destinationGeofenceTag: 'store',
  destinationGeofenceExternalId: 'store-42',
  mode: 'car'
}, (result) => {
  // do something with result.status
});
cordova.plugins.radar.startTrackingContinuous();
```

Update the trip. `options` is required. Leave out `status`, or set it to `'unknown'`, to keep the current status and let location tracking update it.

```javascript
cordova.plugins.radar.updateTrip({
  status: 'arrived',
  options: {
    externalId: 'order-299',
    metadata: {
      parkingSpot: '5'
    }
  }
}, (result) => {
  // do something with result.status
});
```

Complete or cancel the trip:

```javascript
cordova.plugins.radar.completeTrip((result) => {
  // do something with result.status
});

cordova.plugins.radar.cancelTrip((result) => {
  // do something with result.status
});
```

If you started tracking yourself, call `cordova.plugins.radar.stopTracking()` when the trip ends.

`cordova.plugins.radar.getTripOptions(callback)` passes the current trip options to the callback.

For the full workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

### Manual tracking

To send a location you already have, pass it under the `location` key:

```javascript
cordova.plugins.radar.trackOnce({
  location: {
    latitude: 39.2904,
    longitude: -76.6122,
    accuracy: 65
  }
}, (result) => {
  // do something with result.status, result.location, result.events, result.user
});
```

### Verified location

The plugin exposes the verified location methods of the 3.9 native SDKs:

| Method | Description |
| --- | --- |
| `trackVerified(options?, callback)` | Runs a verified location check. Option: `beacons`. The callback receives `status`, `location`, `events`, and `user`. |
| `trackVerifiedToken(options?, callback)` | Runs a verified location check and returns a token. Option: `beacons`. The callback receives `status` and `token`. |
| `startTrackingVerified(options?)` | Starts periodic verified checks. Options: `token` (boolean), `interval`, `beacons`. |
| `onToken(callback)`, `offToken()` | Listen for new tokens. |

On iOS, `trackVerified()` and `trackVerifiedToken()` call your callback only on success.

These methods predate the current fraud plugin and token APIs on the native SDKs. Before you build a Geo-compliance or Fraud integration on Cordova, read [Fraud plugin setup](/sdk/fraud) and confirm support for your use case with your Radar account team.

### Beacons

To range beacons on a single call, pass `beacons: true` in the options for `trackOnce()` or `trackVerified()`. To range during background tracking, set `beacons: true` in your tracking options.

Beacon ranging needs Bluetooth permission and native setup. See [Track indoor location with beacons](/geofencing/beacons).

### Other APIs

The plugin also exposes context, geocoding, search, routing, and conversion APIs. Each takes a callback that receives an object with a `status`.

#### Context

Get context for the device location:

```javascript
cordova.plugins.radar.getContext((result) => {
  // do something with result.status, result.location, result.context
});
```

Pass `{ latitude, longitude }` as the first argument to use a location you already have.

#### Geocoding

Forward geocode an address with the [geocoding API](/api/geocoding):

```javascript
cordova.plugins.radar.geocode('20 jay st brooklyn ny', (result) => {
  // do something with result.status, result.addresses
});
```

Reverse geocode a location. Omit the first argument to use the device location.

```javascript
cordova.plugins.radar.reverseGeocode({
  latitude: 40.783826,
  longitude: -73.975363
}, (result) => {
  // do something with result.status, result.addresses
});
```

Geocode the device's IP address to a city, state, and country:

```javascript
cordova.plugins.radar.ipGeocode((result) => {
  // do something with result.status, result.address
});
```

#### Search

Autocomplete partial addresses and place names with the [search API](/api/search). Pass `country`: the Android implementation requires it. `layers` and `mailable` are optional.

```javascript
cordova.plugins.radar.autocomplete({
  query: 'brooklyn roasting',
  near: {
    latitude: 40.783826,
    longitude: -73.975363
  },
  limit: 10,
  country: 'US'
}, (result) => {
  // do something with result.status, result.addresses
});
```

Search for geofences near a location, sorted by distance. Omit `near` to search near the device location. `radius` is in meters.

```javascript
cordova.plugins.radar.searchGeofences({
  radius: 1000,
  tags: ['venue'],
  limit: 10
}, (result) => {
  // do something with result.status, result.geofences
});
```

Search for places near a location, sorted by distance. Filter with `chains`, `chainMetadata`, `categories`, or `groups`.

```javascript
cordova.plugins.radar.searchPlaces({
  near: {
    latitude: 40.783826,
    longitude: -73.975363
  },
  radius: 1000,
  chains: ['starbucks'],
  limit: 10
}, (result) => {
  // do something with result.status, result.places
});
```

#### Distance

Calculate travel distance and duration from an origin to a destination with the [routing API](/api/routing). Omit `origin` to use the device location.

```javascript
cordova.plugins.radar.getDistance({
  origin: {
    latitude: 40.78382,
    longitude: -73.97536
  },
  destination: {
    latitude: 40.70390,
    longitude: -73.98670
  },
  modes: [
    'foot',
    'car'
  ],
  units: 'imperial'
}, (result) => {
  // do something with result.status, result.routes
});
```

#### Matrix

Calculate travel distance and duration between multiple origins and destinations, for up to 25 routes. `origins` and `destinations` are flat arrays of locations.

```javascript
cordova.plugins.radar.getMatrix({
  origins: [
    {
      latitude: 40.78382,
      longitude: -73.97536
    }
  ],
  destinations: [
    {
      latitude: 40.70390,
      longitude: -73.98670
    },
    {
      latitude: 40.73237,
      longitude: -73.94884
    }
  ],
  mode: 'car',
  units: 'imperial'
}, (result) => {
  // do something with result.status, result.matrix
});
```

#### Conversions

Log a conversion, such as a purchase or signup, to analyze alongside location activity. Pass `name` and `metadata`. `revenue` is optional.

```javascript
cordova.plugins.radar.logConversion({
  name: 'purchase',
  revenue: 12.5,
  metadata: { sku: 'example-sku' }
}, (result) => {
  // do something with result.status, result.event
});
```

### Notification options

On Android, `setNotificationOptions()` sets the icon and color of the foreground service notification and event notifications. Values are resource names in your Android project.

```javascript
cordova.plugins.radar.setNotificationOptions({
  iconString: 'icon_1',
  iconColor: 'color_1'
});
```

This method is Android only.
