The Radar Android SDK adds location tracking, geofencing, trip tracking, verified location, geocoding, search, and routing to your Android app. At the end of the setup sections, your app initializes the SDK, and a `Radar.trackOnce()` call returns `RadarStatus.SUCCESS` with a location and a user that you can find in the Radar dashboard.

This page documents Android SDK 4.3.0. The [source](https://github.com/radarlabs/radar-sdk-android) and the [releases](https://github.com/radarlabs/radar-sdk-android/releases) are on GitHub.

Most examples are in Kotlin. Every method is also callable from Java through a callback interface, and the core setup examples show both.

## Install SDK

We recommend adding the SDK to your project with Gradle in Android Studio.

### Gradle (recommended)

The SDK is distributed using [Maven Central](https://search.maven.org/artifact/io.radar/sdk).

Add the SDK to the `dependencies` section of your app's `build.gradle` file:

```gradle
dependencies {
  implementation 'io.radar:sdk:4.3.+'
}
```

### Add manually

You can also add the SDK to your project manually. Download [the current release](https://github.com/radarlabs/radar-sdk-android/releases) and unzip the package. The package contains an `aar` file. Add the `aar` file to your app module as a local dependency.

## Dependencies

| Requirement | Value |
| --- | --- |
| Minimum Android version | API level 23 (Android 6.0), from Android SDK 4.0.0. Earlier SDK versions support lower API levels. |
| Build tooling | Android Gradle Plugin 7.0 or later, from Android SDK 4.0.0. The SDK is compiled to Java 11 bytecode. You don't need to change your own `compileOptions`. |
| Location services | [Google Play Services Location](https://developer.android.com/training/location) 21.0.1 or later, added automatically as a transitive dependency. |

If you haven't already configured your project for Google Play Services, follow the [Google services setup instructions](https://developers.google.com/android/guides/google-services-plugin).

If another dependency that depends on `play-services-location` causes version conflicts, you can exclude the transitive dependency and include `play-services-location` at the project level instead. Use 21.0.1 or later.

As an alternative to Google Play Services, the SDK optionally supports [Huawei Mobile Services](#huawei).

### Optional dependencies

Some SDK features need a library that the SDK doesn't add for you. Add the library only if you use the feature:

| Feature | Library |
| --- | --- |
| [Huawei Mobile Services](#huawei) | `com.huawei.hms:location` |
| [Silent push](/sdk/silent-push) | `com.google.firebase:firebase-messaging` |
| [Verified location](#verified-location) | The Radar fraud plugin. See [Fraud plugin setup](/sdk/fraud). |

From Android SDK 4.3.0, the SDK includes R8 rules for the Huawei and Firebase libraries. You don't need to add `-dontwarn` rules to your `proguard-rules.pro` file when you minify your app. If you added these rules for an earlier SDK version, you can remove them:

```proguard
-dontwarn com.huawei.hmf.tasks.**
-dontwarn com.huawei.hms.location.**
-dontwarn com.google.firebase.FirebaseApp
-dontwarn com.google.firebase.messaging.**
```

## Initialize SDK

When your app starts, initialize the SDK with your publishable key from the [Settings](https://dashboard.radar.com/settings) page. Call `Radar.initialize()` on the main thread in `Application.onCreate()`, before you call any other Radar method.

Use your test publishable key (`prj_test_pk_...`) for the Test environment and your live publishable key (`prj_live_pk_...`) for the Live environment.

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

`Radar.initialize()` has three forms:

```kotlin
Radar.initialize(context: Context?, publishableKey: String? = null)
Radar.initialize(context: Context, publishableKey: String?, options: RadarInitializeOptions = RadarInitializeOptions())
Radar.initialize(context: Context, options: RadarInitializeOptions)
```

For example, in your `Application` class:

<CodeGroup>

```kotlin Kotlin
import android.app.Application
import io.radar.sdk.Radar

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        Radar.initialize(this, "prj_test_pk_...")
    }
}
```

```java Java
import android.app.Application;
import io.radar.sdk.Radar;

public class MyApplication extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        Radar.initialize(this, "prj_test_pk_...");
    }
}
```

</CodeGroup>

Register your `Application` class in the manifest with `android:name` on the `<application>` element.

`Radar.isInitialized()` returns `true` after initialization. `Radar.sdkVersion()` returns the SDK version string.

### Initialization options

`RadarInitializeOptions` is a Kotlin data class. From Java, use `RadarInitializeOptions.Builder`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `radarReceiver` | `RadarReceiver?` | `null` | A receiver for client-side delivery of events. See [Listening for events with a receiver](#listening-for-events-with-a-receiver). |
| `locationProvider` | `Radar.RadarLocationServicesProvider` | `GOOGLE` | The location services provider, `GOOGLE` or `HUAWEI`. See [Huawei](#huawei). |
| `fraud` | `Boolean` | `false` | Whether to enable additional fraud detection signals for location verification. See [Fraud plugin setup](/sdk/fraud). |
| `customForegroundNotification` | `Notification?` | `null` | A custom notification for the foreground service. |
| `inAppMessageReceiver` | `RadarInAppMessageReceiver?` | `null` | A receiver for in-app message events. See [In-app messages](#in-app-messages). |
| `silentPush` | `Boolean` | `false` | Whether to configure silent push. See [Silent push](/sdk/silent-push). |
| `publishableKey` | `String?` | `null` | The publishable key, when you use `Radar.initialize(context, options)`. |
| `authToken` | `String?` | `null` | An auth token to use in place of a publishable key, when you use `Radar.initialize(context, options)`. Don't set both. See [Authenticate the SDK with auth tokens](/sdk/fraud#authenticate-the-sdk-with-auth-tokens). |
| `activity` | `Activity?` | `null` | An activity that overrides the activity from the context. |
| `networkTimeout` | `kotlin.time.Duration?` | `null` (10 seconds) | Connect and base read timeout for Radar API requests. See [Network timeout](#network-timeout). |
| `trackVerifiedAutoFailover` | `Boolean` | `true` | Whether `trackVerified()` retries against a secondary host when the primary host doesn't return a response from Radar. Added in 3.32.0. Enabled by default from 4.2.0. |
| `ipChangeDebounceInterval` | `kotlin.time.Duration?` | `null` (10 seconds) | Minimum interval between deliveries of `RadarVerifiedReceiver.onIpChanged`. Pass `Duration.ZERO` to deliver every detected change. |

`networkTimeout` and `ipChangeDebounceInterval` are persisted when you set them. If you pass `null`, the SDK uses the previously saved value, or the default.

For example, to pass options when you initialize the SDK:

<CodeGroup>

```kotlin Kotlin
import io.radar.sdk.Radar
import io.radar.sdk.RadarInitializeOptions

val options = RadarInitializeOptions(
    radarReceiver = MyRadarReceiver(),
    silentPush = false,
)
Radar.initialize(this, "prj_test_pk_...", options)
```

```java Java
import io.radar.sdk.Radar;
import io.radar.sdk.RadarInitializeOptions;

RadarInitializeOptions options = new RadarInitializeOptions.Builder()
    .radarReceiver(new MyRadarReceiver())
    .silentPush(false)
    .build();
Radar.initialize(this, "prj_test_pk_...", options);
```

</CodeGroup>

In Kotlin, an older overload also accepts `receiver`, `provider`, and `fraud` as arguments: `Radar.initialize(context, publishableKey, receiver, provider, fraud)`. Its parameters have Kotlin default values and no Java overloads, so from Java use `RadarInitializeOptions.Builder`.

### Network timeout

To override the default network timeout, set `networkTimeout` on `RadarInitializeOptions` as a Kotlin `Duration`. The extended timeout used for longer-running requests is automatically set to 2.5 times this value. Values are clamped to the range 1 to 300 seconds. For example, to set a 30-second timeout:

```kotlin
import io.radar.sdk.Radar
import io.radar.sdk.RadarInitializeOptions
import kotlin.time.Duration.Companion.seconds

val options = RadarInitializeOptions(networkTimeout = 30.seconds)
Radar.initialize(this, "prj_test_pk_...", options)
```

## Request permissions

Radar respects [standard Android location permissions](https://developer.android.com/training/permissions/requesting.html). The SDK doesn't show permission prompts. Your app requests runtime permissions.

### Manifest requirements

The SDK manifest merges these permissions into your app automatically:

- `ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION`
- `INTERNET` and `ACCESS_NETWORK_STATE`
- `RECEIVE_BOOT_COMPLETED`
- `FOREGROUND_SERVICE`

It also declares the SDK's own components: `RadarLocationReceiver`, `RadarBootReceiver` (which restores tracking after a reboot or an app update), and the `RadarJobScheduler` job service. You don't declare these yourself.

Add these to your app manifest yourself, only when you use the feature:

| Feature | What to add |
| --- | --- |
| Background tracking (`RESPONSIVE` or `EFFICIENT`) on API level 29 and later | `ACCESS_BACKGROUND_LOCATION` permission |
| Foreground service (`CONTINUOUS` or `foregroundServiceEnabled`) | `FOREGROUND_SERVICE_LOCATION` permission and, in Android SDK 4.0.0 and later, the `RadarForegroundService` declaration. See [Foreground services and Google Play policy](#foreground-services-and-google-play-policy). |
| [Beacons](#beacons) | Bluetooth permissions |
| [Location metadata](#location-metadata) | `ACTIVITY_RECOGNITION` permissions |
| [Silent push](/sdk/silent-push) | `RadarFirebaseMessagingService` declaration |

A manifest for background tracking and a foreground service:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
    <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
    <application>
        <service
            android:name="io.radar.sdk.RadarForegroundService"
            android:foregroundServiceType="location"
            tools:targetApi="26" />
    </application>
</manifest>
```

### Runtime permissions

| What you call | Required runtime permission |
| --- | --- |
| `Radar.trackOnce()`, `Radar.trackVerified()`, and other foreground calls | `ACCESS_FINE_LOCATION` for precise location, or `ACCESS_COARSE_LOCATION` for [approximate location](https://developer.android.com/about/versions/12/approximate-location) |
| `Radar.startTracking()` or a trip with `CONTINUOUS`, while the foreground service notification is shown | Foreground location permission |
| `Radar.startTracking()` with `RESPONSIVE` or `EFFICIENT` | `ACCESS_BACKGROUND_LOCATION` as well, on API level 29 and later |

Request foreground location permission first. On Android 11 (API level 30) and later, request `ACCESS_BACKGROUND_LOCATION` in a separate request after the user grants foreground permission. The system sends the user to a settings screen to choose **Allow all the time**.

For when to ask, how to explain each prompt, and how to handle denial and approximate location, see [Location permissions](/fundamentals/location-permissions).

If a permission prompt doesn't appear, check that the permission is in your merged manifest and that the device hasn't already recorded a choice for your app in Settings.

## Foreground tracking

Once the user has granted foreground permission, you can track the user's location in the foreground.

```kotlin
Radar.trackOnce(callback: RadarTrackCallback? = null)
Radar.trackOnce(desiredAccuracy: RadarTrackingOptionsDesiredAccuracy, beacons: Boolean, callback: RadarTrackCallback? = null)
```

| Parameter | Type | Description |
| --- | --- | --- |
| `desiredAccuracy` | `RadarTrackingOptions.RadarTrackingOptionsDesiredAccuracy` | `HIGH`, `MEDIUM`, `LOW`, or `NONE`. `trackOnce(callback)` uses `MEDIUM`, or `HIGH` on an emulator. |
| `beacons` | `Boolean` | Whether to range beacons. `trackOnce(callback)` uses `false`. |
| `callback` | `RadarTrackCallback?` | Optional. `onComplete` receives `(status: RadarStatus, location: Location?, events: Array<RadarEvent>?, user: RadarUser?)`. In Kotlin, you can pass a lambda instead. |

To track the user's location in the foreground, call:

<CodeGroup>

```kotlin Kotlin
Radar.trackOnce { status, location, events, user ->
    if (status == Radar.RadarStatus.SUCCESS) {
        // do something with location, events, user
    } else {
        Log.w("Radar", "trackOnce failed: $status")
    }
}
```

```java Java
Radar.trackOnce(new Radar.RadarTrackCallback() {
    @Override
    public void onComplete(@NonNull Radar.RadarStatus status, @Nullable Location location, @Nullable RadarEvent[] events, @Nullable RadarUser user) {
        // do something with location, events, user
    }
});
```

</CodeGroup>

These calls are subject to [rate limits](/api/fundamentals).

The request status can be:

| Status | Meaning |
| --- | --- |
| `RadarStatus.SUCCESS` | Success |
| `RadarStatus.ERROR_PUBLISHABLE_KEY` | SDK not initialized |
| `RadarStatus.ERROR_PERMISSIONS` | Location permissions not granted |
| `RadarStatus.ERROR_LOCATION` | Location services error or timeout (20 seconds) |
| `RadarStatus.ERROR_BLUETOOTH` | Beacon ranging error or timeout (5 seconds) |
| `RadarStatus.ERROR_NETWORK` | Network error or timeout (10 seconds by default; see [network timeout](#network-timeout)) |
| `RadarStatus.ERROR_BAD_REQUEST` | Bad request (missing or invalid params) |
| `RadarStatus.ERROR_UNAUTHORIZED` | Unauthorized (invalid API key) |
| `RadarStatus.ERROR_PAYMENT_REQUIRED` | Payment required (organization disabled or usage exceeded) |
| `RadarStatus.ERROR_FORBIDDEN` | Forbidden (insufficient permissions or no beta access) |
| `RadarStatus.ERROR_NOT_FOUND` | Not found |
| `RadarStatus.ERROR_PLUGIN` | Missing or incompatible plugin, such as the fraud plugin for `trackVerified()` |
| `RadarStatus.ERROR_RATE_LIMIT` | Too many requests (rate limit exceeded) |
| `RadarStatus.ERROR_SERVER` | Internal server error |
| `RadarStatus.ERROR_UNKNOWN` | Unknown error |

To check your integration, build and run the app, then find your user on the [Users](https://dashboard.radar.com/geofencing/users) page. To generate an event, first create a geofence around your location on the [Geofences](https://dashboard.radar.com/geofencing/geofences) page. If the user doesn't appear, check `status` in the callback.

### Get location

To get the device's current location without sending it to Radar, call:

```kotlin
Radar.getLocation(callback: RadarLocationCallback? = null)
Radar.getLocation(desiredAccuracy: RadarTrackingOptionsDesiredAccuracy, callback: RadarLocationCallback? = null)
```

`onComplete` receives `(status: RadarStatus, location: Location?, stopped: Boolean)`. For example:

```kotlin
Radar.getLocation(RadarTrackingOptions.RadarTrackingOptionsDesiredAccuracy.HIGH) { status, location, stopped ->
    // do something with location
}
```

## Background tracking for geofencing

Once you have initialized the SDK and the user has authorized background permission, you can start tracking the user's location in the background.

The SDK supports custom tracking options as well as three presets. See [Tracking options](/sdk/tracking).

For geofencing, use `RadarTrackingOptions.RESPONSIVE`. This preset detects whether the device is stopped or moving. When moving, it tells the SDK to send location updates to the server about every 2.5 minutes. When stopped, it tells the SDK to shut down to save battery. Once stopped, the device needs to move more than 100 meters to wake up and start moving again.

With background permission, background tracking works even if the app has been backgrounded or terminated by the system, because Android location services wake up the app to deliver location updates, and the SDK uses `JobScheduler` to schedule network requests.

Android can delay location updates significantly because of [Doze and App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby) and [background location limits](https://developer.android.com/about/versions/oreo/background-location-limits), or if the device has connectivity issues, low battery, or Wi-Fi turned off. In practice, location updates may be sent to the server every 5 to 10 minutes while moving, faster if the screen is on or if other apps are requesting location, and slower otherwise. These restrictions apply to all apps that use location services.

The tracking methods are:

```kotlin
Radar.startTracking(options: RadarTrackingOptions)
Radar.stopTracking()
Radar.isTracking(): Boolean
Radar.getTrackingOptions(): RadarTrackingOptions
Radar.isUsingRemoteTrackingOptions(): Boolean
```

To start tracking for geofencing, call:

<CodeGroup>

```kotlin Kotlin
Radar.startTracking(RadarTrackingOptions.RESPONSIVE)
```

```java Java
Radar.startTracking(RadarTrackingOptions.RESPONSIVE);
```

</CodeGroup>

To determine whether tracking has been started, call:

<CodeGroup>

```kotlin Kotlin
Radar.isTracking()
```

```java Java
Radar.isTracking();
```

</CodeGroup>

To stop tracking, for example when the user logs out, call:

<CodeGroup>

```kotlin Kotlin
Radar.stopTracking()
```

```java Java
Radar.stopTracking();
```

</CodeGroup>

You only need to call these methods once. The tracking state and options persist across app sessions.

`Radar.getTrackingOptions()` returns the options in effect. If you set [remote tracking options](/sdk/remote-configuration#remotely-set-tracking-options) in the dashboard, they override the options you pass to `startTracking`, and `Radar.isUsingRemoteTrackingOptions()` returns `true`.

To test, go for a walk or a drive. If you don't see location updates or events, check two things: once stopped, the device needs to move more than 100 meters to wake up, and the app needs background location permission in the device settings. Find your user on the [Users](https://dashboard.radar.com/geofencing/users) page and events on the [Events](https://dashboard.radar.com/geofencing/events) page.

### Foreground services and Google Play policy

Geofencing doesn't require a [foreground service](https://developer.android.com/guide/components/foreground-services). The SDK registers nearby geofences with the Android [Geofence API](https://developer.android.com/develop/sensors-and-location/location/geofencing), and Android wakes up the app to deliver geofence transitions. The `RESPONSIVE` and `EFFICIENT` presets never start a foreground service.

Google Play's [updated location permissions policy](https://support.google.com/googleplay/android-developer/answer/16926792) no longer accepts geofencing as a use case for foreground services. Only enable a foreground service, with the `CONTINUOUS` preset or `foregroundServiceEnabled`, for use cases that Google Play still allows, such as [trips](#background-tracking-for-trips), navigation, or user-initiated location sharing. You must declare foreground service usage in the Play Console.

Starting in Android SDK 4.0.0, the SDK manifest doesn't declare `RadarForegroundService`. To use the `CONTINUOUS` preset or `foregroundServiceEnabled`, declare the service and the `FOREGROUND_SERVICE_LOCATION` permission in your app manifest:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
    <application>
        <service
            android:name="io.radar.sdk.RadarForegroundService"
            android:foregroundServiceType="location"
            tools:targetApi="26" />
    </application>
</manifest>
```

If the service isn't declared, the SDK logs an error and tracks without a foreground service. This also applies when [remote tracking options](/sdk/remote-configuration) enable the foreground service.

In Android SDK versions before 4.0.0, the SDK manifest declares `RadarForegroundService`. If your app never uses the foreground service, remove it from your merged manifest:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <application>
        <service
            android:name="io.radar.sdk.RadarForegroundService"
            tools:node="remove" />
    </application>
</manifest>
```

## Background tracking for trips

For trips, use `RadarTrackingOptions.CONTINUOUS`. This preset tells the SDK to send location updates to the server every 30 seconds, regardless of whether the device is moving.

To avoid [background location limits](https://developer.android.com/about/versions/oreo/background-location-limits), the continuous preset starts a [foreground service](https://developer.android.com/guide/components/foreground-services) with a notification while tracking. While the foreground service notification is shown, only foreground permission is required for tracking. To adjust the foreground service notification copy and behavior, see [Android foreground service options](/sdk/tracking#android-foreground-service-options). In Android SDK 4.0.0 and later, you must [declare `RadarForegroundService`](#foreground-services-and-google-play-policy) in your app manifest. If you publish on Google Play, declare foreground service usage in the Play Console.

To start or update tracking for the duration of a trip, pass tracking options to `Radar.startTrip()`:

<CodeGroup>

```kotlin Kotlin
val tripOptions = RadarTripOptions(
    externalId = "order-299",
    destinationGeofenceTag = "store",
    destinationGeofenceExternalId = "store-42",
    mode = Radar.RadarRouteMode.CAR,
)

Radar.startTrip(tripOptions, RadarTrackingOptions.CONTINUOUS) { status, trip, events ->
    if (status == Radar.RadarStatus.SUCCESS) {
        // do something
    } else {
        // handle error
    }
}
```

```java Java
RadarTripOptions tripOptions = new RadarTripOptions(
    "order-299", // externalId
    null, // metadata
    "store", // destinationGeofenceTag
    "store-42", // destinationGeofenceExternalId
    Radar.RadarRouteMode.CAR, // mode
    null, // scheduledArrivalAt
    0, // approachingThreshold
    true, // startTracking
    null // legs
);

Radar.startTrip(tripOptions, RadarTrackingOptions.CONTINUOUS, new Radar.RadarTripCallback() {
    @Override
    public void onComplete(@NonNull Radar.RadarStatus status, @Nullable RadarTrip trip, @Nullable RadarEvent[] events) {
        if (status == Radar.RadarStatus.SUCCESS) {
            // do something
        } else {
            // handle error
        }
    }
});
```

</CodeGroup>

If tracking wasn't started before the trip started, it stops after the trip ends. Otherwise, it reverts to the tracking options in use before the trip started:

```kotlin
// complete trip
Radar.completeTrip { status, trip, events ->
    // do something
}

// cancel trip
Radar.cancelTrip { status, trip, events ->
    // do something
}
```

For every trip method, see [Trips](#trips). For the workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

## Mock tracking for testing

You can simulate a sequence of location updates without moving the device.

```kotlin
Radar.mockTracking(origin: Location, destination: Location, mode: RadarRouteMode, steps: Int, interval: Int, callback: RadarTrackCallback?)
```

| Parameter | Type | Description |
| --- | --- | --- |
| `origin` | `Location` | The origin. |
| `destination` | `Location` | The destination. |
| `mode` | `Radar.RadarRouteMode` | The travel mode: `FOOT`, `BIKE`, `CAR`, `TRUCK`, or `MOTORBIKE`. |
| `steps` | `Int` | The number of mock location updates. |
| `interval` | `Int`, seconds | The interval between mock location updates. A number between 1 and 60. |
| `callback` | `RadarTrackCallback?` | Optional. Called for each mock location update. |

For example, to simulate a sequence of 10 location updates every 3 seconds by car from an origin to a destination, call:

```kotlin
val origin = Location("mock")
origin.latitude = 40.78382
origin.longitude = -73.97536

val destination = Location("mock")
destination.latitude = 40.70390
destination.longitude = -73.98670

Radar.mockTracking(
    origin,
    destination,
    Radar.RadarRouteMode.CAR,
    10,
    3
) { status, location, events, user ->
    // do something with location, events, user
}
```

See [Test, troubleshoot, and go live](/fundamentals/testing-and-launch).

## Location metadata

The SDK can send motion activity, speed, heading, and pressure with location updates. Turn on the `useMotion` or `usePressure` [tracking option](/sdk/tracking#android-options), in code or with [remote tracking options](/sdk/remote-configuration#remotely-set-tracking-options).

To collect motion activity, add the activity recognition permissions to your manifest:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="com.google.android.gms.permission.ACTIVITY_RECOGNITION" />
    <uses-permission android:name="android.permission.ACTIVITY_RECOGNITION" />
</manifest>
```

Then request the runtime permission from your activity. The SDK doesn't prompt for it.

```kotlin
ActivityCompat.requestPermissions(this, arrayOf(Manifest.permission.ACTIVITY_RECOGNITION), ACTIVITY_RECOGNITION_PERMISSION_CODE)
```

The detected activity is available as `user.activityType`, one of `UNKNOWN`, `STATIONARY`, `FOOT`, `RUN`, `BIKE`, or `CAR`.

## Listening for events with a receiver

To listen for events, location updates, and errors client-side, create a class that extends `RadarReceiver`. Then pass an instance of your receiver when you initialize the SDK in `Application.onCreate()`, or call `Radar.setReceiver()`.

```kotlin
Radar.setReceiver(receiver: RadarReceiver?)
```

`RadarReceiver` is an abstract class. You must implement all five methods:

| Method | Called when |
| --- | --- |
| `onEventsReceived(context: Context, events: Array<RadarEvent>, user: RadarUser?)` | Events were received. |
| `onLocationUpdated(context: Context, location: Location, user: RadarUser)` | The user's location was updated and synced to the server. |
| `onClientLocationUpdated(context: Context, location: Location, stopped: Boolean, source: Radar.RadarLocationSource)` | The client's location was updated but not necessarily synced to the server. |
| `onError(context: Context, status: Radar.RadarStatus)` | A request failed. |
| `onLog(context: Context, message: String)` | A debug log message was received. |

For example, to set a receiver when you initialize the SDK:

<CodeGroup>

```kotlin Kotlin
import android.app.Application
import android.content.Context
import android.location.Location
import io.radar.sdk.Radar
import io.radar.sdk.RadarInitializeOptions
import io.radar.sdk.RadarReceiver
import io.radar.sdk.model.RadarEvent
import io.radar.sdk.model.RadarUser

class MyRadarReceiver : RadarReceiver() {

    override fun onEventsReceived(context: Context, events: Array<RadarEvent>, user: RadarUser?) {
        // do something with events, user
    }
```

### Receiver lifecycle

- Create the receiver once and set it before tracking begins.
- Set the receiver in `Application.onCreate()`, not in an activity. When Android starts your app process in the background to deliver a location update or geofence transition, `Application.onCreate()` runs and no activity is created.
- `Radar.setReceiver()` may be called before `Radar.initialize()`. The SDK keeps the receiver and uses it when it initializes. Pass `null` to clear the receiver.
- Every callback receives a `Context`. Use it instead of holding a reference to an activity.

`RadarLocationSource` is one of `FOREGROUND_LOCATION`, `BACKGROUND_LOCATION`, `MANUAL_LOCATION`, `GEOFENCE_ENTER`, `GEOFENCE_DWELL`, `GEOFENCE_EXIT`, `MOCK_LOCATION`, `BEACON_ENTER`, `BEACON_EXIT`, or `UNKNOWN`.

To listen for events server-side instead, add a [webhook](/integrations/webhooks) or enable an [integration](/integrations/integrations).

## Verified location

`Radar.trackVerified()` tracks the user's location with device integrity information and returns a signed `RadarVerifiedLocationToken` that your backend validates. The verified location and risk methods require the Radar fraud plugin (`io.radar:sdk-fraud`) in addition to `io.radar:sdk`. Without a compatible plugin, they return `RadarStatus.ERROR_PLUGIN`.

Before you call these methods, install and configure the plugin. See [Fraud plugin setup](/sdk/fraud). For the end-to-end workflow, including backend token validation, see the [Geo-compliance overview](/geo-compliance/overview).

| Method | Description |
| --- | --- |
| `Radar.trackVerified(callback)` | Performs a location check with `beacons = false` and `desiredAccuracy = MEDIUM`. |
| `Radar.trackVerified(beacons, desiredAccuracy, callback)` | Performs a location check, optionally ranging beacons. `beacons` defaults to `false` and `desiredAccuracy` to `MEDIUM`. |
| `Radar.trackVerified(beacons, desiredAccuracy, reason, transactionId, callback)` | Performs a location check with an optional `reason` and `transactionId`, both displayed in the dashboard and reports. |
| `Radar.startTrackingVerified(interval: Int, beacons: Boolean)` | Starts repeated location checks. `interval` is the interval between checks, in seconds. |
| `Radar.stopTrackingVerified()` | Stops repeated location checks. |
| `Radar.isTrackingVerified(): Boolean` | Whether repeated location checks have been started. |
| `Radar.getVerifiedLocationToken(callback)` | Returns the last token if it is still valid, or requests a fresh token if not. |
| `Radar.getVerifiedLocationToken(beacons, desiredAccuracy, callback)` | The same, with beacon and accuracy options for a fresh request. |
| `Radar.clearVerifiedLocationToken()` | Clears the last token. |
| `Radar.setExpectedJurisdiction(countryCode: String?, stateCode: String?)` | Optionally sets the user's expected country code and state code for jurisdiction checks. |
| `Radar.setExpectedAddress(address: String?)` | Optionally sets the user's expected address. |
| `Radar.isSharing(): Boolean` | The current screen sharing state. |
| `Radar.clearSharing()` | Clears the last screen sharing state. |
| `Radar.revealRisk(callback)` | Reveals device and network risk signals for the device. Doesn't require location permissions. Added in 3.35.0. |
| `Radar.clearRevealRiskId()` | Clears the user's last reveal risk ID. |
| `Radar.setVerifiedReceiver(verifiedReceiver: RadarVerifiedReceiver?)` | Sets a receiver for token updates and for IP address and screen sharing changes. May be called before `Radar.initialize()`. |

`RadarTrackVerifiedCallback.onComplete` receives `(status: RadarStatus, token: RadarVerifiedLocationToken?)`. `RadarRevealRiskCallback.onComplete` receives `(status: RadarStatus, token: RadarRevealRiskToken?)`.

For example, to run a location check at login:

```kotlin
Radar.trackVerified(
    beacons = false,
    desiredAccuracy = RadarTrackingOptions.RadarTrackingOptionsDesiredAccuracy.HIGH,
    reason = "login",
    transactionId = null,
) { status, token ->
    if (status != Radar.RadarStatus.SUCCESS || token == null) {
        // handle error
        return@trackVerified
    }
    if (token.passed) {
        // send token.token to your backend for validation
    } else {
        // deny access, and inspect token.failureReasons
    }
}
```

`RadarVerifiedLocationToken` properties:

| Property | Type | Description |
| --- | --- | --- |
| `token` | `String` | The signed JSON Web Token. Validate it on your backend. See [Geolocation token schema](/api/geolocation-tokens). |
| `passed` | `Boolean` | Whether the user passed all jurisdiction and fraud detection checks. Don't rely on this value alone. Validate the token on your backend. |
| `failureReasons` | `Array<String>` | The reasons the user didn't pass, if any. |
| `expiresAt` | `Date` | When the token expires. |
| `expiresIn` | `Int` | Seconds until the token expires. |
| `user` | `RadarUser` | The user. |
| `events` | `Array<RadarEvent>` | The events generated, if any. |
| `_id` | `String` | The Radar ID of the location check. |

`RadarVerifiedReceiver` is an abstract class:

| Method | Called when |
| --- | --- |
| `onTokenUpdated(context: Context, token: RadarVerifiedLocationToken)` | The user's verified location was updated. Required. |
| `onIpChanged(context: Context)` | The device's IP address changed while IP change monitoring is active. Optional. Added in 3.33.0. |
| `onSharingChanged(context: Context, sharing: Boolean)` | The device's screen sharing state changed. Optional. Added in 3.33.0. |

## Other APIs

The Android SDK also exposes APIs for beacons, trips, context, geocoding, search, distance, conversions, and user tags.

Each method takes a callback interface, listed with the method. In Kotlin, you can pass a lambda with the same parameters instead. Check that the status is `RadarStatus.SUCCESS` before you use the other values.

### Beacons

To range and monitor [beacons](/geofencing/beacons), you must [request Bluetooth permissions](https://developer.android.com/about/versions/12/features/bluetooth-permissions#declare-new-permissions). On Android 12 (API level 31) and later, the SDK requires the `BLUETOOTH_SCAN` runtime permission and `ACCESS_FINE_LOCATION`. On earlier versions, it requires `BLUETOOTH`, `BLUETOOTH_ADMIN`, and `ACCESS_FINE_LOCATION`.

Add the Bluetooth permissions to your manifest:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.BLUETOOTH" />
    <uses-permission android:name="android.permission.BLUETOOTH_ADMIN" />
    <uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
    <uses-permission android:name="android.permission.BLUETOOTH_SCAN" />
</manifest>
```

To range beacons in the foreground, call:

```kotlin
Radar.trackOnce(RadarTrackingOptions.RadarTrackingOptionsDesiredAccuracy.HIGH, true) { status, location, events, user ->
    // do something with user?.beacons
}
```

If beacon ranging fails or times out (5 seconds), the status is `RadarStatus.ERROR_BLUETOOTH`.

To monitor beacons in the background, update your tracking options:

```kotlin
val trackingOptions = RadarTrackingOptions.RESPONSIVE.copy(beacons = true)
Radar.startTracking(trackingOptions)
```

If you call `Radar.trackVerified(beacons = true)`, you can call `Radar.startRangingBeacons()` to range beacons continuously in the foreground, so that location checks don't wait for a new ranging window.

```kotlin
Radar.startRangingBeacons()
Radar.stopRangingBeacons()
```

Call `Radar.startRangingBeacons()` after `initialize()` and after location and Bluetooth permissions are granted, ideally when the user enters a flow that calls `trackVerified(beacons = true)`. Call `Radar.stopRangingBeacons()` when you no longer need beacons. Ranging pauses automatically when the app enters the background and resumes when it returns to the foreground. Until ranging has run for 5 seconds, `trackVerified(beacons = true)` ranges beacons as usual. These methods require Android 8.0 (API level 26) or later.

### Context

Context is what Radar knows about a location: its geofences, place, regions, and beacons. See [Understand geofences, places, regions, beacons, and fraud context](/fundamentals/context-types).

To get the geofences, place, and regions for a location without sending device or user identifiers to the server, call:

```kotlin
Radar.getContext(callback: RadarContextCallback)
```

```kotlin
Radar.getContext { status, location, context ->
```

### Search

With the [autocomplete API](/api/search), autocomplete partial addresses and place names, sorted by relevance. Create one `RadarAutocompleteSession` per search field. When the user selects a result, call `session.select`. If your project has [address enrichment](/maps/addresses) enabled, selecting also returns the enriched address. `RadarAutocompleteSession` requires Android SDK 4.3.0 or later.

| Parameter | Type | Description |
| --- | --- | --- |
| `query` | `String` | The partial address or place name to autocomplete. |
| `near` | `Location?` | A location for the search. |
| `layers` | `Array<String>?` | Optional layer filters. |
| `limit` | `Int?` | The maximum number of addresses to return. A number between 1 and 100. |
| `country` | `String?` | An optional two-letter country code filter. |
| `mailable` | `Boolean?` | Whether to only include mailable addresses. |

For example, to autocomplete a query and select the first result:

```kotlin
val session = RadarAutocompleteSession()

session.autocomplete(
    query = "brooklyn roasting",
    near = near,
    limit = 10
) { status, addresses ->
    val selected = addresses?.firstOrNull() ?: return@autocomplete

    // with address enrichment enabled
    session.select(selected) { status, address ->
        // do something with the enriched address
    }

    // otherwise
    session.select(selected)
}
```

`RadarAutocompleteSelectCallback.onComplete` receives `(status: RadarStatus, address: RadarAutocompleteEnrichedAddress?)`.

To autocomplete without a session, call `Radar.autocomplete(query, near, layers, limit, country, mailable, callback)` with the same parameters.

```java Java
    "20", // number
    null, // unit
    "Brooklyn", // city
    "NY", // stateCode
    "11201", // postalCode
    "US", // countryCode
    new Radar.RadarValidateAddressCallback() {
        @Override
        public void onComplete(@NonNull Radar.RadarStatus status, @Nullable RadarAddress address, @Nullable Radar.RadarAddressVerificationStatus verificationStatus) {
            // address and verificationStatus are null unless status is SUCCESS
        }
    });

Radar.validateAddress(
    "20 Jay St", // addressLabel
    "Suite 900", // unit
    "Brooklyn", // city
    "NY", // stateCode
    "11201", // postalCode
    "US", // countryCode
    new Radar.RadarValidateAddressCallback() {
        @Override
        public void onComplete(@NonNull Radar.RadarStatus status, @Nullable RadarAddress address, @Nullable Radar.RadarAddressVerificationStatus verificationStatus) {
            // address and verificationStatus are null unless status is SUCCESS
        }
    });
```

</CodeGroup>

`RadarAddressVerificationStatus` is one of `VERIFIED`, `PARTIALLY_VERIFIED`, `AMBIGUOUS`, `UNVERIFIED`, or `NONE`.

To validate an address from autocomplete or geocoding, pass its `street` and `number` (or its `addressLabel`) and the other fields to one of these methods. These methods are available in Android SDK 4.3.0 and later. In earlier versions, use `validateAddress(address)`, which is deprecated. Addresses from autocomplete and geocoding have a street, a number, and an address label. Versions before 4.3.0 send all three, and the API rejects the request with `RadarStatus.ERROR_BAD_REQUEST`. On those versions, validate a new `RadarAddress` built without `addressLabel`.

### Distance

With the [distance API](/api/routing), calculate the travel distance and duration from an origin to a destination:

```kotlin
Radar.getDistance(destination: Location, modes: EnumSet<RadarRouteMode>, units: RadarRouteUnits, callback: RadarRouteCallback)
Radar.getDistance(origin: Location, destination: Location, modes: EnumSet<RadarRouteMode>, units: RadarRouteUnits, callback: RadarRouteCallback)
```

The form without `origin` uses the device's current location. `modes` is a set of `FOOT`, `BIKE`, `CAR`, `TRUCK`, and `MOTORBIKE`. `units` is `IMPERIAL` or `METRIC`. `onComplete` receives `(status: RadarStatus, routes: RadarRoutes?)`. `RadarRoutes` has `geodesic` and one optional `RadarRoute` per mode. For example:

```kotlin
Radar.getDistance(
    origin,
    destination,
    EnumSet.of(Radar.RadarRouteMode.FOOT, Radar.RadarRouteMode.CAR),
    Radar.RadarRouteUnits.IMPERIAL
) { status, routes ->
    // do something with routes?.car
}
```

### Matrix

With the [matrix API](/api/routing), calculate the travel distance and duration between multiple origins and destinations for up to 25 routes:

```kotlin
Radar.getMatrix(origins: Array<Location>, destinations: Array<Location>, mode: RadarRouteMode, units: RadarRouteUnits, callback: RadarMatrixCallback)
```

`RadarMatrixCallback.onComplete` receives `(status: RadarStatus, matrix: RadarRouteMatrix?)`. For example, to get the route between the first origin and the first destination:

```kotlin
Radar.getMatrix(
    origins,
    destinations,
    Radar.RadarRouteMode.CAR,
    Radar.RadarRouteUnits.IMPERIAL
) { status, matrix ->
    val route = matrix?.routeBetween(0, 0)
    // do something with route
}
```

### Conversions

With the [conversions API](/api/events), log a conversion, such as a purchase or signup, to analyze alongside your app's location activity:

```kotlin
Radar.logConversion(name: String, metadata: JSONObject? = null, callback: RadarLogConversionCallback)
Radar.logConversion(name: String, revenue: Double, metadata: JSONObject? = null, callback: RadarLogConversionCallback)
```

`onComplete` receives `(status: RadarStatus, event: RadarEvent?)`. For example:

```kotlin
val metadata = JSONObject().put("orderId", "order-299")

Radar.logConversion("order_placed", metadata) { status, event ->
    // do something with the conversion event
}

// conversion with revenue
Radar.logConversion("order_placed", 24.5, metadata) { status, event ->
    // do something with the conversion event
}
```

### Verify events

After a user check-in or another form of verification, you can accept or reject an event. Radar uses event verifications to improve the accuracy and confidence level of future events.

```kotlin
Radar.acceptEvent(eventId: String, verifiedPlaceId: String? = null)
Radar.rejectEvent(eventId: String)
```

For example, to accept an event:

```kotlin
Radar.acceptEvent(event._id, event.place?._id)
```

### User tags

Set tags on the user so that you can target [campaigns](/geofencing/geofences-and-places) at users with the corresponding tags. Added in 3.22.0.

| Method | Description |
| --- | --- |
| `Radar.addTags(tags: Array<String>)` | Adds tags to the existing set. |
| `Radar.removeTags(tags: Array<String>)` | Removes tags from the existing set. |
| `Radar.setTags(tags: Array<String>)` | Replaces all tags. |
| `Radar.getTags(): Array<String>?` | Returns the current tags. |

For example:

```kotlin
Radar.addTags(arrayOf("tag1", "tag2"))
Radar.removeTags(arrayOf("tag1"))
Radar.setTags(arrayOf("tag2", "tag3"))
val tags = Radar.getTags()
```

### In-app messages

To customize how Radar in-app messages are handled, implement `RadarInAppMessageReceiver` and pass it in `RadarInitializeOptions.inAppMessageReceiver` or to `Radar.setInAppMessageReceiver()`. Every method of the interface has a default implementation: `onNewInAppMessage(inAppMessage)` shows the message with `Radar.showInAppMessage()`, and `onInAppMessageDismissed(inAppMessage)` and `onInAppMessageButtonClicked(inAppMessage)` do nothing. Override `createInAppMessageView` to supply your own view.

## Notifications

With `Radar.setNotificationOptions()`, set the icon and the background color of foreground service and event notifications. Pass a `RadarNotificationOptions`:

| Property | Type | Description |
| --- | --- | --- |
| `iconString` | `String?` | The name of the drawable resource to use for notifications. Defaults to the app icon. |
| `iconColor` | `String?` | The background color used for notifications. |
| `foregroundServiceIconString` | `String?` | The icon for foreground service notifications. Defaults to `iconString`. |
| `foregroundServiceIconColor` | `String?` | The color for foreground service notifications. Defaults to `iconColor`. |
| `eventIconString` | `String?` | The icon for event notifications. Defaults to `iconString`. |
| `eventIconColor` | `String?` | The color for event notifications. Defaults to `iconColor`. |
| `deepLink` | `String?` | The deep link for event notifications. |

For example:

<CodeGroup>

```kotlin Kotlin
// Set both foreground service and event notifications
Radar.setNotificationOptions(
    RadarNotificationOptions(
        iconString = "icon_1",
        iconColor = "color_1",
    )
)

// Or, set the foreground service notification and event notifications separately
Radar.setNotificationOptions(
    RadarNotificationOptions(
        foregroundServiceIconString = "icon_2",
        foregroundServiceIconColor = "color_2",
        eventIconString = "icon_3",
        eventIconColor = "color_3",
    )
)
```

```java Java
JSONObject notificationOptions = new JSONObject();
try {
    notificationOptions.put("iconString", "icon_1");
    notificationOptions.put("iconColor", "color_1");
} catch (JSONException e) {
    // handle error
}

Radar.setNotificationOptions(RadarNotificationOptions.fromJson(notificationOptions));
```

</CodeGroup>

To set the text, title, and behavior of the foreground service notification, see [Android foreground service options](/sdk/tracking#android-foreground-service-options).

Radar can associate `opened_app` conversions with a Radar notification that the user tapped to open the app. The SDK does this from its activity lifecycle callbacks. `Radar.logOpenedAppConversion(intent: Intent)` is public for cases where you need to pass the launching intent yourself.

## Huawei

By default, the SDK [depends on](#dependencies) [Google Play Services Location](https://developer.android.com/training/location). However, you can use [Huawei Mobile Services Location Kit](https://developer.huawei.com/consumer/en/hms/huawei-locationkit/) instead.

If you haven't already configured your project for Huawei Mobile Services, follow the [HMS Core integration instructions](https://developer.huawei.com/consumer/en/doc/development/HMSCore-Guides/integrate-as-sdk-0000001050168936).

Then add the dependency to your app's `build.gradle` file:

```gradle
dependencies {
    implementation 'com.huawei.hms:location:6.4.0.300'
}
```

Finally, set the location provider to `HUAWEI` when you initialize the SDK:

<CodeGroup>

```kotlin Kotlin
val options = RadarInitializeOptions(
    locationProvider = Radar.RadarLocationServicesProvider.HUAWEI,
)
Radar.initialize(this, "prj_test_pk_...", options)
```

```java Java
RadarInitializeOptions options = new RadarInitializeOptions.Builder()
    .locationProvider(Radar.RadarLocationServicesProvider.HUAWEI)
    .build();
Radar.initialize(this, "prj_test_pk_...", options);
```

</CodeGroup>

<Warning>
  If you set the `HUAWEI` provider but your app doesn't include `com.huawei.hms:location`, the SDK doesn't get locations or add geofences. From Android SDK 4.3.0, it logs an error and location requests fail with `ERROR_LOCATION`.
</Warning>

## Upgrade notes

Breaking changes in recent versions. For the full list, see the [migration guide](https://github.com/radarlabs/radar-sdk-android/blob/master/MIGRATION.md).

| Version | Change |
| --- | --- |
| 4.3.0 | Adds `RadarAutocompleteSession` and the structured `Radar.validateAddress()` methods. `Radar.validateAddress(address)` is deprecated. The SDK includes R8 rules for optional dependencies. |
| 4.2.0 | `trackVerified()` retries against a backup host by default. To opt out, set `trackVerifiedAutoFailover` to `false`. |
| 4.0.0 | The SDK manifest no longer declares `RadarForegroundService`. See [Foreground services and Google Play policy](#foreground-services-and-google-play-policy). The minimum Android version is API level 23. The SDK is compiled to Java 11 bytecode and requires Android Gradle Plugin 7.0 or later. |
| 4.0.0 | Removed: the three-argument `RadarIpGeocodeCallback.onComplete(status, address, proxy)`, the `expandUnits` parameter on `Radar.autocomplete()`, the `Radar.autocomplete()` overloads without `mailable`, and the `Radar.searchPlaces()` overloads without `chainMetadata`. If you passed `expandUnits` positionally, remove the argument, because that `Boolean` is now read as `mailable`. |
| 3.39.0 | Verified tracking and reveal risk requests encrypt the complete request body and require a compatible `io.radar:sdk-fraud` version. A missing or incompatible fraud plugin returns `ERROR_PLUGIN`. |
| 3.21.0 | `Radar.searchPlaces()` takes an additional `countryCodes` parameter. |
| 3.13.0 | `Radar.trackVerified()` returns a `RadarVerifiedLocationToken`. `Radar.trackVerifiedToken()` was removed. |
