The Web SDK (`radar-sdk-js`) calls Radar from the browser with a publishable key. At the end of the setup sections, a page initializes the SDK and a `Radar.trackOnce()` call resolves with the user's location, the Radar user, and any events.

This page documents Web SDK 5.3.0. The source is on [GitHub](https://github.com/radarlabs/radar-sdk-js) and the package is on [npm](https://www.npmjs.com/package/radar-sdk-js).

## Requirements

- A Radar publishable key from the [Settings](https://dashboard.radar.com/settings) page of the Radar dashboard: `prj_test_pk_...` for the Test environment and `prj_live_pk_...` for the Live environment. The SDK throws `RadarPublishableKeyError` if you pass a secret key.
- A browser environment. The SDK uses `fetch`, `localStorage`, and, for device location, the [Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API). Browsers only expose the Geolocation API on secure origins (HTTPS or `localhost`).
- The npm package is an ES module with TypeScript types. In Web SDK 5.0.0 and later, Maps, Autocomplete UI, and Fraud are separate plugins. If you are on 4.x, see the [migration guide](https://github.com/radarlabs/radar-sdk-js/blob/master/MIGRATION.md).

The Web SDK tracks only while your page is open. It has no background tracking and no silent push.

## Install

In an HTML page, add the SDK script:

```html
<script src="https://js.radar.com/v5.3.0/radar.min.js"></script>
```

If you use Maps or Autocomplete UI, add the corresponding plugin scripts after the SDK script:

```html
<!-- maps plugin (auto-registers) -->
<link href="https://js.radar.com/maps/v1.2.0/radar-maps.css" rel="stylesheet">
<script src="https://js.radar.com/maps/v1.2.0/radar-maps.min.js"></script>

<!-- autocomplete plugin (auto-registers) -->
<link href="https://js.radar.com/autocomplete/v1.2.0/radar-autocomplete.css" rel="stylesheet">
<script src="https://js.radar.com/autocomplete/v1.2.0/radar-autocomplete.min.js"></script>
```

In a web app, install the package from npm:

```bash
npm install radar-sdk-js
```

If you use Maps or Autocomplete UI, install the corresponding plugins:

```bash
# maps (requires maplibre-gl as a peer dependency)
npm install @radarlabs/plugin-maps maplibre-gl

# autocomplete
npm install @radarlabs/plugin-autocomplete
```

Then import the library and register any plugins before you use them:

```javascript
import Radar from 'radar-sdk-js';

// for maps
import { createMapsPlugin } from '@radarlabs/plugin-maps';
import '@radarlabs/plugin-maps/dist/radar-maps.css';
Radar.registerPlugin(createMapsPlugin());

// for autocomplete
import { createAutocompletePlugin } from '@radarlabs/plugin-autocomplete';
import '@radarlabs/plugin-autocomplete/dist/radar-autocomplete.css';
Radar.registerPlugin(createAutocompletePlugin());
```

`Radar.registerPlugin(...plugins)` accepts one or more plugins. Registering a plugin with a name that is already registered logs a warning and does nothing.

## Setup

### Initialize

Initialize the library with your publishable key before you call any other function:

```javascript
Radar.initialize('prj_test_pk_...');
```

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

`Radar.initialize` has two forms:

```typescript
Radar.initialize(publishableKey: string, options?: RadarOptions): void
Radar.initialize(options: RadarInitOptions): void
```

In the second form, pass the key as `publishableKey` in the options object:

```javascript
Radar.initialize({ publishableKey: 'prj_test_pk_...', logLevel: 'warn' });
```

To initialize with an auth token in place of a publishable key, pass `authToken` in the options object and omit `publishableKey`. See [Authenticate the SDK with auth tokens](/sdk/fraud#authenticate-the-sdk-with-auth-tokens).

`Radar.initialize` throws `RadarPublishableKeyError` if the key is missing or is a secret key, if `authToken` isn't a JWT, or if you pass both `publishableKey` and `authToken`.

Available options:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `logLevel` | `'none'`, `'error'`, `'warn'`, `'info'`, `'debug'` | `'debug'` when `debug` is on, otherwise `'error'` | Log level for console logging. |
| `debug` | boolean | `true` with a test publishable key, `false` with a live publishable key | Adds the raw API response body to results, as `response`. |
| `desiredAccuracy` | `'high'`, `'medium'`, `'low'` | None | Accuracy hint for device location. `'high'` requests high accuracy from the browser (`enableHighAccuracy`), and so does leaving the option unset. `'medium'` and `'low'` don't. Higher accuracy can take longer. |
| `locationTimeout` | number, milliseconds | `10000` | How long to wait for the browser to return a location before the request fails with `RadarLocationError`. |
| `locationMaximumAge` | number, milliseconds | `0` | Maximum age of a browser location the SDK accepts. `0` always requests a new location. See [`getCurrentPosition()` options](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition). |
| `cacheLocationMinutes` | number, minutes | None | If set, the SDK reuses the last device location for this many minutes instead of asking the browser again. If not set or `0`, the SDK always requests a new location. |
| `networkTimeoutInterval` | number, seconds | `10` | How long to wait for a network request. Values are clamped to the range 1 to 300. A request that times out fails with `RadarNetworkError`. |
| `getRequestHeaders` | function returning an object of header names and values | None | Called for every request. The headers it returns are added to the request. |
| `host` | string | `'https://api.radar.io'` | Overrides the Radar API host. |
| `version` | string | `'v1'` | API version. |
| `trackVerifiedAutoFailover` | boolean | `false` | Read only by the fraud plugin. Retries verified requests on a secondary host when the primary host doesn't return a response from Radar. See [Fraud plugin setup](/sdk/fraud). |

The `live` option is deprecated. The SDK infers the environment from the publishable key.

### Other setup methods

| Method | Description |
| --- | --- |
| `Radar.VERSION` | The SDK version string, such as `'5.3.0'`. |
| `Radar.onError(callback: (error: RadarError) => void)` | Registers one global callback that receives SDK errors. |
| `Radar.clear()` | Clears the SDK options and the error callback. Call `Radar.initialize` again before you make more requests. |
| `Radar.setProduct(product?: string)` | Sets an optional product name sent with tracking requests, displayed in the dashboard and reports. Pass `undefined` to clear. |

## Geofencing

### Identify user

The SDK generates a device ID and an install ID and stores them in `localStorage`.

To identify the user when logged in, call `Radar.setUserId()` with a stable unique ID for the user:

```javascript
Radar.setUserId('user-123');
```

<Warning>
  Don't send personal information, such as names, email addresses, or publicly available IDs, for `userId`.
</Warning>

To set custom metadata for the user, call `Radar.setMetadata()` with an object that has up to 16 keys and values of type string, boolean, or number:

```javascript
Radar.setMetadata({ plan: 'pro', beta: true });
```

To set an optional description for the user, displayed in the dashboard, call:

```javascript
Radar.setDescription('Test user');
```

All three methods take an optional argument. Pass `undefined`, or call the method with no argument, to clear the stored value. Call these when the user logs out or changes, for example:

```javascript
function onLogout() {
  Radar.setUserId();
  Radar.setMetadata();
  Radar.setDescription();
}
```

The values are stored in `localStorage` and persist across browser sessions, so you only need to set them when they change.

For how Radar creates and matches user records, see [Accounts and authentication](/fundamentals/authentication-and-access).

### Foreground tracking

Once you have initialized the SDK and the user has granted location permission in the browser, you can track the user's location.

```typescript
Radar.trackOnce(params?: RadarTrackParams): Promise<RadarTrackResponse>
```

To track the user's location with the device location, call:

```javascript
Radar.trackOnce()
  .then((result) => {
    const { location, user, events } = result;
    // do something with location, user, or events
  })
  .catch((err) => {
    // handle error
  });
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `latitude`, `longitude` | number | No | If both are set, the SDK uses them and doesn't ask the browser for a location. See [Manual tracking](#manual-tracking). |
| `accuracy` | number, meters | No | Accuracy of the supplied location. |
| `desiredAccuracy` | `'high'`, `'medium'`, `'low'` | No | Overrides the `desiredAccuracy` initialization option for this call. |
| `userId`, `description`, `metadata` | string, string, object | No | Overrides for the stored values, for this call only. |
| `tripOptions` | `RadarTripOptions` | No | Overrides the saved [trip options](#trips) for this call. |

The promise resolves with:

| Field | Type | Description |
| --- | --- | --- |
| `location` | `{ latitude, longitude, accuracy }` | The location that was sent. `accuracy` is in meters. |
| `user` | `RadarUser` | The user, including `geofences`, `place`, `country`, `state`, `dma`, `postalCode`, `trip`, and `fraud` where available. |
| `events` | `RadarEvent[]` | The events generated, if any. |
| `response` | object | The raw API response body. Present only when `debug` is on. |

These calls are subject to [rate limits](/api/fundamentals).

To get the device location without sending it to Radar, call `Radar.getLocation()`. It resolves with `{ latitude, longitude, accuracy }`.

To check that tracking works, call `Radar.trackOnce()` in your page, then find your user on the [Users](https://dashboard.radar.com/geofencing/users) page. To generate an event, first create a geofence around your location on the [Geofences](https://dashboard.radar.com/geofencing/geofences) page.

### Manual tracking

To update the user's location with a location you supply, call:

```javascript
Radar.trackOnce({
  latitude: 39.2904,
  longitude: -76.6122,
  accuracy: 65
}).then((result) => {
  const { location, user, events } = result;
  // do something with location, user, or events
}).catch((err) => {
  // handle error
});
```

### Context

Context is what Radar knows about a location: its geofences, place, regions, and beacons. See [Understand geofences, places, regions, beacons, and fraud context](/fundamentals/context-types).

To get the geofences, place, and regions for a location without tracking the user, call:

```typescript
Radar.getContext(params: { latitude: number; longitude: number }): Promise<RadarContextResponse>
```

For example:

```javascript
Radar.getContext({ latitude: 40.783826, longitude: -73.975363 })
  .then((result) => {
    const { geofences, place, country, state, dma, postalCode } = result;
    // do something with context
  })
  .catch((err) => {
    // handle error
  });
```

### Trips

Use trips to track a user to a destination geofence and get ETAs. For the full workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

| Method | Returns | Description |
| --- | --- | --- |
| `Radar.startTrip(tripOptions)` | `Promise<RadarTripResponse>` | Starts a trip and saves the trip options in `localStorage`. If `tripOptions.userId` is set, it also becomes the stored user ID. |
| `Radar.updateTrip(tripOptions)` | `Promise<RadarTripResponse>` | Updates the trip identified by `tripOptions.externalId`. |
| `Radar.completeTrip()` | `Promise<RadarTripResponse>` | Completes the current trip and clears the saved trip options. |
| `Radar.cancelTrip()` | `Promise<RadarTripResponse>` | Cancels the current trip and clears the saved trip options. |
| `Radar.getTripOptions()` | `RadarTripOptions` | Returns the saved trip options, if any. |
| `Radar.setTripOptions(tripOptions?)` | `void` | Saves trip options without starting a trip. Pass `undefined` to clear. |
| `Radar.clearTripOptions()` | `void` | Clears the saved trip options. |

`RadarTripOptions` fields:

| Field | Type | Description |
| --- | --- | --- |
| `externalId` | string | A stable unique ID for the trip. |
| `destinationGeofenceTag` | string | The tag of the destination geofence. |
| `destinationGeofenceExternalId` | string | The external ID of the destination geofence. |
| `mode` | `'car'`, `'foot'`, `'bike'`, `'motorbike'`, `'truck'` | The travel mode. |
| `scheduledArrivalAt` | `Date` | The scheduled arrival time. Must be a valid `Date` object. Other values are ignored with a warning. |
| `approachingThreshold` | number | The approaching threshold for the trip. |
| `metadata` | object | Custom key-value pairs for the trip. |
| `userId` | string | A user ID for the trip. |

The response has `trip` (the `RadarTrip`) and `events` (the events generated).

While trip options are saved, each `Radar.trackOnce()` call includes them, which updates the trip. The Web SDK doesn't track on its own during a trip. Call `Radar.trackOnce()` on the schedule your use case needs. For example:

```javascript
const { trip } = await Radar.startTrip({
  externalId: 'order-299',
  destinationGeofenceTag: 'store',
  destinationGeofenceExternalId: 'store-42',
  mode: 'car'
});

// update the user's location and the trip ETA
const { user } = await Radar.trackOnce();
console.log(user?.trip?.status);

// when the order is picked up
await Radar.completeTrip();
```

### Conversions

To log a conversion, such as a purchase or signup, call:

```typescript
Radar.logConversion(params: RadarConversionParams): Promise<RadarConversionResponse>
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | The name of the conversion. |
| `metadata` | object | No | Custom key-value pairs for the conversion. |
| `revenue` | number | No | Revenue for the conversion. The SDK sends it as `metadata.revenue`. |
| `createdAt` | `Date` or ISO 8601 string | No | Defaults to the current time. |
| `userId` | string | No | Defaults to the stored user ID. |

For example:

```javascript
Radar.logConversion({
  name: 'order_placed',
  revenue: 24.5,
  metadata: { orderId: 'order-299' }
}).then((result) => {
  const { event } = result;
  // do something with the conversion event
}).catch((err) => {
  // handle error
});
```

See [Events API](/api/events).

## Verified location

`Radar.trackVerified()` and the other verified location and risk methods aren't part of the core Web SDK. They are provided by the fraud plugin, `@radarlabs/plugin-fraud`, on the `Radar.fraud` namespace, for example `Radar.fraud.trackVerified()`.

For installation, the supported browser and desktop paths, and the method reference, see [Fraud plugin setup](/sdk/fraud). For the end-to-end workflow, including validating the token on your backend, see the [Geo-compliance overview](/geo-compliance/overview).

## Maps

### Geocoding

With the [forward geocoding API](/api/geocoding), geocode an address, converting address to coordinates:

```typescript
Radar.forwardGeocode(params: RadarForwardGeocodeParams): Promise<RadarGeocodeResponse>
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `query` | string | Yes | The address or place name to geocode. |
| `layers` | string[] | No | Layer filters. |
| `country` | string | No | Country code filter. |
| `lang` | string | No | Language code for results. |

For example:

```javascript
Radar.forwardGeocode({
  query: '841 broadway, new york, ny'
})
  .then((result) => {
    const { addresses } = result;
    // do something with addresses
  })
  .catch((err) => {
    // handle error
  });
```

With the [reverse geocoding API](/api/geocoding), reverse geocode a location, converting coordinates to address. If you omit `latitude` and `longitude`, the SDK uses the device location. `layers` is an optional array of layer filters.

```javascript
Radar.reverseGeocode({
  latitude: 40.783826,
  longitude: -73.975363
})
  .then((result) => {
    const { addresses } = result;
    // do something with addresses
  })
  .catch((err) => {
    // handle error
  });
```

With the [IP geocoding API](/api/geocoding), geocode the device's current IP address, converting IP address to city, state, and country. `Radar.ipGeocode()` takes no parameters and doesn't use device location.

```javascript
Radar.ipGeocode()
  .then((result) => {
    const { ip, address, proxy } = result;
    // do something with results
  })
  .catch((err) => {
    // handle error
  });
```

### Search

With the [autocomplete API](/api/search), autocomplete partial addresses and place names, sorted by relevance. Open one `Radar.AutocompleteSession` per search field, and report the result the user chooses with `session.select()`. Selections are how autocomplete quality is measured and improved. If your project has [address enrichment](/maps/addresses) enabled, selecting also returns the enriched address. `Radar.AutocompleteSession` requires Web SDK 5.3.0 or later.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `query` | string | Yes | The partial address or place name. |
| `near` | `{ latitude, longitude }` or `'lat,lng'` string | No | Biases results toward a location. If omitted, the API uses the location of the request's IP address. |
| `limit` | number | No | Maximum number of results. |
| `layers` | string[] | No | Layer filters. |
| `countryCode` | string | No | Country code filter. |
| `postalCode` | string | No | Postal code filter. |
| `mailable` | boolean | No | Only return mailable addresses. |
| `lang` | string | No | Language code for results. |

For example, to autocomplete a query and select the first result:

```javascript
const session = new Radar.AutocompleteSession();

const { addresses } = await session.autocomplete({
  query: '841 bro',
  near: {
    latitude: 40.783826,
    longitude: -73.975363
  },
  limit: 10
});

// with address enrichment enabled
const { address } = await session.select(addresses[0]);

// otherwise
await session.select(addresses[0]);
```

`session.select()` throws `RadarBadRequestError` if the address didn't come from a session's `autocomplete()` call.

`Radar.autocomplete(params)` takes the same parameters without a session. Its results can't be passed to `select()`. The `sessionToken` and `expandUnits` parameters are deprecated.

With the [geofence search API](/api/search), search for geofences near a location, sorted by distance. If you omit `near`, the SDK uses the device location.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `near` | `{ latitude, longitude }` or `'lat,lng'` string | No | The location to search. |
| `radius` | number, meters | No | The radius to search. |
| `tags` | string[] or comma-separated string | No | Tag filters. |
| `metadata` | object | No | Metadata filters. |
| `limit` | number | No | Maximum number of results. |
| `includeGeometry` | boolean | No | Whether to include geofence geometries in the response. |

For example:

```javascript
Radar.searchGeofences({
  radius: 1000,
  tags: ['venue'],
  limit: 10
}).then((result) => {
  const { geofences } = result;
  // do something with geofences
}).catch((err) => {
  // handle error
});
```

With the [places search API](/api/search), search for places near a location, sorted by distance. If you omit `near`, the SDK uses the device location. `chains`, `categories`, and `groups` each accept an array or a comma-separated string.

```javascript
Radar.searchPlaces({
  near: {
    latitude: 40.783826,
    longitude: -73.975363
  },
  radius: 1000,
  chains: ['starbucks'],
  limit: 10
}).then((result) => {
  const { places } = result;
  // do something with places
}).catch((err) => {
  // handle error
});
```

With the [address validation API](/api/geocoding), validate a structured address in the US or Canada. `city`, `stateCode`, `postalCode`, and `countryCode` are required. Pass either `number` and `street`, or a single-line `addressLabel`. `unit` is optional.

```javascript
Radar.validateAddress({
  addressLabel: '841 BROADWAY',
  city: 'NEW YORK',
  stateCode: 'NY',
  postalCode: '10003',
  countryCode: 'US',
}).then((response) => {
  const { address, result } = response;
  // result.verificationStatus is 'verified', 'partially verified', 'ambiguous', or 'unverified'
}).catch((err) => {
  // handle error
});
```

### Distance

With the [distance API](/api/routing), calculate the travel distance and duration between two locations:

```typescript
Radar.distance(params: RadarDistanceParams): Promise<RadarRouteResponse>
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `origin` | `{ latitude, longitude }` or `'lat,lng'` string | No | The origin. Defaults to the device location. |
| `destination` | `{ latitude, longitude }` or `'lat,lng'` string | Yes | The destination. |
| `modes` | array of `'car'`, `'foot'`, `'bike'`, `'motorbike'`, `'truck'`, or a comma-separated string | Yes | The travel modes. |
| `units` | `'metric'` or `'imperial'` | No | The distance units. |
| `geometry` | `'polyline'`, `'polyline5'`, `'polyline6'`, or `'linestring'` | No | The route geometry encoding. |
| `geometryPoints` | number | No | The number of points in the route geometry. |
| `avoid` | array of `'tolls'`, `'highways'`, `'ferries'`, `'borderCrossings'`, or a comma-separated string | No | Road features to avoid. |

Each route has `distance` and `duration`, each with a numeric `value` and a display `text`. `distance.value` is in meters for metric units and feet for imperial units. `duration.value` is in minutes. For example:

```javascript
Radar.distance({
  origin: {
    latitude: 40.78382,
    longitude: -73.97536
  },
  destination: {
    latitude: 40.70390,
    longitude: -73.98670
  },
  modes: ['foot', 'car'],
  units: 'imperial'
}).then((result) => {
  const { routes } = result;
  const { geodesic, foot, car } = routes;
  // do something with distance result
}).catch((err) => {
  // handle error
});
```

### Matrix

With the [matrix API](/api/routing), calculate the travel distances and durations between multiple origins and destinations for up to 25 routes. `origins` defaults to the device location, `destinations` and `mode` are required, and `units` and `avoid` are optional.

```javascript
Radar.matrix({
  origins: [{
    latitude: 40.70390,
    longitude: -73.98690
  }],
  destinations: [{
    latitude: 40.70390,
    longitude: -73.98690
  }, {
    latitude: 40.73237,
    longitude: -73.94884
  }],
  mode: 'car',
  units: 'imperial'
}).then((result) => {
  const { origins, destinations, matrix } = result;
  matrix.forEach((row) => {
    row.forEach((route) => {
      const { distance, duration, originIndex, destinationIndex } = route;
      // do something with each route
    });
  });
}).catch((err) => {
  // handle error
});
```

`matrix` is a two-dimensional array indexed by origin and then destination.

## Maps and UI kits

The maps and autocomplete plugins add UI components under `Radar.ui`. `Radar.ui` exists only after you register a plugin that provides it.

| Plugin | Package | Adds |
| --- | --- | --- |
| Maps | `@radarlabs/plugin-maps` (requires `maplibre-gl`) | `Radar.ui.map()`, `Radar.ui.marker()`, `Radar.ui.popup()`, and `Radar.ui.maplibregl` |
| Autocomplete | `@radarlabs/plugin-autocomplete` | `Radar.ui.autocomplete()` |

For a walkthrough with complete examples, see [Display maps](/maps/maps) and [Autocomplete, geocode, and validate addresses](/maps/addresses). The sections below list every option.

### Map options and functions

`Radar.ui.map()` returns a `RadarMap`, which extends the MapLibre map. It accepts any MapLibre [MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/) except `transformRequest`, which the SDK uses to attach your key. These are the options most maps set:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `container` | string or `HTMLElement` | None | Required. The element ID or element to render into. Its width and height set the map size. |
| `style` | string or object | `radar-default-v1` | The map style: a Radar style name, a custom style ID, a style URL, or a MapLibre style object. See [Styles](/maps/maps#styles). |
| `center` | `[longitude, latitude]` | Estimated from the client's IP address | The initial center. If you omit it, Radar centers the map on an approximate estimate of the client's location from its IP address. |
| `zoom` | number | Set by the style | The initial zoom level. Higher numbers are closer. |
| `language` | string | None | The language for map labels: a language code such as `en` or `es`, or `local` to use the browser's language. |
| `showZoomControls` | boolean | `true` | Whether to show the zoom in and zoom out buttons. |

The SDK changes four MapLibre defaults:

| MapLibre option | Radar default | Override |
| --- | --- | --- |
| `maxZoom` | `20` | Pass the option. |
| `dragRotate` | `false` | Pass the option. |
| `touchPitch` | `false` | Pass the option. |
| Attribution control and logo | Replaced by Radar's logo and attribution control | None. See [Attribution](/api/maps#attribution). |

When the map container is narrower than 380 pixels, the SDK hides the attribution text and keeps the logo.

`RadarMap` adds these functions to the MapLibre map:

| Function | Arguments | Returns | Description |
| --- | --- | --- | --- |
| `getMarkers` | None | `RadarMarker[]` | Returns all markers on the map. |
| `fitToMarkers` | `fitBoundsOptions` (optional), `RadarMarker[]` (optional) | void | Fits the view to all markers, or to the markers you pass. Default padding is 50 pixels. Does nothing when there are no markers. |
| `clearMarkers` | None | void | Removes all markers. |
| `getFeatures` | None | `RadarMapFeature[]` | Returns all features added with `addPolygon`, `addLine`, and `addPolyline`. |
| `fitToFeatures` | `fitBoundsOptions` (optional), `RadarMapFeature[]` (optional) | void | Fits the view to all features, or to the features you pass. |
| `clearFeatures` | None | void | Removes all features. |
| `addPolygon` | GeoJSON `Polygon` or `MultiPolygon` feature, options (optional) | `RadarMapFeature` | Adds a polygon. |
| `addLine` | GeoJSON `LineString` feature, options (optional) | `RadarMapFeature` | Adds a line. |
| `addPolyline` | Encoded polyline string, options (optional) | `RadarMapFeature` | Decodes a polyline and adds it as a line. Precision defaults to `6`. |

`fitBoundsOptions` are MapLibre [FitBoundsOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/FitBoundsOptions/), such as `padding` and `maxZoom`. Use `map.on()` for MapLibre [map events](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapEventType/). To switch styles after the map is created, call MapLibre's `map.setStyle()` with a Radar style name or custom style ID.

This example listens for map events and fits the view:

```javascript
map.on('load', () => {
  // The style has loaded and the map is ready.
});

map.on('click', (event) => {
  console.log(event.lngLat);
});

map.fitToMarkers({ padding: 20 });
map.fitToFeatures({ padding: 20 });
```

### Marker and popup options

`Radar.ui.marker()` returns a `RadarMarker`, which extends the MapLibre [`Marker`](https://maplibre.org/maplibre-gl-js/docs/API/classes/Marker/) class. Position it with `setLngLat([longitude, latitude])` and add it with `addTo(map)`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `color` | string | `#000257` | Color of the default marker. |
| `marker` | string | None | ID of a marker image uploaded to a [custom style](/maps/maps#custom-styles). |
| `url` | string | None | URL of an image to use as the marker. |
| `element` | `HTMLElement` | None | A DOM element to use as the marker. |
| `width` | number or string | None | Image width, in pixels or as a CSS value. |
| `height` | number or string | None | Image height, in pixels or as a CSS value. |
| `scale` | number | `1` | Scale of the default marker. |
| `popup` | object | None | Popup options for a popup that opens when the marker is selected. |

When you set `url` or `marker` without a width or height, the image is capped at 64 by 64 pixels. If the image fails to load, the SDK logs an error and shows the default marker.

Of MapLibre's own marker options, the plugin forwards only `color`, `element`, and `scale`. For other MapLibre marker behavior, call the marker's methods after you create it, for example `marker.setDraggable(true)`.

Selecting a marker opens its popup and closes any other open marker popup. The marker's `click` event receives `target` (the marker), `lngLat`, `point`, and `originalEvent`. A click on a marker doesn't also fire the map's `click` event.

A popup shows text or HTML at a point on the map. Attach one to a marker with the marker's `popup` option, or create a standalone popup with `Radar.ui.popup()`. Popups accept all MapLibre [PopupOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/PopupOptions/) plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `text` | string | None | Plain text to show in the popup. |
| `html` | string | None | An HTML string to show in the popup. |
| `element` | `HTMLElement` | None | A DOM element to use as the popup content. |

<Warning>
  `html` is inserted as markup. If any part of it comes from user input or from data you don't control, use `text` or build an `element` with `textContent` to avoid script injection.
</Warning>

This example adds a marker with a popup, listens for clicks, and creates a standalone popup:

```javascript
const marker = Radar.ui.marker({
  color: '#000257',
  popup: {
    text: 'Flatiron',
  },
})
  .setLngLat([-73.9897, 40.7411])
  .addTo(map);

marker.on('click', (event) => {
  console.log(event.lngLat, event.target);
});

const popup = Radar.ui.popup({
  text: 'Union Square',
})
  .setLngLat([-73.990550, 40.735225])
  .addTo(map);
```

### Shape paint defaults

Features are lines and polygons that you add to the map, style, and listen to. The input is a [GeoJSON Feature](https://datatracker.ietf.org/doc/html/rfc7946#section-3.2) with `Polygon`, `MultiPolygon`, or `LineString` geometry.

- Each feature needs a unique `id`. Adding a second feature with the same ID throws an error. If you omit the ID, the SDK generates one.
- `properties` carry your own data and are returned in feature events.
- `feature.on(type, callback)` supports `click`, `mousemove`, `mouseenter`, and `mouseleave`. The callback receives an object with `type`, `feature`, and `originalEvent` (the MapLibre mouse event, which has `lngLat`).
- `feature.remove()` removes the feature and its layers.

`map.addPolygon(feature, options)` adds a `Polygon` or `MultiPolygon`. Its `paint` option supports these properties:

| Property | Possible values | Default |
| --- | --- | --- |
| `fill-color` | string (CSS color) | `#FF6F00` |
| `fill-opacity` | number (0 to 1) | `0.3` |
| `border-width` | number (pixels) | `2` |
| `border-color` | string (CSS color) | `#FF6F00` |
| `border-opacity` | number (0 to 1) | `1` |

`map.addLine(feature, options)` adds a GeoJSON `LineString`, and `map.addPolyline(polyline, options)` adds an encoded polyline. For polylines, `options` also takes `id`, `properties`, and `precision` (default `6`; use `5` for polylines encoded with five decimal places). The `paint` option for both supports these properties:

| Property | Possible values | Default |
| --- | --- | --- |
| `line-color` | string (CSS color) | `#000257` |
| `line-width` | number (pixels) | `4` |
| `line-opacity` | number (0 to 1) | None |
| `line-cap` | `butt`, `round`, or `square` | `round` |
| `line-offset` | number (pixels) | None |
| `line-blur` | number (pixels) | None |
| `line-dasharray` | array of numbers | None |
| `line-gap-width` | number (pixels) | None |
| `line-gradient` | MapLibre [expression](https://maplibre.org/maplibre-gl-js/docs/examples/line-gradient/) | None |
| `border-width` | number (pixels) | `2` |
| `border-color` | string (CSS color) | `#FFFFFF` |
| `border-opacity` | number (0 to 1) | None |

This example adds an encoded polyline as a styled line:

```javascript
const feature = map.addPolyline(encodedPolyline, {
  id: 'route-1',
  precision: 6,
  properties: {
    name: 'Delivery route',
  },
  paint: {
    'line-color': 'blue',
    'line-opacity': 0.6,
    'line-width': 6,
    'border-width': 2,
    'border-color': '#FFFFFF',
  },
});
```

For a polygon example with a click handler, see [Display a polygon](/maps/maps#display-a-polygon).

### Autocomplete options

`Radar.ui.autocomplete()` creates an address search input with a suggestions list in the element you name. It takes these options:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `container` | string or `HTMLElement` | `autocomplete` | The element ID or element to render the component into. |
| `minCharacters` | number | `3` | Characters required before the first request. Lower values send more requests and return less relevant results. |
| `debounceMS` | number | `200` | Milliseconds to wait after the last keystroke before a request is sent. |
| `limit` | number | `8` | Maximum number of suggestions shown. |
| `layers` | array of string | None | Restricts results to kinds of result, for example `['address']` for street addresses only, or `['postalCode', 'locality']` for a city or postal code search. Without it, results come from the address and coarse (postal code, city, county, state, country) layers. |
| `countryCode` | string | None | Restricts results to a country, as a two-letter code. |
| `lang` | string | None | The language for results. |
| `near` | object or string | None | A location to prefer results near, as `{ latitude, longitude }` or a `"latitude,longitude"` string. Without it, results are biased by the request's IP-derived location. |
| `postalCode` | string | None | Restricts results to a postal code. |
| `mailable` | boolean | None | Returns only mailable addresses. |
| `placeholder` | string | `Search address` | Placeholder text for the input. |
| `responsive` | boolean | `true` | Whether the input takes the full width of its container, with `width` as a maximum. |
| `width` | number or string | `400` | Width in pixels or as a CSS value. With `responsive` set to `true` it acts as a maximum width. |
| `maxHeight` | number or string | None | Maximum height of the suggestions list, in pixels or as a CSS value. |
| `disabled` | boolean | `false` | Disables the input. |
| `showMarkers` | boolean | `true` | Shows a marker icon next to each suggestion. |
| `markerColor` | string | `#ACBDC8` | Color of the marker icons. |
| `hideResultsOnBlur` | boolean | `true` | Closes the list when the input loses focus. |
| `idPrefix` | string | `radar-autocomplete` | Prefix for element IDs. Set a different value for each component when a page has more than one. |
| `ariaLabel` | string | `Search for an address` | Accessible label for the input. |
| `onSelection` | function | None | Called with the chosen address. |
| `onResults` | function | None | Called with the array of suggestions each time the list refreshes. |
| `onRequest` | function | None | Called with the request parameters before each request. |
| `onError` | function | None | Called with the error when a request fails. |
| `onEnrichment` | function | None | Called after `onSelection` with the enriched address, only when the project has address enrichment enabled. |

For checkout forms that take United States and Canada addresses, set `layers` to `['address']` and limit results to those countries.

The component that `Radar.ui.autocomplete()` returns has setters for changes after creation, including `setNear()`, `setPlaceholder()`, `setDisabled()`, `setMinCharacters()`, `setLimit()`, `setLang()`, `setPostalCode()`, and `setWidth()`, and a `remove()` method. To keep your own input and suggestions list, use `Radar.AutocompleteSession` in [Search](#search).

## Errors

Every method that returns a promise rejects with a subclass of `RadarError`. Each error has a `name`, a `message`, and a `status` string. The error classes are available on `Radar.errors`.

| Error | `status` | HTTP code | Cause |
| --- | --- | --- | --- |
| `RadarPublishableKeyError` | `ERROR_PUBLISHABLE_KEY` | None | The SDK isn't initialized, or the key is missing or is a secret key. |
| `RadarPermissionsError` | `ERROR_PERMISSIONS` | None | The user denied location permission in the browser. |
| `RadarLocationError` | `ERROR_LOCATION` | None | The browser couldn't determine a location, the location request timed out (10 seconds by default), or the Geolocation API isn't available. |
| `RadarNetworkError` | `ERROR_NETWORK` | None | The network is unavailable or the request timed out (10 seconds by default). |
| `RadarBadRequestError` | `ERROR_BAD_REQUEST` | 400 | Missing or invalid parameters. |
| `RadarUnauthorizedError` | `ERROR_UNAUTHORIZED` | 401 | Invalid API key. |
| `RadarPaymentRequiredError` | `ERROR_PAYMENT_REQUIRED` | 402 | Organization disabled or usage exceeded. |
| `RadarForbiddenError` | `ERROR_FORBIDDEN` | 403 | Insufficient permissions or no access to the feature. |
| `RadarNotFoundError` | `ERROR_NOT_FOUND` | 404 | Not found. |
| `RadarRateLimitError` | `ERROR_RATE_LIMIT` | 429 | Too many requests. See [rate limits](/api/fundamentals). The error also has a `type` field with the rate limit type from the API. |
| `RadarServerError` | `ERROR_SERVER` | 5xx | Internal server error. |
| `RadarUnknownError` | `ERROR_UNKNOWN` | Other | An unexpected response. |

Errors that come from an API response include the API response body as `response`. The 400, 401, 402, 403, 404, and 429 errors also include the HTTP response code as `code`:

```javascript
Radar.trackOnce()
  .catch((err) => {
    if (err instanceof Radar.errors.RadarPermissionsError) {
      // ask the user to allow location access for this site
    } else if (err instanceof Radar.errors.RadarRateLimitError) {
      // back off before retrying
    }
    console.error(err.name, err.status, err.code, err.response?.meta?.message);
  });
```

To observe every SDK error in one place, register a callback with `Radar.onError()`.

## Request IDs

Every API response includes an `X-Radar-Request-ID` header with a unique identifier for the request. The Web SDK surfaces this identifier as `meta.requestId` on the API response body.

If a request fails, get the request ID from the API response body on the error:

```javascript
Radar.trackOnce()
  .catch((err) => {
    const requestId = err.response?.meta?.requestId;
  });
```

When the `debug` option is on, the API response body is also included on successful results, as `response`:

```javascript
Radar.initialize('prj_live_pk_...', { debug: true });

Radar.trackOnce()
  .then((result) => {
    const requestId = result.response?.meta?.requestId;
  });
```

If you contact [Radar support](https://radar.com/support) about a specific API call, include the request ID.
