At the end of this page you have `react-native-radar` installed, the native iOS and Android projects configured, and a reference for every method, listener, and UI component the module exposes.

This page documents `react-native-radar` 4.39.0. The source is on [GitHub](https://github.com/radarlabs/react-native-radar) and the package is on [npm](https://www.npmjs.com/package/react-native-radar).

### Upgrade from 3.x

Version 4 raised the minimum React Native version from 0.60.0 to 0.80.0, React from 16.8.6 to 19.1.0, and `@maplibre/maplibre-react-native` from 10.2.1 to 11. It also moved iOS fraud detection out of the main SDK: `Radar.trackVerified()` now requires the fraud plugin on both platforms. For every step, see [MIGRATION.md](https://github.com/radarlabs/react-native-radar/blob/master/MIGRATION.md).

## Install

Install the package from npm:

```bash
npm install --save react-native-radar
```

The module autolinks. It needs native code, so it doesn't run in Expo Go. Use a development build or a bare React Native app.

Then choose one path:

- **Expo**: Configure the [Expo plugin](#expo) and run `npx expo prebuild`. The plugin applies the iOS and Android steps below for you.
- **Bare React Native**: Follow the [iOS](#ios) and [Android](#android) steps by hand.

### iOS

1. Install pods:

   ```bash
   cd ios && pod install
   ```

   The `Radar` pod vendors the Radar iOS SDK, so you don't add `RadarSDK` to your `Podfile` separately.

2. Add location usage descriptions to `Info.plist`. These strings appear in the permission prompts.

   | Key | When it is required |
   | --- | --- |
   | `NSLocationWhenInUseUsageDescription` | Always. Needed for foreground permission. |
   | `NSLocationAlwaysAndWhenInUseUsageDescription` | When you request background permission. |
   | `NSMotionUsageDescription` | When you add the motion plugin. |

3. For background tracking with the responsive or continuous preset, open your target in Xcode, select **Signing & Capabilities**, add **Background Modes**, and select **Location updates** and **Background fetch**. Your `Info.plist` then lists `location` and `fetch` under `UIBackgroundModes`. Background location needs justification during App Store review. See the [iOS SDK reference](/sdk/ios).

4. Optional. To link the fraud plugin or the motion plugin, add the pods inside your app target in `ios/Podfile`, then run `pod install` again:

   ```ruby
   pod 'RadarSDKFraud', :path => '../node_modules/react-native-radar'
   pod 'RadarSDKMotion', :path => '../node_modules/react-native-radar'
   ```

### Android

1. Add Google Play Services Location to `android/app/build.gradle`. Use version 21.0.1 or later.

   ```gradle
   implementation "com.google.android.gms:play-services-location:21.0.1"
   ```

   The module already declares `io.radar:sdk`, so you don't add the Radar Android SDK yourself.

2. The Radar Android SDK manifest contributes `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `INTERNET`, `ACCESS_NETWORK_STATE`, `RECEIVE_BOOT_COMPLETED`, and `FOREGROUND_SERVICE`. Add the permissions below to your own `AndroidManifest.xml` only when you use the matching feature.

   | Permission | When to add it |
   | --- | --- |
   | `android.permission.ACCESS_BACKGROUND_LOCATION` | Background tracking without a foreground service, when you target API level 29 or later. |
   | `android.permission.FOREGROUND_SERVICE_LOCATION` | Tracking with a foreground service. |
   | `android.permission.ACTIVITY_RECOGNITION` | Motion activity detection. |

   For example, to add the background location permission:

   ```xml
   <manifest xmlns:android="http://schemas.android.com/apk/res/android">
     <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
   </manifest>
   ```

3. Optional. To use verified location, add the fraud plugin and Play Integrity. See [Fraud plugin setup](/sdk/fraud) for the `io.radar:sdk-fraud` version that matches your SDK.

If the build reports a core library desugaring error, enable desugaring in `android/app/build.gradle`. The Expo plugin does this for you with `coreLibraryDesugaringEnabled true` and `com.android.tools:desugar_jdk_libs:2.1.5`.

### Expo

Add `react-native-radar` to `plugins` in `app.json` and set the options you need:

```json
{
  "expo": {
    "plugins": [
      [
        "react-native-radar",
        {
          "iosNSLocationWhenInUseUsageDescription": "Your foreground location usage description.",
          "iosNSLocationAlwaysAndWhenInUseUsageDescription": "Your background location usage description.",
          "iosBackgroundMode": true,
          "androidBackgroundPermission": true,
          "androidForegroundService": true
        }
      ],
      [
        "expo-build-properties",
        {
          "ios": {
            "useFrameworks": "static"
          }
        }
      ]
    ]
  }
}
```

If you use the `Map` component, also add `"@maplibre/maplibre-react-native"` to `plugins`.

Then regenerate the native projects:

```bash
npx expo prebuild --clean
```

All plugin options are optional. Boolean options default to `false`.

| Option | Type | Description |
| --- | --- | --- |
| `iosNSLocationWhenInUseUsageDescription` | string | Sets `NSLocationWhenInUseUsageDescription`. If omitted, the plugin writes a generic default string. |
| `iosNSLocationAlwaysAndWhenInUseUsageDescription` | string | Sets `NSLocationAlwaysAndWhenInUseUsageDescription`. Required for background permission. |
| `iosBackgroundMode` | boolean | Adds `location` and `fetch` to `UIBackgroundModes`. Required for the responsive and continuous presets. |
| `iosFraud` | boolean | Adds the `RadarSDKFraud` pod, links it into the app target, and adds the App Transport Security pinning entry for `api-verified.radar.io`. |
| `addRadarSDKMotion` | boolean | Adds the `RadarSDKMotion` pod and `NSMotionUsageDescription`. |
| `iosNSMotionUsageDescription` | string | Overrides the default `NSMotionUsageDescription` string. Used only with `addRadarSDKMotion`. |
| `iosAutoHandleNotificationDeepLinks` | boolean | Injects `Radar.nativeSetup()` into `AppDelegate` with `autoHandleNotificationDeepLinks` on, so cold-start notification taps open the URL in the payload. |
| `iosAutoLogNotificationConversions` | boolean | Injects `Radar.nativeSetup()` into `AppDelegate` with `autoLogNotificationConversions` on. |
| `androidFraud` | boolean | Adds `io.radar:sdk-fraud` and `com.google.android.play:integrity` to `android/app/build.gradle` and writes `network_security_config.xml`. |
| `androidBackgroundPermission` | boolean | Adds `ACCESS_BACKGROUND_LOCATION`. |
| `androidForegroundService` | boolean | Adds `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_LOCATION`. |
| `androidActivityRecognition` | boolean | Adds `ACTIVITY_RECOGNITION`. |

On Android the plugin always adds `play-services-location` 21.0.1 and enables core library desugaring.

## Integrate

### Import module

Import the module:

```javascript
import Radar from 'react-native-radar';
```

### Initialize

Initialize the SDK with your publishable key when your app starts:

```javascript
Radar.initialize('prj_test_pk_...');
```

Use your test publishable key (`prj_test_pk_...`) in development and your live publishable key (`prj_live_pk_...`) in production.

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

The full signature is `Radar.initialize(publishableKey, fraud?, options?)`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `publishableKey` | string | Yes | Your publishable key. |
| `fraud` | boolean | No | Pass `true` when you use verified location. Defaults to `false`. |
| `options` | object or `null` | No | Initialization options. See the next table. |

| Field | Type | Description |
| --- | --- | --- |
| `silentPush` | boolean | Enables [silent push](/sdk/silent-push). |
| `autoLogNotificationConversions` | boolean | Logs a conversion when a Radar notification opens the app. |
| `autoHandleNotificationDeepLinks` | boolean | Opens the deep link in a Radar notification payload. |
| `trackVerifiedAutoFailover` | boolean | Enables automatic failover for `trackVerified()` requests. |
| `networkTimeoutInterval` | number | Request timeout for standard API calls, in seconds. |
| `ipChangeDebounceInterval` | number | Minimum interval between IP-change callbacks, in seconds. `0` delivers every change. |

For example, to initialize with fraud detection:

```javascript
Radar.initialize('prj_test_pk_...', true, {});
```

`Radar.initializeWithAuthToken(authToken, fraud?, options?)` takes the same arguments with an auth token in place of the publishable key. See [Authenticate the SDK with auth tokens](/sdk/fraud#authenticate-the-sdk-with-auth-tokens). `Radar.isInitialized()` resolves to a boolean.

To verify, call `Radar.nativeSdkVersion()` after initializing. It resolves to the native SDK version string. `Radar.rnSdkVersion()` returns the module version.

### Identify user

Identify the user with an ID, metadata, and a description:

```javascript
Radar.setUserId('user-123');
Radar.setMetadata({ tier: 'gold', orders: 12, optedIn: true });
Radar.setDescription('Example user');
```

| Method | Argument |
| --- | --- |
| `setUserId(userId)` | A stable unique ID for the user. |
| `setMetadata(metadata)` | An object with string, number, or boolean values. Radar accepts up to 16 keys. |
| `setDescription(description)` | A string shown in the Radar dashboard. |

These values persist across app sessions, so call each setter once, for example after login. `getUserId()`, `getMetadata()`, and `getDescription()` return promises with the stored values.

`Radar.setAnonymousTrackingEnabled(enabled)` turns anonymous tracking on or off. `Radar.setProduct(product)` and `Radar.getProduct()` set and read an optional product name, shown in the dashboard and reports.

For how identity affects each product, see the [iOS SDK reference](/sdk/ios) and [Android SDK reference](/sdk/android).

### Debug logging

By default, only critical errors are logged to the console. To change the level, call:

```javascript
Radar.setLogLevel('debug');
```

Valid levels are `'none'`, `'error'`, `'warning'`, `'info'`, and `'debug'`. To receive log lines in JavaScript, register `Radar.onLog((message) => {})`.

Logging app lifecycle events happens in native code. On iOS, see the [iOS SDK reference](/sdk/ios). On Android, it needs no extra setup.

### Request permissions

The user must grant location permission before you track. To read the current status, call:

```javascript
const status = await Radar.getPermissionsStatus();
```

`status` is one of:

- `GRANTED_BACKGROUND`
- `GRANTED_FOREGROUND`
- `NOT_DETERMINED`
- `DENIED`
- `UNKNOWN`

To request permission, call `Radar.requestPermissions(background)`, where `background` is a boolean. It resolves to the new status. On iOS and Android the user must grant foreground permission before you can ask for background permission:

```javascript
try {
  const foreground = await Radar.requestPermissions(false);
  if (foreground === 'GRANTED_FOREGROUND') {
    const background = await Radar.requestPermissions(true);
    console.log('Location permission:', background);
  }
} catch (err) {
  console.warn('Permission request failed', err);
}
```

To verify, build and run the app on a device and confirm both prompts appear. For when to ask for each level, see [Understand foreground and background location permissions](/fundamentals/location-permissions).

### Foreground tracking

After you initialize the SDK and the user grants permission, track the user's location once:

```javascript
try {
  const result = await Radar.trackOnce();
  // result.status, result.location, result.events, result.user
} catch (err) {
  console.warn('trackOnce failed', err.code);
}
```

`trackOnce()` accepts an optional options object:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `location` | object | None | A `{ latitude, longitude, accuracy }` object. Sends this location instead of reading the device location. See [Manual tracking](#manual-tracking). |
| `desiredAccuracy` | string | `'medium'` | One of `'high'`, `'medium'`, `'low'`, or `'none'`. |
| `beacons` | boolean | `false` | Ranges nearby beacons. |

Promise-returning methods resolve only on success, with `status` set to `SUCCESS`. On failure they reject with an error whose `code` and `message` are one of these status strings:

- **`ERROR_PUBLISHABLE_KEY`**: SDK not initialized
- **`ERROR_PERMISSIONS`**: location permissions not granted
- **`ERROR_LOCATION`**: location services error or timeout
- **`ERROR_BLUETOOTH`**: beacon ranging error or timeout
- **`ERROR_NETWORK`**: network error or timeout
- **`ERROR_BAD_REQUEST`**: bad request (missing or invalid params)
- **`ERROR_UNAUTHORIZED`**: unauthorized (invalid API key)
- **`ERROR_PAYMENT_REQUIRED`**: payment required (organization disabled or usage exceeded)
- **`ERROR_FORBIDDEN`**: forbidden (insufficient permissions or no beta access)
- **`ERROR_NOT_FOUND`**: not found
- **`ERROR_PLUGIN`**: a required plugin, such as the fraud plugin, is missing
- **`ERROR_RATE_LIMIT`**: too many requests (rate limit exceeded)
- **`ERROR_SERVER`**: internal server error
- **`ERROR_UNKNOWN`**: unknown error

`Radar.getLocation(desiredAccuracy?)` reads the device location without sending it to Radar. It resolves to `{ status, location, stopped }`.

### Background tracking

After you initialize the SDK and the user grants permission, start tracking in the background. The SDK supports custom tracking options and three presets:

- **`EFFICIENT`**: A low frequency of location updates and the lowest battery usage. On Android, avoids Android vitals bad behavior thresholds.
- **`RESPONSIVE`**: A medium frequency of location updates and low battery usage. Suitable for most consumer use cases.
- **`CONTINUOUS`**: A high frequency of location updates and higher battery usage. Suitable for on-demand use cases such as delivery tracking.

Start tracking with one of the presets:

```javascript
Radar.startTrackingEfficient();
Radar.startTrackingResponsive();
Radar.startTrackingContinuous();
```

Call one of these once. Tracking options persist across app sessions.

Presets cover most use cases. To customize, pass a full options object to `startTrackingCustom()`. The package exports `presetEfficient`, `presetResponsive`, and `presetContinuous`, which resolve to the right values for the current platform, so you can start from a preset and change the fields you need. For field meanings, units, and defaults, see the [tracking options reference](/sdk/tracking).

```javascript
import Radar, { presetContinuous } from 'react-native-radar';

// Android only: configure the foreground service notification
Radar.setForegroundServiceOptions({
  text: 'Location tracking started',
  title: 'Location updates',
  updatesOnly: false,
  importance: 2,
  activity: 'com.example.app.MainActivity',
});

Radar.startTrackingCustom({
  ...presetContinuous,
  desiredStoppedUpdateInterval: 180,
  desiredMovingUpdateInterval: 60,
  desiredSyncInterval: 10,
});
```

`setForegroundServiceOptions()` takes the options object directly. It accepts `text`, `title`, `icon`, `iconString`, `iconColor`, `updatesOnly`, `activity`, `importance`, `id`, and `channelName`. It does nothing on iOS.

To check and stop tracking:

```javascript
const tracking = await Radar.isTracking();
Radar.stopTracking();
```

`Radar.getTrackingOptions()` resolves to the options in use. `Radar.isUsingRemoteTrackingOptions()` resolves to `true` when [remote configuration](/sdk/remote-configuration) controls them.

#### Listen for events

Each listener method takes one callback. Calling it again replaces the previous callback. Passing `null` removes it.

```javascript
Radar.onClientLocationUpdated((result) => {
  // result.location, result.stopped, result.source
});

Radar.onLocationUpdated((result) => {
  // result.location, result.user
});

Radar.onEventsReceived((result) => {
  // result.events, result.user
});

Radar.onError((status) => {
  // status is a status string such as ERROR_LOCATION
});
```

| Listener | Callback argument |
| --- | --- |
| `onClientLocationUpdated` | `{ location, stopped, source }`. Fires when the device location updates, whether or not it has synced to the server. |
| `onLocationUpdated` | `{ location, user }`. Fires after a location syncs to the server. |
| `onEventsReceived` | `{ events, user }`. |
| `onError` | A status string. |
| `onLog` | A log message string. |
| `onTokenUpdated` | A geolocation token. See [Verified location](#verified-location). |
| `onSharingChanged` | A boolean. Fires when screen sharing starts or stops. |
| `onIpChanged` | No argument. Fires when the device IP address changes. |
| `onNewInAppMessage`, `onInAppMessageDismissed`, `onInAppMessageClicked` | An in-app message object. |

Register listeners once, before tracking begins. To have them fire when the app is in the background, register them outside your component lifecycle, for example at module scope.

To remove listeners:

```javascript
Radar.onClientLocationUpdated(null);
Radar.onLocationUpdated(null);
Radar.onEventsReceived(null);
Radar.onError(null);
```

`initialize()` registers an `onNewInAppMessage` listener that calls `Radar.showInAppMessage()`. Register your own `onNewInAppMessage` callback after `initialize()` to replace that behavior.

### Battery usage

React Native loads and parses your JavaScript bundle on each app launch, and background tracking can launch the app in the background. Background tracking with the React Native module can therefore use more battery than a native integration.

On iOS, the app loads the JavaScript bundle when it launches. If you don't need events in JavaScript while in the background, check `launchOptions` for `UIApplicationLaunchOptionsLocationKey` in your `AppDelegate` and skip loading the bundle for location launches.

On Android, version 4 of the module registers its receiver in code when the module loads, not in the manifest. The 3.x manifest override for `io.radar.react.RNRadarReceiver` no longer applies, so remove it.

### Mock tracking

To simulate a sequence of location updates for testing, call `mockTracking()`. This example simulates 10 updates, 3 seconds apart, by car:

```javascript
Radar.mockTracking({
  origin: { latitude: 40.714708, longitude: -74.035807 },
  destination: { latitude: 40.717410, longitude: -74.053334 },
  mode: 'car',
  steps: 10,
  interval: 3,
});
```

`mode` is one of `'foot'`, `'bike'`, `'car'`, `'truck'`, or `'motorbike'`. `interval` is in seconds.

### Trip tracking

Start a trip to a destination geofence. `trackingOptions` is optional and applies while the trip is active.

```javascript
import Radar, { presetContinuous } from 'react-native-radar';

try {
  const result = await Radar.startTrip({
    tripOptions: {
      externalId: 'order-299',
      destinationGeofenceTag: 'store',
      destinationGeofenceExternalId: 'store-42',
      mode: 'car',
    },
    trackingOptions: presetContinuous,
  });
  // result.status, result.trip, result.events
} catch (err) {
  console.warn('startTrip failed', err.code);
}
```

The `tripOptions` object has these fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `externalId` | string | Yes | Your ID for the trip. |
| `destinationGeofenceTag` | string | No | Tag of the destination geofence. |
| `destinationGeofenceExternalId` | string | No | External ID of the destination geofence. |
| `mode` | string | No | Travel mode. One of `'foot'`, `'bike'`, `'car'`, `'truck'`, or `'motorbike'`. |
| `metadata` | object | No | Custom metadata. |
| `scheduledArrivalAt` | number | No | The scheduled arrival time for the trip. |
| `approachingThreshold` | number | No | Approaching threshold in minutes. |
| `startTracking` | boolean | No | Set to `false` to start the trip without starting tracking. Defaults to `true`. |
| `legs` | array | No | Legs of a multi-leg trip. |

Update the trip. Set `status` to `'unknown'` to leave the status unchanged and let location tracking update it.

```javascript
const result = await Radar.updateTrip({
  status: 'arrived',
  options: {
    externalId: 'order-299',
    metadata: { parkingSpot: '5' },
  },
});
```

`status` is one of `'unknown'`, `'started'`, `'approaching'`, `'arrived'`, `'expired'`, `'completed'`, or `'canceled'`.

Complete or cancel the trip:

```javascript
await Radar.completeTrip();
await Radar.cancelTrip();
```

If tracking was off before the trip started, it stops when the trip ends. Otherwise it reverts to the tracking options in use before the trip.

`Radar.getTrip()` resolves to the current trip or `null`. `Radar.getTripOptions()` resolves to the current trip options.

For multi-leg trips, `Radar.updateTripLeg({ legId, status, tripId? })` updates one leg and resolves to `{ status, trip, leg, events }`. `Radar.reorderTripLegs({ legIds, tripId? })` reorders legs and resolves to `{ status, trip, events }`. Leg status is one of `'unknown'`, `'pending'`, `'started'`, `'approaching'`, `'arrived'`, `'completed'`, `'canceled'`, or `'expired'`.

For the full workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

### Manual tracking

To send a location you already have, pass it as `location`:

```javascript
const result = await Radar.trackOnce({
  location: {
    latitude: 39.2904,
    longitude: -76.6122,
    accuracy: 65,
  },
});
// result.events, result.user
```

### Verified location

Verified location methods need the fraud plugin on each platform and `fraud` set to `true` in `initialize()`. For install steps, attestation setup, and compatible plugin versions, see [Fraud plugin setup](/sdk/fraud).

Run a verified location check and send the token to your backend:

```javascript
Radar.initialize('prj_test_pk_...', true);

try {
  const result = await Radar.trackVerified({ reason: 'login' });
  const token = result.token;
  // Send token.token to your backend and validate it there.
} catch (err) {
  console.warn('trackVerified failed', err.code);
}
```

| Method | Description |
| --- | --- |
| `trackVerified(options?)` | Runs a verified location check. Options: `beacons`, `desiredAccuracy`, `reason`, `transactionId`. Resolves to `{ status, token }`. |
| `getVerifiedLocationToken()` | Resolves to `{ status, token }`. |
| `clearVerifiedLocationToken()` | Clears the cached token. |
| `startTrackingVerified(options?)` | Starts periodic verified checks. Options: `interval` in seconds, `beacons`. |
| `stopTrackingVerified()` | Stops periodic verified checks. |
| `isTrackingVerified()` | Resolves to a boolean. |
| `setExpectedJurisdiction(countryCode, stateCode)` | Sets the expected country and state. Pass `null` to clear. |
| `setExpectedAddress(address)` | Sets the expected address. Pass `null` to clear. |
| `onTokenUpdated(callback)` | Fires when a new token is available. |
| `revealRisk()` | Resolves to `{ status, token }` with a risk token that has `risk`, `network`, and `device` fields. |
| `isSharing()`, `clearSharing()`, `onSharingChanged(callback)` | Read, reset, and observe screen sharing state. |

The geolocation token has `token`, `expiresAt`, `expiresIn`, `passed`, `user`, and `events`. Reading `passed` in the app isn't validation. Send `token.token` to your backend and validate it there. See [Geolocation token schema](/api/geolocation-tokens) and the [Geo-compliance overview](/geo-compliance/overview).

If the fraud plugin isn't linked, `trackVerified()` rejects with `ERROR_PLUGIN`.

### Beacons

To range beacons on a single call, set `beacons: true` on `trackOnce()` or `trackVerified()`. To range during background tracking, set `beacons: true` in your tracking options. `Radar.startRangingBeacons()` and `Radar.stopRangingBeacons()` start and stop ranging directly.

Beacon ranging needs Bluetooth permission and native setup. See [Track indoor location with beacons](/geofencing/beacons).

### Location metadata

The SDK can attach motion activity, speed, and heading to location updates.

On iOS, motion activity needs the motion plugin. With Expo, set `addRadarSDKMotion` to `true` in the plugin options. In a bare app, add the `RadarSDKMotion` pod and `NSMotionUsageDescription` as described in [iOS](#ios).

On Android, motion activity needs the `ACTIVITY_RECOGNITION` permission. With Expo, set `androidActivityRecognition` to `true`.

### Other APIs

The module also exposes context, geocoding, search, routing, and conversion APIs. Each returns a promise and rejects with a status string on failure.

#### Context

`Radar.getContext(location?)` resolves to `{ status, location, context }` for the device location or for a location you pass:

```javascript
const result = await Radar.getContext({ latitude: 40.783826, longitude: -73.975363 });
// result.context.geofences, result.context.place, result.context.country
```

#### Geocoding

Forward geocode an address with the [geocoding API](/api/geocoding). `geocode()` takes an options object with a required `address` and optional `layers` and `countries` arrays:

```javascript
const result = await Radar.geocode({ address: '20 jay st brooklyn ny' });
// result.addresses
```

Reverse geocode a location. Omit the argument to use the device location. `layers` is optional.

```javascript
const result = await Radar.reverseGeocode({
  location: { latitude: 40.783826, longitude: -73.975363 },
});
// result.addresses
```

Geocode the device's IP address to a city, state, and country:

```javascript
const result = await Radar.ipGeocode();
// result.address, result.proxy
```

`Radar.validateAddress(address)` validates a structured address object, such as one returned by `geocode()` or `autocomplete()`. It resolves to `{ status, address, verificationStatus }`.

#### Search

Autocomplete partial addresses and place names with the [search API](/api/search). `query` and `limit` are required. `near`, `layers`, `country`, and `mailable` are optional.

```javascript
const result = await Radar.autocomplete({
  query: 'brooklyn roasting',
  near: { latitude: 40.783826, longitude: -73.975363 },
  limit: 10,
});
// result.addresses
```

Search for geofences near a location, sorted by distance. `near`, `radius` (meters), `tags`, `metadata`, and `limit` are optional. Omit `near` to search near the device location.

```javascript
const result = await Radar.searchGeofences({
  radius: 1000,
  tags: ['venue'],
  limit: 10,
  includeGeometry: false,
});
// result.geofences
```

Search for places near a location, sorted by distance. Filter with `chains`, `chainMetadata`, `categories`, `groups`, or `countryCodes`.

```javascript
const result = await Radar.searchPlaces({
  near: { latitude: 40.783826, longitude: -73.975363 },
  radius: 1000,
  chains: ['starbucks'],
  limit: 10,
});
// result.places
```

#### Distance

Calculate travel distance and duration from an origin to a destination with the [routing API](/api/routing). Omit `origin` to use the device location.

```javascript
const result = await Radar.getDistance({
  origin: { latitude: 40.78382, longitude: -73.97536 },
  destination: { latitude: 40.70390, longitude: -73.98670 },
  modes: ['foot', 'car'],
  units: 'imperial',
});
// result.routes
```

`units` is `'metric'` or `'imperial'`.

#### Matrix

Calculate travel distance and duration between multiple origins and destinations, for up to 25 routes:

```javascript
const result = await Radar.getMatrix({
  origins: [
    { latitude: 40.78382, longitude: -73.97536 },
    { latitude: 40.70390, longitude: -73.98670 },
  ],
  destinations: [
    { latitude: 40.64189, longitude: -73.78779 },
    { latitude: 35.99801, longitude: -78.94294 },
  ],
  mode: 'car',
  units: 'imperial',
});
// result.matrix
```

#### Conversions

Log a conversion, such as a purchase or signup, to analyze alongside location activity. `logConversion()` takes one options object. `name` is required. `revenue` and `metadata` are optional.

```javascript
const result = await Radar.logConversion({
  name: 'purchase',
  revenue: 12.5,
  metadata: { sku: 'example-sku' },
});
// result.event
```

To log app opens from notification taps on iOS, see [Set up campaign notifications](#set-up-campaign-notifications).

`Radar.acceptEvent(eventId, verifiedPlaceId)` and `Radar.rejectEvent(eventId)` send feedback on an event.

#### User tags

Tags let you target users, for example in campaigns:

```javascript
Radar.setTags(['tag1', 'tag2']);
Radar.addTags(['tag3']);
Radar.removeTags(['tag1']);
const tags = await Radar.getTags();
```

### Set up campaign notifications

[Radar campaigns](/geofencing/geofences-and-places#use-radar-campaigns) can open a deep link when the user taps a notification, and can log the tap as an `opened_app` conversion. On iOS, both are turned on with `RadarInitializeOptions` in native code, so that they apply when a notification tap launches the app, before the JavaScript bundle loads. On Android, no setup is needed for conversions. Configure deep links as you would for any Android app.

<Tabs>
  <Tab title="Expo">
    Set the two options in the `react-native-radar` plugin configuration in `app.json`:

    ```json app.json
    {
      "expo": {
        "plugins": [
          [
            "react-native-radar",
            {
              "iosAutoHandleNotificationDeepLinks": true,
              "iosAutoLogNotificationConversions": true
            }
          ]
        ]
      }
    }
    ```

    Then run `npx expo prebuild --clean`. The plugin adds a `Radar.nativeSetup()` call with these options to your `AppDelegate`, before the `super` call in `didFinishLaunchingWithOptions`. If the plugin can't find that call, it prints a warning and skips the change.
  </Tab>
  <Tab title="Without Expo">
    Call `Radar.nativeSetup()` in your `AppDelegate`, before the `super` call:

    ```objc AppDelegate.mm
    #import <RadarSDK/RadarSDK.h>

    - (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
      RadarInitializeOptions *radarInitializeOptions = [[RadarInitializeOptions alloc] init];
      radarInitializeOptions.autoHandleNotificationDeepLinks = YES;
      radarInitializeOptions.autoLogNotificationConversions = YES;
      [Radar nativeSetup:radarInitializeOptions];
      return [super application:application didFinishLaunchingWithOptions:launchOptions];
    }
    ```

    If your `AppDelegate` is the `UNUserNotificationCenterDelegate`, you can handle taps yourself instead:

    ```objc AppDelegate.mm
    - (void)userNotificationCenter:(UNUserNotificationCenter *)center didReceiveNotificationResponse:(UNNotificationResponse *)response withCompletionHandler:(void (^)(void))completionHandler {
      [Radar openURLFromNotification:response.notification];
      [Radar logConversionWithNotificationResponse:response];
      completionHandler();
    }
    ```
  </Tab>
</Tabs>

To check the setup, send a campaign notification with a link to a test device, force-quit the app, and tap the notification. The app opens at the link, and an `opened_app` conversion appears on the [Events](https://dashboard.radar.com/geofencing/events) page.

iOS can open a universal link from a local notification in Safari, so use a custom URL scheme for campaign links.

### Notification options

On Android, `setNotificationOptions()` sets the icon and color of the foreground service notification and event notifications. Values are resource names in your Android project.

```javascript
// Same icon and color for foreground service and event notifications
Radar.setNotificationOptions({
  iconString: 'icon_1',
  iconColor: 'color_1',
});

// Or set them separately
Radar.setNotificationOptions({
  foregroundServiceIconString: 'icon_1',
  foregroundServiceIconColor: 'color_1',
  eventIconString: 'icon_2',
  eventIconColor: 'color_2',
});
```

This method does nothing on iOS, which uses the app's standard notification icon.

Three more methods are platform specific. `setPushNotificationToken(token)` runs on Android only. `setAppGroup(groupId)` and `setLocationExtensionToken(token)` run on iOS only.

### Maps and UI kits

The package exports two React components, `Map` and `Autocomplete`. Both read the publishable key you passed to `initialize()`.

`Map` renders a Radar base map with MapLibre. Install `@maplibre/maplibre-react-native` version 11 first. Without it, the component renders nothing and logs a warning. This example renders a map with the default style:

```jsx
import { Map } from 'react-native-radar';

export default function StoreMap() {
  return <Map mapOptions={{ mapStyle: 'radar-default-v1', showUserLocation: true }} />;
}
```

| Field | Type | Description |
| --- | --- | --- |
| `mapStyle` | string | Radar map style ID. Defaults to `radar-default-v1`. |
| `showUserLocation` | boolean | Shows the user's location. Defaults to `true`. |
| `mapRef` | React ref | Ref to the underlying MapLibre map, for imperative methods. |
| `onRegionDidChange` | function | Called when the map region changes. |
| `onWillStartLoadingMap`, `onDidFinishLoadingMap`, `onDidFailLoadingMap` | function | Map loading callbacks. |

Children of `Map` render inside the MapLibre map, so you can add your own sources and layers.

`Autocomplete` renders an address search input that calls `Radar.autocomplete()`:

```jsx
import { Autocomplete } from 'react-native-radar';

export default function AddressSearch() {
  return (
    <Autocomplete
      options={{
        placeholder: 'Search address',
        limit: 8,
        onSelection: (address) => console.log(address.formattedAddress),
      }}
    />
  );
}
```

| Option | Default | Description |
| --- | --- | --- |
| `debounceMS` | `200` | Debounce time in milliseconds. |
| `minCharacters` | `3` | Minimum characters before a request is sent. |
| `limit` | `8` | Maximum number of results. |
| `placeholder` | `"Search address"` | Input placeholder text. |
| `showMarkers` | `true` | Shows a marker icon next to each result. |
| `disabled` | `false` | Disables the input. |
| `near` | None | `{ latitude, longitude }` to bias results. |
| `layers` | None | Array of layers to search. |
| `countryCode` | None | Country code to restrict results. |
| `onResults` | None | Called with the array of addresses after each request. |
| `onSelection` | None | Called with the selected address. |
| `onError` | None | Called when a request fails. |
| `style` | None | Style overrides. |

If `react-native-safe-area-context` 5.6.2 or later is installed, `Autocomplete` uses its `SafeAreaView`.

For map and address workflows, see [Display maps](/maps/maps) and [Autocomplete, geocode, and validate addresses](/maps/addresses).
