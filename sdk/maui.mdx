At the end of this page you have the `RadarIO.Xamarin` package installed in your .NET MAUI or Xamarin app, the platform projects configured, and a reference for every method and event the package exposes.

This page documents `RadarIO.Xamarin` 3.9.3, the latest stable version on [NuGet](https://www.nuget.org/packages/RadarIO.Xamarin/). The source is on [GitHub](https://github.com/radarlabs/radar-sdk-xamarin).

## Versions and feature availability

One package, `RadarIO.Xamarin`, carries both the .NET MAUI and the Xamarin bindings. There is no separate MAUI package.

| Item | `RadarIO.Xamarin` 3.9.3 |
| --- | --- |
| .NET MAUI targets | `net8.0-android21.0` and `net8.0-ios14.2`. |
| Xamarin targets | `MonoAndroid12.0` and `Xamarin.iOS`. |
| Shared code target | `netstandard2.0` (interfaces and models only). |
| iOS SDK | Radar iOS SDK 3.9.6, bound in the package. |
| Android SDK | Radar Android SDK 3.9.8, bound in the package. |

The package pairs with the 3.9 native SDKs. Methods and options added to the native SDKs after those versions aren't available through it.

| Feature | Available | Notes |
| --- | --- | --- |
| Foreground and background tracking | Yes | Presets, custom options, mock tracking, events. |
| Trips | Yes | `StartTrip()`, `UpdateTrip()`, `CompleteTrip()`, `CancelTrip()`. No multi-leg methods. |
| Verified location (Geo-compliance and Fraud) | Partial | `TrackVerified()`, `TrackVerifiedToken()`, and `StartTrackingVerified()` from the 3.9 SDKs are exposed. See [Verified location](#verified-location). |
| Beacons | Yes | `beacons` argument on `TrackOnce()` and `TrackVerified()`, and `Beacons` in tracking options. |
| Maps and address UI | No | The package has no map or autocomplete control. |
| In-app messages | No | Not exposed in 3.9.3. |

The package doesn't expose user tags or product, and it doesn't request permissions. Use the .NET MAUI permissions API, as described in [Request permissions](#request-permissions). For how the wrappers compare, see [SDK overview and compatibility](/sdk/sdk).

### Migrate from older versions

- **3.7.8**: The `RadarIO.Xamarin` namespace became `RadarIO`, and `Xamarin.Essentials.Location` was replaced by `RadarIO.RadarLocation`. The NuGet package ID didn't change.
- **3.5.3**: You must call `RadarSingleton.Initialize(new RadarSDKImpl())` before you use `Radar`, and foreground service settings moved from tracking options to `Radar.SetForegroundServiceOptions()`.

For details, see [MIGRATION.md](https://github.com/radarlabs/radar-sdk-xamarin/blob/master/MIGRATION.md).

## Install

Install the package from [NuGet](https://www.nuget.org/packages/RadarIO.Xamarin/):

```powershell
Install-Package RadarIO.Xamarin
```

Or with the .NET CLI:

```bash
dotnet add package RadarIO.Xamarin
```

In a Xamarin solution with separate iOS and Android projects, add the package to each project.

### iOS

Add location usage descriptions to `Platforms/iOS/Info.plist`. These strings appear in the permission prompts.

| Key | When it is required |
| --- | --- |
| `NSLocationWhenInUseUsageDescription` | Always. Needed for foreground permission. |
| `NSLocationAlwaysAndWhenInUseUsageDescription` | When you request background permission. |

For background tracking with the responsive or continuous preset, add `location` and `fetch` to `UIBackgroundModes` in `Info.plist`:

```xml
<key>UIBackgroundModes</key>
<array>
  <string>fetch</string>
  <string>location</string>
</array>
```

### Android

Declare the permissions for the features you use in `Platforms/Android/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
```

`ACCESS_BACKGROUND_LOCATION` is needed only for background tracking without a foreground service, when you target API level 29 or later. `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_LOCATION` are needed only when you track with a foreground service.

The package brings in Google Play Services Location as a NuGet dependency.

## Integrate

### Initialize

`RadarSDKImpl` is the platform implementation. It exists only in the iOS and Android targets, so construct it from platform code or from a MAUI app project, not from a `netstandard2.0` library. Register it with `RadarSingleton` once, then initialize with your publishable key:

```csharp
using RadarIO;
using static RadarIO.RadarSingleton;

namespace MyProject
{ 
  public class Example 
  { 
    void Example () 
    {
      RadarSingleton.Initialize(new RadarSDKImpl());
      Radar.Initialize("prj_test_pk_..."); 
    } 
  }
}
```

Use your test publishable key (`prj_test_pk_...`) in development and your live publishable key (`prj_live_pk_...`) in production.

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

`RadarSingleton.Initialize()` throws if you call it twice. `Radar` throws if you use it before `RadarSingleton.Initialize()`.

The full signature is `Radar.Initialize(string publishableKey, bool fraud = false)`. Pass `true` for `fraud` when you use verified location. The package passes the value to the native SDK on Android. On iOS, the argument has no effect.

The examples on the rest of this page assume `using RadarIO;` and `using static RadarIO.RadarSingleton;`.

### Identify user

Identify the user with an ID, metadata, and a description:

```csharp
Radar.UserId = "user-123";
Radar.Metadata = new JSONObject
{
  { "tier", "gold" },
  { "orders", 12 },
  { "optedIn", true }
};
Radar.Description = "Example user";
```

| Property | Value |
| --- | --- |
| `Radar.UserId` | A stable unique ID for the user. |
| `Radar.Metadata` | A `JSONObject` (a `Dictionary<string, object>`) with string, number, or boolean values. Radar accepts up to 16 keys. |
| `Radar.Description` | A string shown in the Radar dashboard. |

These values persist across app sessions, so set each one once, for example after login.

`Radar.AnonymousTrackingEnabled` is a write-only property that turns anonymous tracking on or off. `Radar.SdkVersion` returns the SDK version string.

### Debug logging

By default, only critical errors are logged to the console. To change the level, call:

```csharp
Radar.SetLogLevel(RadarLogLevel.Debug);
```

Levels are `None`, `Error`, `Warning`, `Info`, and `Debug`. To receive log lines in your app, subscribe to `Radar.Log`.

### Request permissions

The user must grant location permission before you track. The package doesn't request permissions or report permission status. Use the [.NET MAUI permissions API](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/appmodel/permissions):

```csharp
var foreground = await Permissions.RequestAsync<Permissions.LocationWhenInUse>();
if (foreground == PermissionStatus.Granted)
{
  var background = await Permissions.RequestAsync<Permissions.LocationAlways>();
}
```

To verify, build and run the app on a device and confirm the prompts appear. For when to ask for each level, see [Understand foreground and background location permissions](/fundamentals/location-permissions).

### Foreground tracking

After you initialize the SDK and the user grants permission, track the user's location once:

```csharp
var (status, location, events, user) = await Radar.TrackOnce();
if (status == RadarStatus.Success)
{
  // use location, events, user
}
```

`TrackOnce()` has three overloads:

| Overload | Description |
| --- | --- |
| `TrackOnce()` | Tracks the device location with default settings. |
| `TrackOnce(RadarTrackingOptionsDesiredAccuracy desiredAccuracy, bool beacons)` | Sets accuracy and whether to range beacons. |
| `TrackOnce(RadarLocation location)` | Sends a location you already have. See [Manual tracking](#manual-tracking). |

Async methods return a result you can deconstruct. The first element is always a `RadarStatus`:

- **`Success`**: success
- **`ErrorPublishableKey`**: SDK not initialized
- **`ErrorPermissions`**: location permissions not granted
- **`ErrorLocation`**: location services error or timeout
- **`ErrorBluetooth`**: beacon ranging error or timeout
- **`ErrorNetwork`**: network error or timeout
- **`ErrorBadRequest`**: bad request (missing or invalid params)
- **`ErrorUnauthorized`**: unauthorized (invalid API key)
- **`ErrorPaymentRequired`**: payment required (organization disabled or usage exceeded)
- **`ErrorForbidden`**: forbidden (insufficient permissions or no beta access)
- **`ErrorNotFound`**: not found
- **`ErrorRateLimit`**: too many requests (rate limit exceeded)
- **`ErrorServer`**: internal server error
- **`ErrorUnknown`**: unknown error

`Radar.GetLocation()` reads the device location without sending it to Radar. It returns `(status, location, stopped)` and has an overload that takes a desired accuracy.

### Background tracking

After you initialize the SDK and the user grants permission, start tracking in the background. The SDK supports custom tracking options and three presets:

- **`TrackingOptionsEfficient`**: A low frequency of location updates and the lowest battery usage. On Android, avoids Android vitals bad behavior thresholds.
- **`TrackingOptionsResponsive`**: A medium frequency of location updates and low battery usage. Suitable for most consumer use cases.
- **`TrackingOptionsContinuous`**: A high frequency of location updates and higher battery usage. Suitable for on-demand use cases such as delivery tracking.

Start tracking with one of the presets:

```csharp
Radar.StartTracking(Radar.TrackingOptionsEfficient);

Radar.StartTracking(Radar.TrackingOptionsResponsive);

Radar.StartTracking(Radar.TrackingOptionsContinuous);
```

Call one of these once. Tracking options persist across app sessions.

Presets cover most use cases. To customize, start from a preset and change the fields you need. For field meanings, units, and defaults, see the [tracking options reference](/sdk/tracking). This package pairs with the 3.9 SDKs, so options added later aren't available.

```csharp
RadarTrackingOptions trackingOptions = Radar.TrackingOptionsContinuous;
trackingOptions.DesiredStoppedUpdateInterval = 180;
trackingOptions.DesiredMovingUpdateInterval = 60;
trackingOptions.DesiredSyncInterval = 50;
trackingOptions.DesiredAccuracy = RadarTrackingOptionsDesiredAccuracy.High;
trackingOptions.StopDuration = 140;
trackingOptions.StopDistance = 70;
trackingOptions.Sync = RadarTrackingOptionsSync.All;
trackingOptions.Replay = RadarTrackingOptionsReplay.None;

Radar.StartTracking(trackingOptions);
```

On Android, to track with a foreground service, set `trackingOptions.ForegroundServiceEnabled = true` and configure the notification before you start tracking:

```csharp
Radar.SetForegroundServiceOptions(new RadarTrackingOptionsForegroundService
{
  Title = "Location updates",
  Text = "Location tracking started",
  UpdatesOnly = false,
  Importance = 2,
  Activity = "com.example.app.MainActivity"
});
```

`SetForegroundServiceOptions()` does nothing on iOS.

To check and stop tracking:

```csharp
bool tracking = Radar.IsTracking;

Radar.StopTracking();
```

`Radar.TrackingOptions` returns the options in use. `Radar.IsUsingRemoteTrackingOptions` is `true` when [remote configuration](/sdk/remote-configuration) controls them.

#### Listen for events

Subscribe to events on `Radar`:

```csharp
Radar.ClientLocationUpdated += (result) =>
{ 
  // result.Location, result.Stopped, result.Source
};

Radar.LocationUpdated += (result) =>
{ 
  // result.Location, result.User
};

Radar.EventsReceived += (result) =>
{ 
  // result.Events, result.User
};

Radar.Error += (status) => 
{ 
  // status is a RadarStatus
};
```

| Event | Handler argument |
| --- | --- |
| `ClientLocationUpdated` | `ClientLocationUpdatedData` with `Location`, `Stopped`, `Source` |
| `LocationUpdated` | `LocationUpdatedData` with `Location`, `User` |
| `EventsReceived` | `EventsData` with `Events`, `User` |
| `Error` | `RadarStatus` |
| `Log` | `string` |
| `TokenUpdated` | `string`. See [Verified location](#verified-location). |

Subscribe once, before tracking begins.

### Mock tracking

To simulate a sequence of location updates for testing, call `MockTracking()`. This example simulates 10 updates, 3 seconds apart, by car:

```csharp
RadarLocation origin = new() { Latitude = 40.714708, Longitude = -74.035807 };
RadarLocation destination = new() { Latitude = 40.717410, Longitude = -74.053334 };

Radar.MockTracking(origin, destination, RadarRouteMode.Car, 10, 3, data =>
{ 
  System.Console.WriteLine($"Mock update status: {data.Status}");
});
```

### Trip tracking

Start a trip to a destination geofence. To apply tracking options while the trip is active, pass them as the second argument.

```csharp
RadarTripOptions tripOptions = new()
{ 
  ExternalId = "order-299",
  DestinationGeofenceTag = "store", 
  DestinationGeofenceExternalId = "store-42", 
  Mode = RadarRouteMode.Car
};

var (status, trip, events) = await Radar.StartTrip(tripOptions, Radar.TrackingOptionsContinuous);
```

`RadarTripOptions` also has `Metadata`, `ScheduledArrivalAt`, and `ApproachingThreshold`.

You can also call `Radar.StartTrip(tripOptions)` with one argument and start tracking yourself with `Radar.StartTracking()`.

Update the trip. The second argument defaults to `RadarTripStatus.Unknown`, which keeps the current status.

```csharp
await Radar.UpdateTrip(tripOptions, RadarTripStatus.Arrived);
```

Complete or cancel the trip:

```csharp
await Radar.CompleteTrip();

await Radar.CancelTrip();
```

If you started tracking yourself, call `Radar.StopTracking()` when the trip ends.

`Radar.TripOptions` returns the current trip options.

For the full workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

### Manual tracking

To send a location you already have, pass a `RadarLocation`:

```csharp
RadarLocation loc = new() { Latitude = 40.714708, Longitude = -74.035807, Accuracy = 65 };

var (status, location, events, user) = await Radar.TrackOnce(loc);
```

### Verified location

The package exposes the verified location methods of the 3.9 native SDKs. Pass `true` for `fraud` in `Radar.Initialize()` first. The argument takes effect on Android only.

| Method | Description |
| --- | --- |
| `TrackVerified(bool beacons = false)` | Runs a verified location check. Returns `(status, location, events, user)`. |
| `TrackVerifiedToken(bool beacons = false)` | Runs a verified location check and returns a token. Returns `(status, token)`. |
| `StartTrackingVerified(bool token = false, int interval = 1, bool beacons = false)` | Starts periodic verified checks. |
| `TokenUpdated` event | Fires when a new token is available. |

Run a verified location check and send the token to your backend:

```csharp
Radar.Initialize("prj_test_pk_...", true);

var (status, token) = await Radar.TrackVerifiedToken();
if (status == RadarStatus.Success)
{
  // Send the token to your backend and validate it there.
}
```

Reading the result in the app isn't validation. Send the token to your backend and validate it there. See [Geolocation token schema](/api/geolocation-tokens).

These methods predate the current fraud plugin and token APIs on the native SDKs. Before you build a Geo-compliance or Fraud integration on .NET MAUI, read [Fraud plugin setup](/sdk/fraud) and confirm support for your use case with your Radar account team.

### Beacons

To range beacons on a single call, use `Radar.TrackOnce(desiredAccuracy, true)` or `Radar.TrackVerified(true)`. To range during background tracking, set `Beacons = true` in your tracking options.

Beacon ranging needs Bluetooth permission and native setup. See [Track indoor location with beacons](/geofencing/beacons).

### Other APIs

The package also exposes context, geocoding, search, routing, and conversion APIs.

#### Context

Get context for the device location:

```csharp
var (status, location, context) = await Radar.GetContext();
```

Pass a `RadarLocation` to use a location you already have. `context` has `Geofences`, `Place`, `Country`, `State`, `Dma`, and `PostalCode`.

#### Geocoding

Forward geocode an address with the [geocoding API](/api/geocoding):

```csharp
var (status, addresses) = await Radar.Geocode("20 jay st brooklyn ny");
```

Reverse geocode a location. Call `ReverseGeocode()` with no argument to use the device location.

```csharp
RadarLocation loc = new() { Latitude = 40.714708, Longitude = -74.035807 };

var (status, addresses) = await Radar.ReverseGeocode(loc);
```

Geocode the device's IP address to a city, state, and country:

```csharp
var (status, address, proxy) = await Radar.IpGeocode();
```

#### Search

Autocomplete partial addresses and place names with the [search API](/api/search):

```csharp
RadarLocation near = new() { Latitude = 40.714708, Longitude = -74.035807 };

var (status, addresses) = await Radar.Autocomplete("brooklyn roasting", near, 10);
```

A second overload also takes `layers`, `country`, `expandUnits`, and `mailable`.

Search for geofences near a location, sorted by distance. The radius is in meters. Omit `near` to search near the device location.

```csharp
RadarLocation near = new() { Latitude = 40.714708, Longitude = -74.035807 };

var (status, location, geofences) = await Radar.SearchGeofences(near, 1000, new string[] { "venue" }, limit: 10);
```

Search for places near a location, sorted by distance. The arguments after the radius are `chains`, `categories`, `groups`, `limit`, and `chainMetadata`.

```csharp
RadarLocation near = new() { Latitude = 40.714708, Longitude = -74.035807 };

var (status, location, places) = await Radar.SearchPlaces(near, 1000, new string[] { "starbucks" }, null, null, 10);
```

#### Distance

Calculate travel distance and duration from an origin to a destination with the [routing API](/api/routing). Omit the origin to use the device location.

```csharp
RadarLocation origin = new() { Latitude = 40.78382, Longitude = -73.97536 };
RadarLocation destination = new() { Latitude = 40.70390, Longitude = -73.98670 };

var (status, routes) = await Radar.GetDistance(origin, destination, new[] { RadarRouteMode.Foot, RadarRouteMode.Car }, RadarRouteUnits.Imperial);
```

#### Matrix

Calculate travel distances and durations between multiple origins and destinations, for up to 25 routes. `GetMatrix()` takes a single mode.

```csharp
RadarLocation[] origins =
{
  new() { Latitude = 40.78382, Longitude = -73.97536 },
  new() { Latitude = 40.70390, Longitude = -73.98670 }
};
RadarLocation[] destinations =
{
  new() { Latitude = 40.64189, Longitude = -73.78779 },
  new() { Latitude = 35.99801, Longitude = -78.94294 }
};

var (status, matrix) = await Radar.GetMatrix(origins, destinations, RadarRouteMode.Car, RadarRouteUnits.Imperial);
RadarRoute route = matrix.RouteBetween(0, 0);
```

#### Conversions

Log a conversion, such as a purchase or signup, to analyze alongside location activity:

```csharp
var metadata = new JSONObject { { "sku", "example-sku" } };

var (status, conversionEvent) = await Radar.LogConversion("purchase", metadata);

// With revenue
var (revenueStatus, revenueEvent) = await Radar.LogConversion("purchase", 12.5, metadata);
```

`Radar.AcceptEventId(eventId, verifiedPlaceId)` and `Radar.RejectEventId(eventId)` send feedback on an event.

### Notification options

On Android, `SetNotificationOptions()` sets the icon and color of the foreground service notification and event notifications. Values are resource names in your Android project.

```csharp
Radar.SetNotificationOptions(new RadarNotificationOptions
{
  IconString = "icon_1",
  IconColor = "color_1"
});
```

To set them separately, use `ForegroundServiceIconString`, `ForegroundServiceIconColor`, `EventIconString`, and `EventIconColor`. This method is Android only.
