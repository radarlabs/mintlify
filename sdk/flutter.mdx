At the end of this page you have `flutter_radar` installed, the native iOS and Android projects configured, and a reference for every method and listener the package exposes.

This page documents `flutter_radar` 3.12.4, the latest stable release. The source is on [GitHub](https://github.com/radarlabs/flutter-radar) and the package is on [pub.dev](https://pub.dev/packages/flutter_radar).

## Versions and feature availability

| Item | `flutter_radar` 3.12.4 |
| --- | --- |
| Dart SDK | 2.12.0 or later, below 4.0.0. |
| Flutter | 1.20.0 or later. The plugin uses the v2 Android embedding. |
| iOS SDK | `RadarSDK` 3.19.5, declared by the plugin's podspec. Minimum iOS 10.0. |
| Android SDK | `io.radar:sdk:3.18.10`, declared by the plugin's Gradle file. |

| Feature | Available | Notes |
| --- | --- | --- |
| Foreground and background tracking | Yes | Presets, custom options, mock tracking, listeners. |
| Trips | Yes | `startTrip()`, `updateTrip()`, `completeTrip()`, `cancelTrip()`. No multi-leg methods. |
| Verified location (Geo-compliance and Fraud) | Partial | `trackVerified()`, `getVerifiedLocationToken()`, and `startTrackingVerified()` are exposed. See [Verified location](#verified-location). |
| Beacons | Yes | `beacons` option on `trackOnce()`, `trackVerified()`, `startTrackingVerified()`, and tracking options. |
| Maps and address UI | No | The package has no map or autocomplete widget. Use the geocoding and search methods with your own UI. |
| In-app messages | No | Not exposed in 3.12.4. |

The package doesn't expose user tags, product, or initialization options. For how the wrappers compare, see [SDK overview and compatibility](/sdk/sdk).

## Install

Add the package to your `pubspec.yaml` file:

```yaml
dependencies: 
  flutter_radar: ^3.12.4
```

Then, update dependencies:

```bash
flutter pub get
```

### iOS

1. In `ios/Podfile`, set `platform :ios, '10.0'` or later for your target, then run `pod install` from the `ios/` directory. The plugin's podspec brings in `RadarSDK`.

2. Add location usage descriptions to `ios/Runner/Info.plist`. These strings appear in the permission prompts.

   | Key | When it is required |
   | --- | --- |
   | `NSLocationWhenInUseUsageDescription` | Always. Needed for foreground permission. |
   | `NSLocationAlwaysAndWhenInUseUsageDescription` | When you request background permission. |
   | `NSMotionUsageDescription` | When you use motion activity detection. |

3. For background tracking with the responsive or continuous preset, open the Runner target in Xcode, select **Signing & Capabilities**, add **Background Modes**, and select **Location updates** and **Background fetch**. Your `Info.plist` then lists `location` and `fetch` under `UIBackgroundModes`.

4. Initialize the SDK in `application:didFinishLaunchingWithOptions:` with your publishable key. Native initialization keeps the SDK ready when iOS relaunches the app in the background, before your Dart code runs.

<CodeGroup>

```swift Swift
import UIKit
import Flutter

import RadarSDK

@main
@objc class AppDelegate: FlutterAppDelegate {
  override func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
    GeneratedPluginRegistrant.register(with: self)
    Radar.initialize(publishableKey: "prj_test_pk_...")
    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }
}
```

```objc Objective-C
#import "AppDelegate.h"
#import "GeneratedPluginRegistrant.h"

#import <RadarSDK/RadarSDK.h>

@implementation AppDelegate

- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
  [GeneratedPluginRegistrant registerWithRegistry:self];
  [Radar initializeWithPublishableKey:@"prj_test_pk_..."];
  return [super application:application didFinishLaunchingWithOptions:launchOptions];
}

@end
```

</CodeGroup>

### Android

1. Add the Radar Android SDK to the `dependencies` section of `android/app/build.gradle`. The plugin declares the SDK as an internal dependency, so your app module needs its own declaration to call `Radar` from native code. Keep the version in line with the one the plugin pins.

   ```gradle
   dependencies { 
     implementation 'io.radar:sdk:3.18.+'
   }
   ```

   When you upgrade `flutter_radar`, update this line to match the Android SDK version the new plugin release pins. Each release lists it on the [releases page](https://github.com/radarlabs/flutter-radar/releases).

2. Initialize the SDK in `onCreate()` of your `Application` class with your publishable key, and reference the class in your manifest with `android:name=".MainApplication"` on the `application` element.

<CodeGroup>

```kotlin Kotlin
import android.app.Application

import io.radar.sdk.Radar

class MainApplication : Application() {

  override fun onCreate() {
    super.onCreate()
    Radar.initialize(this, "prj_test_pk_...")
  }
}
```

```java Java
import android.app.Application;

import io.radar.sdk.Radar;

public class MainApplication extends Application {

  @Override
  public void onCreate() {
    super.onCreate();
    Radar.initialize(this, "prj_test_pk_...");
  }
}
```

</CodeGroup>

3. Add permissions to `android/app/src/main/AndroidManifest.xml` for the features you use. For background tracking without a foreground service, when you target API level 29 or later, add `ACCESS_BACKGROUND_LOCATION`:

   ```xml
   <manifest xmlns:android="http://schemas.android.com/apk/res/android">
     <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
   </manifest>
   ```

   Add `android.permission.ACTIVITY_RECOGNITION` if you use motion activity detection. For the full permission list, see the [Android SDK reference](/sdk/android).

## Integrate

### Import module

Import the package:

```dart
import 'package:flutter_radar/flutter_radar.dart';
```

All methods are static methods on the `Radar` class and return a `Future`.

### Initialize

Initialize the SDK with your publishable key when your app starts:

```dart
await Radar.initialize('prj_test_pk_...');
```

Use your test publishable key (`prj_test_pk_...`) in development and your live publishable key (`prj_live_pk_...`) in production.

<Warning>
  Use publishable keys in client code. Never put a secret key in an app or web page.
</Warning>

`Radar.initialize()` takes one argument, the publishable key. It also connects the listener channel, so call it before you register listeners.

### Identify user

Identify the user with an ID, metadata, and a description:

```dart
Radar.setUserId('user-123');
Radar.setMetadata({'tier': 'gold', 'orders': 12, 'optedIn': true});
Radar.setDescription('Example user');
```

| Method | Argument |
| --- | --- |
| `setUserId(userId)` | A stable unique ID for the user. |
| `setMetadata(metadata)` | A `Map<String, dynamic>` with string, number, or boolean values. Radar accepts up to 16 keys. |
| `setDescription(description)` | A string shown in the Radar dashboard. |

These values persist across app sessions, so call each setter once, for example after login. `getUserId()`, `getMetadata()`, and `getDescription()` return the stored values.

`Radar.setAnonymousTrackingEnabled(enabled)` turns anonymous tracking on or off.

### Debug logging

By default, only critical errors are logged to the console. To change the level, call:

```dart
Radar.setLogLevel('debug');
```

Valid levels are `'none'`, `'error'`, `'warning'`, `'info'`, and `'debug'`. To receive log lines in Dart, register `Radar.onLog()`.

`Radar.logBackgrounding()` and `Radar.logResigningActive()` record app lifecycle events. `Radar.logTermination()` does the same on iOS only.

### Request permissions

The user must grant location permission before you track. To read the current status, call:

```dart
String? status = await Radar.getPermissionsStatus();
```

`status` is one of:

- `GRANTED_FOREGROUND`
- `GRANTED_BACKGROUND`
- `DENIED`
- `NOT_DETERMINED`

To request permission, call:

```dart
await Radar.requestPermissions(false); // foreground
await Radar.requestPermissions(true);  // background
```

The argument is a boolean: `true` requests background permission and `false` requests foreground permission. Request foreground permission first. On iOS, the background prompt appears only after the user grants foreground permission.

To verify, build and run the app on a device and confirm both prompts appear. For when to ask for each level, see [Understand foreground and background location permissions](/fundamentals/location-permissions).

### Foreground tracking

After you initialize the SDK and the user grants permission, track the user's location once:

```dart
var res = await Radar.trackOnce();
if (res?['status'] == 'SUCCESS') {
  // res['location'], res['events'], res['user']
}
```

`trackOnce()` takes optional named parameters:

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `location` | `Map<String, dynamic>` | No | Sends this location instead of reading the device location. See [Manual tracking](#manual-tracking). |
| `desiredAccuracy` | `String` | No | One of `'high'`, `'medium'`, or `'low'`. |
| `beacons` | `bool` | No | Ranges nearby beacons. |

Methods that call the Radar API resolve to a `Map` with a `status` key. Check it before you read other keys. `status` is `SUCCESS` or one of:

- **`ERROR_PUBLISHABLE_KEY`**: SDK not initialized
- **`ERROR_PERMISSIONS`**: location permissions not granted
- **`ERROR_LOCATION`**: location services error or timeout
- **`ERROR_BLUETOOTH`**: beacon ranging error or timeout
- **`ERROR_NETWORK`**: network error or timeout
- **`ERROR_BAD_REQUEST`**: bad request (missing or invalid params)
- **`ERROR_UNAUTHORIZED`**: unauthorized (invalid API key)
- **`ERROR_PAYMENT_REQUIRED`**: payment required (organization disabled or usage exceeded)
- **`ERROR_FORBIDDEN`**: forbidden (insufficient permissions or no beta access)
- **`ERROR_NOT_FOUND`**: not found
- **`ERROR_RATE_LIMIT`**: too many requests (rate limit exceeded)
- **`ERROR_SERVER`**: internal server error
- **`ERROR_UNKNOWN`**: unknown error

If the platform call itself throws, these methods catch the `PlatformException` and resolve to a map with an `error` key instead.

`Radar.getLocation([accuracy])` reads the device location without sending it to Radar. It resolves to a map with `status`, `location`, and `stopped`.

### Background tracking

After you initialize the SDK and the user grants permission, start tracking in the background. The SDK supports custom tracking options and three presets:

- **`EFFICIENT`**: A low frequency of location updates and the lowest battery usage. On Android, avoids Android vitals bad behavior thresholds.
- **`RESPONSIVE`**: A medium frequency of location updates and low battery usage. Suitable for most consumer use cases.
- **`CONTINUOUS`**: A high frequency of location updates and higher battery usage. Suitable for on-demand use cases such as delivery tracking.

Start tracking with one of the presets:

```dart
Radar.startTracking('efficient');

Radar.startTracking('responsive');

Radar.startTracking('continuous');
```

Call one of these once. Tracking options persist across app sessions. An unrecognized preset name starts tracking with the responsive preset.

Presets cover most use cases. To customize, pass a full options map to `startTrackingCustom()`. The `Radar` class has `presetEfficient`, `presetResponsive`, and `presetContinuous` maps, which resolve to the right values for the current platform, so you can start from a preset and change the fields you need. For field meanings, units, and defaults, see the [tracking options reference](/sdk/tracking).

```dart
// Android only: configure the foreground service notification
Radar.setForegroundServiceOptions({
  'text': 'Location tracking started',
  'title': 'Location updates',
  'importance': 2,
  'updatesOnly': false,
  'activity': 'com.example.app.MainActivity',
});

Radar.startTrackingCustom({
  ...Radar.presetContinuous,
  'desiredStoppedUpdateInterval': 180,
  'desiredMovingUpdateInterval': 60,
  'desiredSyncInterval': 50,
});
```

To check and stop tracking:

```dart
bool? tracking = await Radar.isTracking();
Radar.stopTracking();
```

`Radar.getTrackingOptions()` resolves to the options in use. `Radar.isUsingRemoteTrackingOptions()` resolves to `true` when [remote configuration](/sdk/remote-configuration) controls them.

#### Listen for events

Register a callback for each update you want. Each callback receives a `Map`:

```dart
void onClientLocation(Map res) {
  // res['location'], res['stopped'], res['source']
}

void onLocation(Map res) {
  // res['location'], res['user']
}

void onEvents(Map res) {
  // res['events'], res['user']
}

void onError(Map res) {
  // res['status']
}

Radar.onClientLocation(onClientLocation);
Radar.onLocation(onLocation);
Radar.onEvents(onEvents);
Radar.onError(onError);
```

| Listener | Remove with | Callback map keys |
| --- | --- | --- |
| `onClientLocation` | `offClientLocation()` | `location`, `stopped`, `source` |
| `onLocation` | `offLocation()` | `location`, `user` |
| `onEvents` | `offEvents()` | `events`, `user` |
| `onError` | `offError()` | `status` |
| `onLog` | `offLog()` | `message` |
| `onToken` | `offToken()` | `token` |

Register each listener once, after `Radar.initialize()` and before tracking begins. Registering a second callback for the same listener throws `RadarExistingCallbackException`, so call the matching `off` method first.

Callbacks are delivered to Dart over the plugin's method channel, so they fire while the Flutter engine is running. To act on events when your app isn't running, use the native delegate or receiver described in the [iOS SDK reference](/sdk/ios) and [Android SDK reference](/sdk/android), or send events to your backend with [webhooks](/integrations/webhooks).

### Mock tracking

To simulate a sequence of location updates for testing, call `mockTracking()`. This example simulates 10 updates, 3 seconds apart, by car:

```dart
Radar.mockTracking( 
  origin: {'latitude': 40.714708, 'longitude': -74.035807}, 
  destination: {'latitude': 40.717410, 'longitude': -74.053334}, 
  mode: 'car', 
  steps: 10, 
  interval: 3
);
```

`interval` is in seconds.

### Trip tracking

Start a trip to a destination geofence. `trackingOptions` is optional and applies while the trip is active.

```dart
var res = await Radar.startTrip(
  tripOptions: {
    'externalId': 'order-299',
    'destinationGeofenceTag': 'store',
    'destinationGeofenceExternalId': 'store-42',
    'mode': 'car',
  },
  trackingOptions: Radar.presetContinuous,
);
// res['status'], res['trip'], res['events']
```

Update the trip. Both named parameters are required.

```dart
var res = await Radar.updateTrip(
  options: {
    'externalId': 'order-299',
    'metadata': {'parkingSpot': '5'},
  },
  status: 'arrived',
);
```

`status` is one of `'started'`, `'approaching'`, `'arrived'`, `'completed'`, or `'canceled'`. Any other value leaves the status unchanged.

Complete or cancel the trip:

```dart
await Radar.completeTrip();
await Radar.cancelTrip();
```

If tracking was off before the trip started, it stops when the trip ends. Otherwise it reverts to the tracking options in use before the trip.

`Radar.getTripOptions()` resolves to the current trip options.

For the full workflow, see [Track pickups, deliveries, and workers](/geofencing/trips).

### Manual tracking

To send a location you already have, pass it as the named `location` parameter:

```dart
var res = await Radar.trackOnce(
  location: {
    'latitude': 39.2904,
    'longitude': -76.6122,
    'accuracy': 65,
  },
);
// res['status'], res['location'], res['events'], res['user']
```

### Verified location

The package exposes these verified location methods:

| Method | Description |
| --- | --- |
| `trackVerified({bool? beacons})` | Runs a verified location check. Resolves to a map with `status` and `token`. |
| `getVerifiedLocationToken()` | Resolves to a map with `status` and `token`. |
| `startTrackingVerified(int interval, bool beacons)` | Starts periodic verified checks. `interval` is in seconds. |
| `stopTrackingVerified()` | Stops periodic verified checks. |
| `onToken(callback)` | Fires when a new token is available. The callback map has a `token` key. |

Run a verified location check and send the token to your backend:

```dart
var res = await Radar.trackVerified();
if (res?['status'] == 'SUCCESS') {
  var token = res?['token'];
  // Send the token to your backend and validate it there.
}
```

Reading the result in the app isn't validation. Send the token to your backend and validate it there. See [Geolocation token schema](/api/geolocation-tokens).

`flutter_radar` 3.12.4 pairs with the 3.18 and 3.19 native SDKs. `Radar.initialize()` in Dart takes only the publishable key, and the package doesn't install or configure a fraud plugin. Before you build a Geo-compliance or Fraud integration on Flutter, read [Fraud plugin setup](/sdk/fraud) and confirm the native requirements for your SDK versions with your Radar account team.

### Beacons

To range beacons on a single call, pass `beacons: true` to `trackOnce()` or `trackVerified()`. To range during background tracking, set `'beacons': true` in your tracking options.

Beacon ranging needs Bluetooth permission and native setup. See [Track indoor location with beacons](/geofencing/beacons).

### Location metadata

The SDK can attach motion activity, speed, and heading to location updates. Turning it on is a native configuration step. See the [iOS SDK reference](/sdk/ios) and [Android SDK reference](/sdk/android).

### Other APIs

The package also exposes context, geocoding, search, routing, and conversion APIs. Each resolves to a map with a `status` key.

#### Context

Context is what Radar knows about a location: its geofences, place, regions, and beacons. See [Understand geofences, places, regions, beacons, and fraud context](/fundamentals/context-types).

`Radar.getContext(location)` takes a location map and resolves to a map with `status`, `location`, and `context`:

```dart
var res = await Radar.getContext({'latitude': 40.783826, 'longitude': -73.975363});
// res['status'], res['context']
```

#### Geocoding

Forward geocode an address with the [geocoding API](/api/geocoding):

```dart
var res = await Radar.geocode('20 jay st brooklyn ny');
// res['status'], res['addresses']
```

Reverse geocode a location. Both named parameters are optional. Omit `location` to use the device location.

```dart
var res = await Radar.reverseGeocode(
  location: {'latitude': 40.783826, 'longitude': -73.975363},
);
// res['status'], res['addresses']
```

Geocode the device's IP address to a city, state, and country:

```dart
var res = await Radar.ipGeocode();
// res['status'], res['address'], res['proxy']
```

`Radar.validateAddress(address)` validates a structured address map, such as one returned by `geocode()` or `autocomplete()`. It resolves to a map with `status`, `address`, and `verificationStatus`.

#### Search

Autocomplete partial addresses and place names with the [search API](/api/search). `country`, `layers`, and `mailable` are also accepted.

```dart
var res = await Radar.autocomplete( 
  query: 'brooklyn roasting', 
  near: {'latitude': 40.783826, 'longitude': -73.975363}, 
  limit: 10
);
// res['status'], res['addresses']
```

Search for geofences near a location, sorted by distance. `metadata` and `includeGeometry` are also accepted. `radius` is in meters.

```dart
var res = await Radar.searchGeofences( 
  near: {'latitude': 40.783826, 'longitude': -73.975363}, 
  radius: 1000, 
  tags: ['venue'], 
  limit: 10
);
// res['status'], res['geofences']
```

Search for places near a location, sorted by distance. `chainMetadata`, `categories`, and `groups` are also accepted.

```dart
var res = await Radar.searchPlaces( 
  near: {'latitude': 40.783826, 'longitude': -73.975363}, 
  radius: 1000, 
  chains: ['starbucks'],
  limit: 10
);
// res['status'], res['places']
```

#### Distance

Calculate travel distance and duration from an origin to a destination with the [routing API](/api/routing):

```dart
var res = await Radar.getDistance( 
  origin: {'latitude': 40.78382, 'longitude': -73.97536}, 
  destination: {'latitude': 40.70390, 'longitude': -73.98670}, 
  modes: ['foot', 'car'], 
  units: 'imperial'
);
// res['status'], res['routes']
```

#### Matrix

Calculate travel distance and duration between multiple origins and destinations. All four named parameters are required.

```dart
var res = await Radar.getMatrix(
  origins: [
    {'latitude': 40.78382, 'longitude': -73.97536},
    {'latitude': 40.70390, 'longitude': -73.98670},
  ],
  destinations: [
    {'latitude': 40.64189, 'longitude': -73.78779},
    {'latitude': 35.99801, 'longitude': -78.94294},
  ],
  mode: 'car',
  units: 'imperial',
);
// res['status'], res['matrix']
```

#### Conversions

Log a conversion, such as a purchase or signup, to analyze alongside location activity. `name` and `metadata` are required. `revenue` is optional.

```dart
var res = await Radar.logConversion(
  name: 'purchase',
  revenue: 12.5,
  metadata: {'sku': 'example-sku'},
);
// res['status'], res['event']
```

### Notification options

On Android, `setNotificationOptions()` sets the icon and color of the foreground service notification and event notifications. Values are resource names in your Android project.

```dart
Radar.setNotificationOptions({
  'iconString': 'icon_1',
  'iconColor': 'color_1',
});
```

To set them separately, use `foregroundServiceIconString`, `foregroundServiceIconColor`, `eventIconString`, and `eventIconColor`. This method is Android only.
