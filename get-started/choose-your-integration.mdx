description: "Match the outcome you need to a Radar SDK or API path, the permissions it requires, the result you get back, and the guide that implements it."
---

Pick one implementation guide before you write code. Radar returns three kinds of result, from different calls:

- **Location tracking**: `Radar.trackOnce()`, `Radar.startTracking()`, or `Radar.startTrip()` returns the user's geofences, place, and trip, plus events. It needs location permission. It is built for experiences, and isn't evidence for an access decision.
- **Verified location**: `Radar.trackVerified()` returns a signed geolocation token with `passed` and failure reasons. It needs the fraud plugin and foreground location permission.
- **Device and network risk**: `Radar.revealRisk()` returns `risk.level`, `risk.reasons`, and a signed token. It needs the fraud plugin and doesn't request location.

A backend can't manufacture a verified client-location result: the check runs on the user's device, Radar signs the result, and your backend validates the token. Setting up a project and its API keys in the Radar dashboard is also different from identifying an end user, which your app does with `Radar.setUserId()`. See [Set up organizations, projects, accounts, and authentication](/fundamentals/authentication-and-access).
