Until you identify a user, Radar identifies the device by the IDs the SDK collects on its own: `installId`, generated on a fresh install, and `deviceId`. Call `Radar.setUserId()` with your own stable ID as soon as you know who the user is, and before the first tracking or verification call that you want attributed to them.

<Warning>
  Use an opaque internal ID such as `user-123`. Never send a name, email address, phone number, or any publicly known identifier as the `userId`.
</Warning>

Call `Radar.initialize()` first, then set the user ID:

<CodeGroup>

```swift Swift
import RadarSDK

Radar.setUserId("user-123")
```

```kotlin Kotlin
import io.radar.sdk.Radar

Radar.setUserId("user-123")
```

```javascript JavaScript
import Radar from 'radar-sdk-js';

Radar.setUserId('user-123');
```

```javascript React Native
import Radar from 'react-native-radar';

Radar.setUserId('user-123');
```

```dart Flutter
import 'package:flutter_radar/flutter_radar.dart';

await Radar.setUserId('user-123');
```

</CodeGroup>

The SDK stores the `userId` on the device and keeps using it across app sessions, so you don't need to set it on every launch. The `userId` appears as **External ID** in the dashboard.

### Handle login, logout, and user switching

Call `Radar.setUserId()` with the new ID whenever a user logs in. Radar keeps a separate user record for each combination of `installId`, `deviceId`, and `userId`, so a different user who logs in on the same device gets their own record.

`userId` is nullable. When the user logs out, you can clear it by passing `nil` in Swift or `null` in Kotlin, or by calling `Radar.setUserId()` with no argument in JavaScript.

To confirm the result, open the [Users](https://dashboard.radar.com/geofencing/users) page in the dashboard and check that the **External ID** on the most recent record is the one you expect.
