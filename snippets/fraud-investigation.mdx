An investigation starts from one user, device, or check and ends with a recorded outcome. Work through these steps in the Radar dashboard. For definitions of scores, rules, actions, and labels, see [Understand risk scores and decisions](/fraud/overview#understand-risk-scores-and-decisions).

Your dashboard account needs access to Fraud data in the environment you are investigating, and write access to block users, close cases, or create rules. If a control described here isn't shown, ask a project admin.

### Find the user or device

1. Open the [Users](https://dashboard.radar.com/geofencing/users) page and look up the user by the ID your app sets with `Radar.setUserId()`. To start from a device instead, open the **Devices** page and look up the device ID.
2. To find candidates instead of a known ID, filter the list. Useful filters are risk score, blocked or bypassed status, first seen and last seen dates, and the minimum number of devices for a user or users for a device.
3. Open the row. The detail page shows when the user or device was first and last seen, its risk score and the reasons behind it, and whether a block or bypass rule applies.

### Inspect related users and devices

On the user or device detail page, switch from the map view to the network view. The network view draws the user, every device the user was seen on, and every other user seen on those devices.

Read the graph as context:

- One user on two or three devices is common. People replace phones and use both a phone and a computer.
- Two or three users on one device is common for households and shared work devices.
- A device that links many otherwise unrelated users, or a user that keeps appearing on new devices, is worth a closer look. It is still not proof by itself.

Open any linked user or device to see its own risk score and history.

### Review location history

On the user or device detail page, click **History**. The history view lists the location checks for that user across devices and plots them on the map. Set the date range to the period you are investigating.

Look for:

- Checks from two devices in places too far apart for the time between them.
- A change of country or state that doesn't match what you know about the user.
- Many checks from exactly the same coordinates, or from a place where many unrelated accounts also check.

### Examine the specific check

Open the check from the history view, or find it on the [Locations](https://dashboard.radar.com/geofencing/locations) page by user ID, device ID, or check reason. The check detail page shows the result for that one check: whether it passed, its failure reasons, the fraud flags, the IP address and network details, and the device details. For how to read each section, see [Inspect a check](/fraud/overview#inspect-a-check).

Compare the check with the history. A flag on one check is an observation about that moment. The same flag across many checks, devices, or linked users is a pattern.

### Record an outcome

Record what you concluded, including when the conclusion is that nothing is wrong. Recorded outcomes are how Radar and your own team learn which signals were right.

| Outcome | How to record it |
| --- | --- |
| The activity is fraudulent | If a case is open, open it on the **Cases** page and click **Close as fraud**. Closing a case as fraud records a `fraud` label for each user on the case. To stop further activity, block the user or device from its detail page or on the **Block rules** page. |
| The activity is legitimate | Click **Close as not fraud** on the case. This records a `not_fraud` label for each user on the case. Remove any block rule that was created for the user or device. |
| You need a second opinion | Assign the case to a teammate, add a comment with what you found, or click **Request review**. |
| The outcome was decided outside Radar | Send it from your backend with the [Labels API](/api/labels), for example after a chargeback or a support review. |

If a user or device triggers the same rule again after its case is closed, Radar reopens the case with its earlier comments.

### Configure a rule for the pattern

When an investigation shows a pattern you want to catch again, turn it into a fraud rule.

1. Open the **Fraud rules** page and click **Create**.
2. Enter a name and leave the status as **Enabled**.
3. Under **Criteria**, select a field, an operator, and a value. Click **Add condition** for more, and select whether conditions combine with **and** or **or**.
4. Under **Actions**, select **Open case**. Add **Block associated users** or **Block associated devices** only after the rule has run long enough for you to trust what it matches.
5. Save the rule, then check the **Cases** page over the following days to see what it opens.

Start every new rule with **Open case** alone. Review the cases it opens, close the false matches as not fraud, tighten the criteria, and add a blocking action only when the matches are consistently correct. For the available criteria and actions, see [Configure rules and actions](/fraud/overview#configure-rules-and-actions).
