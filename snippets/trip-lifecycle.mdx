The native examples use iOS SDK 3.46.0 and Android SDK 4.3.0. The React Native examples use React Native SDK 4.39.0. Each one assumes the SDK is initialized, the user is identified, and foreground location permission is granted.

### Starting trips

Start a trip at the moment the journey begins, for example when a customer taps "I'm on my way" or a driver accepts a job. A trip needs:

| Option | Required | Description |
| --- | --- | --- |
| `externalId` | Yes | Your stable ID for the journey, such as an order ID. Use the same value everywhere you refer to this trip. |
| `destinationGeofenceTag` and `destinationGeofenceExternalId` | For single-destination trips | The `tag` and `externalId` of the destination geofence. The geofence must already exist in the same environment. |
| `mode` | No | Travel mode used for the ETA: `car` (default), `foot`, `bike`, `truck`, or `motorbike`. |
| `metadata` | No | Custom key-value pairs, returned on the trip in every trip event. |
| `scheduledArrivalAt` | No | The time the user is expected to arrive. Used by delay detection and by order-firing integrations. |
| `approachingThreshold` | No | Overrides the project's approaching threshold, in minutes, for this trip. |

Pass tracking options to `startTrip()` to control location updates for the length of the trip. The continuous preset sends an update about every 30 seconds.

<CodeGroup>

```swift Swift
import RadarSDK

let tripOptions = RadarTripOptions(
    externalId: "order-1001",
    destinationGeofenceTag: "store",
    destinationGeofenceExternalId: "store-42"
)
tripOptions.mode = .car
tripOptions.metadata = ["handoff": "curbside"]

Radar.startTrip(
    options: tripOptions,
    trackingOptions: RadarTrackingOptions.presetContinuous
) { status, trip, events in
    guard status == .success, let trip = trip else {
        // The trip did not start. Keep the order on its non-location path
        // and let the user retry.
        print("startTrip failed: \(Radar.stringForStatus(status))")
        return
    }
    print("Trip \(trip.externalId ?? "") is \(Radar.stringForTripStatus(trip.status))")
}
```

```kotlin Kotlin
import android.util.Log
import io.radar.sdk.Radar
import io.radar.sdk.RadarTrackingOptions
import io.radar.sdk.RadarTripOptions
import org.json.JSONObject

val tripOptions = RadarTripOptions(
    externalId = "order-1001",
    metadata = JSONObject().put("handoff", "curbside"),
    destinationGeofenceTag = "store",
    destinationGeofenceExternalId = "store-42",
    mode = Radar.RadarRouteMode.CAR
)

Radar.startTrip(tripOptions, RadarTrackingOptions.CONTINUOUS) { status, trip, events ->
    if (status != Radar.RadarStatus.SUCCESS || trip == null) {
        // The trip did not start. Keep the order on its non-location path
        // and let the user retry.
        Log.w("Trips", "startTrip failed: $status")
        return@startTrip
    }
    Log.d("Trips", "Trip ${trip.externalId} is ${Radar.stringForTripStatus(trip.status)}")
}
```

```javascript React Native
import Radar, { presetContinuous } from 'react-native-radar';

async function startPickupTrip() {
  try {
    const result = await Radar.startTrip({
      tripOptions: {
        externalId: 'order-1001',
        destinationGeofenceTag: 'store',
        destinationGeofenceExternalId: 'store-42',
        mode: 'car',
        metadata: { handoff: 'curbside' },
      },
      trackingOptions: presetContinuous,
    });
    console.log(`Trip is ${result.trip?.status}`);
  } catch (err) {
    // The trip did not start. Keep the order on its non-location path
    // and let the user retry.
    console.warn('startTrip failed', err);
  }
}
```

</CodeGroup>

What the SDK does when `startTrip()` succeeds:

- If you pass tracking options, the SDK starts tracking with them. If the SDK was already tracking, it remembers the earlier options so it can restore them when the trip ends.
- If you pass no tracking options, the SDK wasn't already tracking, and `startTracking` on the trip options is `true` (the default), the SDK starts tracking with your remote tracking options if they are set, or with the last options used on the device.
- The SDK sends one location update right away so that Radar can generate `user.started_trip`.

If the destination geofence doesn't exist in the environment that matches your publishable key, the call fails with a not-found status (`.errorNotFound` on iOS, `ERROR_NOT_FOUND` on Android) and no trip is created.

On iOS, the continuous preset shows the blue location indicator while the app is in the background and needs the **Location updates** and **Background fetch** background modes. On Android, it runs a foreground service with a notification, which your app must declare. With either one active, foreground ("While Using") permission is enough for the trip to keep updating in the background. For setup, see the [iOS SDK](/sdk/ios#background-tracking-for-trips) and [Android SDK](/sdk/android#background-tracking-for-trips) references.

### Updating trips

Update a trip when something about the journey changes: a parking space is assigned, the pickup time moves, or your app knows the user has arrived before Radar detects it. Read the stored options, change them, and send them back with the status the trip should have. The example adds a parking space and moves the trip to `arrived`.

<CodeGroup>

```swift Swift
guard let tripOptions = Radar.getTripOptions() else { return }

var metadata = tripOptions.metadata ?? [:]
metadata["parkingSpace"] = "4"
tripOptions.metadata = metadata

Radar.updateTrip(options: tripOptions, status: .arrived) { status, trip, events in
    if status != .success {
        print("updateTrip failed: \(Radar.stringForStatus(status))")
    }
}
```

```kotlin Kotlin
import io.radar.sdk.model.RadarTrip
import org.json.JSONObject

val tripOptions = Radar.getTripOptions() ?: return

val metadata = tripOptions.metadata ?: JSONObject()
metadata.put("parkingSpace", "4")
tripOptions.metadata = metadata

Radar.updateTrip(tripOptions, RadarTrip.RadarTripStatus.ARRIVED) { status, trip, events ->
    if (status != Radar.RadarStatus.SUCCESS) {
        Log.w("Trips", "updateTrip failed: $status")
    }
}
```

```javascript React Native
const tripOptions = await Radar.getTripOptions();

await Radar.updateTrip({
  options: {
    ...tripOptions,
    metadata: { ...tripOptions.metadata, parkingSpace: '4' },
  },
  status: 'arrived',
});
```

</CodeGroup>

Your backend can make the same change with the [Trips API](/api/trips), for example when a store associate marks an order as handed off.

### Stopping trips

End every trip explicitly. Complete it when the journey finishes as planned (the order is handed over, the delivery is dropped off). Cancel it when the journey is abandoned (the order is canceled, the job is reassigned).

<CodeGroup>

```swift Swift
// The journey finished.
Radar.completeTrip { status, trip, events in
    if status != .success && status != .errorNotFound {
        // The trip is still active on the server. Retry later.
    }
}

// The journey was abandoned.
Radar.cancelTrip { status, trip, events in
    if status != .success && status != .errorNotFound {
        // The trip is still active on the server. Retry later.
    }
}
```

```kotlin Kotlin
// The journey finished.
Radar.completeTrip { status, trip, events ->
    if (status != Radar.RadarStatus.SUCCESS && status != Radar.RadarStatus.ERROR_NOT_FOUND) {
        // The trip is still active on the server. Retry later.
    }
}

// The journey was abandoned.
Radar.cancelTrip { status, trip, events ->
    if (status != Radar.RadarStatus.SUCCESS && status != Radar.RadarStatus.ERROR_NOT_FOUND) {
        // The trip is still active on the server. Retry later.
    }
}
```

```javascript React Native
// The journey finished.
await Radar.completeTrip();

// The journey was abandoned.
await Radar.cancelTrip();
```

</CodeGroup>

When `completeTrip()` or `cancelTrip()` returns, the SDK changes tracking for you:

- If tracking was running before the trip started, the SDK restores those earlier options. A user who had background tracking for geofence events goes back to it.
- If tracking wasn't running before the trip, the SDK stops tracking.
- The stored trip is cleared only when Radar confirms the change or reports that the trip no longer exists. If the request fails for another reason, such as no network, the trip stays stored on the device so that you can call the method again, but tracking has already returned to its earlier state.

Don't call `Radar.stopTracking()` after a trip unless you want all tracking off, including background tracking that was running before the trip.

A trip can also end without your app: your backend ends it with the [Trips API](/api/trips), an integration cancels it, or it passes the project's expiration threshold. The SDK finds out on its next location update. When the response no longer contains a trip, the SDK clears the stored trip and restores or stops tracking in the same way.

### Recover on app open and resume

Trip state lives on Radar's servers. Tracking state lives on the device. They can drift apart: the user force-quits the app, the device restarts, the network drops while a trip is ending, or the trip ends on the server while the app isn't running. Reconcile them every time the app opens or returns to the foreground.

<CodeGroup>

```swift Swift
// Call from applicationDidBecomeActive or the scene equivalent.
func reconcileTrip() {
    Radar.trackOnce { status, location, events, user in
        guard status == .success else {
            // Unknown state. Show the last known order status and try again
            // on the next foreground.
            return
        }

        if let trip = user?.trip {
            // A trip is active on the server.
            if !Radar.isTracking() {
                Radar.startTracking(trackingOptions: RadarTrackingOptions.presetContinuous)
            }
            // Restore the trip UI from `trip`.
        } else {
            // No active trip. The SDK has already cleared its stored trip and
            // restored or stopped tracking. Remove any trip UI.
        }
    }
}
```

```kotlin Kotlin
// Call from onStart or a ProcessLifecycleOwner observer.
fun reconcileTrip() {
    Radar.trackOnce { status, location, events, user ->
        if (status != Radar.RadarStatus.SUCCESS) {
            // Unknown state. Show the last known order status and try again
            // on the next foreground.
            return@trackOnce
        }

        val trip = user?.trip
        if (trip != null) {
            // A trip is active on the server.
            if (!Radar.isTracking()) {
                Radar.startTracking(RadarTrackingOptions.CONTINUOUS)
            }
            // Restore the trip UI from `trip`.
        } else {
            // No active trip. The SDK has already cleared its stored trip and
            // restored or stopped tracking. Remove any trip UI.
        }
    }
}
```

```javascript React Native
// Call when AppState changes to 'active'.
async function reconcileTrip() {
  try {
    const { user } = await Radar.trackOnce();

    if (user?.trip) {
      // A trip is active on the server.
      if (!(await Radar.isTracking())) {
        Radar.startTrackingContinuous();
      }
      // Restore the trip UI from user.trip.
    } else {
      // No active trip. The SDK has already cleared its stored trip and
      // restored or stopped tracking. Remove any trip UI.
    }
  } catch (err) {
    // Unknown state. Show the last known order status and try again
    // on the next foreground.
  }
}
```

</CodeGroup>

Limits to design around:

- **Force-quit**: A force-quit app doesn't track and can't be restarted by this code. Recovery happens the next time the user opens the app. Plan a path that doesn't depend on location, such as a time-based fallback on your backend.
- **No network**: Trip calls fail with a network status and aren't queued. Retry `startTrip()`, `completeTrip()`, and `cancelTrip()` when connectivity returns, and treat your backend as the owner of the order state.
- **Repeated calls**: Starting a trip is a network request. Disable the button that starts it until the callback returns, and use one `externalId` per journey so that a retry refers to the same trip.
- **Stale UI**: Don't keep "trip in progress" in local storage as the only source. Use `user.trip` from the latest `trackOnce()`, or `Radar.getTrip()`, which returns the trip the SDK last saw.
