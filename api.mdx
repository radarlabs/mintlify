The Radar REST API lets you track locations, manage users, geofences, trips, and beacons, geocode and search, calculate routes, and act on fraud results from your own systems. Start here for the base URL and shared conventions, then go to the reference page for each resource.

If you followed a link to a section that used to be on this page, find it under [Moved sections](#moved-sections).

## Base URL and conventions

All endpoints are served over HTTPS from this base URL:

```text
https://api.radar.io/v1
```

- The API is RESTful, with predictable, resource-oriented URLs.
- All responses, including errors, are JSON, and include a `meta` object with a `code`.
- `POST`, `PUT`, and `PATCH` body parameters can be sent as `application/json` or `application/x-www-form-urlencoded`.
- Datetimes are ISO 8601 strings. GeoJSON coordinates are in `[longitude, latitude]` order.
- Each operation lists the key type it needs: a publishable key, which is safe to use in client code, or a secret key, which is for your backend only.

This request lists the users in a project with a secret key:

```bash
curl "https://api.radar.io/v1/users" \
  -H "Authorization: prj_live_sk_..."
```

Radar returns this response:

```json
{
  "meta": {
    "code": 200,
    "hasMore": false
  },
  "users": []
}
```

On iOS, Android, and the web, the [SDKs](/sdk/sdk) call many of these endpoints for you. Use the REST API directly for backend work and for platforms without an SDK. To decide which to use, see [Choose your integration](/get-started/choose-your-integration).

## Authentication

Send your API key in the `Authorization` header. Use publishable keys in client code and secret keys only on your backend. Test keys read and write test data, and live keys read and write live data.

For key types, prefixes, and environments, see [Authentication, errors, and rate limits](/api/fundamentals#authentication).

## Errors

The API uses standard HTTP response codes. Error responses carry the code, a message, and, for validation errors, the name of the invalid parameter in `meta`.

For the status code table, the error format, rate limits, retries, and pagination, see [Authentication, errors, and rate limits](/api/fundamentals#errors).

## Request IDs

Every API response includes an `X-Radar-Request-ID` header. Include it when you contact [Radar support](https://radar.com/support) about a specific call. See [Request IDs](/api/fundamentals#request-ids).

## Building blocks

Use these resources as building blocks for location-based products such as pickup and delivery tracking, store locators, address entry, and location verification.

| Resource | What it covers | Reference |
| --- | --- | --- |
| Tracking | Send a location update and get back the user and events. Get context for a coordinate. | [Tracking API](/api/tracking) |
| Geocoding | Forward, reverse, and IP geocoding. Address validation. | [Geocoding API](/api/geocoding) |
| Search | Autocomplete, geofence search, and place search. | [Search API](/api/search) |
| Routing | Distance, matrix, route match, directions, and route optimization. | [Routing API](/api/routing) |
| Maps | Map styles, tiles, and static maps. | [Maps API](/api/maps) |

## Manage your Radar data

Use these resources to manage the data in your project from your backend.

| Resource | What it covers | Reference |
| --- | --- | --- |
| Users | List, get, and delete users. Send remote track requests. | [Users API](/api/users) |
| Geofences | List, get, upsert, and delete geofences. List the users in a geofence. | [Geofences API](/api/geofences) |
| Events | The event object. Log conversions and verify events. | [Events API](/api/events) |
| Trips | Create, update, list, and delete trips. Trip routes and multi-leg trips. | [Trips API](/api/trips) |
| Beacons | List, get, create, upsert, and delete beacons. | [Beacons API](/api/beacons) |
| Fraud | The fraud object. Block and unblock users and devices. | [Fraud API](/api/fraud) |
| Labels | Record a confirmed fraud or not-fraud outcome for a user. | [Labels API](/api/labels) |
| Geolocation tokens | The payload of a verified location token and how to read it. | [Geolocation token schema](/api/geolocation-tokens) |
