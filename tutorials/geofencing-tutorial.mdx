This guide walks you through everything you need to add geofencing to your app with Radar — from installing the SDK to handling real-time entry and exit events. By the end, your app will detect when a user enters or exits any location you define.

## What you'll build

- Install and initialize the Radar SDK on your platform
- Request location permissions from the user
- Track a user's location once (foreground) or continuously (background)
- Listen for geofence entry and exit events in your app

## Prerequisites

- A Radar account
- Your **publishable API key** from the [Settings page](https://dashboard.radar.com/settings). Use your `Test Publishable` key during development. **Never use your secret key in client-side code.**
- At least one geofence created in the [Radar dashboard](https://dashboard.radar.com/geofencing/geofences). Geofences can be circles or polygons, grouped by `tag` (e.g. `store`, `venue`) and identified by `externalId`.

## Step 3: Request location permissions

Radar requires location permissions before it can track a user. The right permission level depends on your use case:

| Use case                                   | Required permission      |
| ------------------------------------------ | ------------------------ |
| One-time foreground tracking (`trackOnce`) | When In Use (foreground) |
| Continuous background geofencing           | Always (background)      |
| Trip tracking with continuous preset       | When In Use (foreground) |

<Tip>
  Ask for foreground permission first, then ask for background permission only after the user understands the value. Showing the background prompt without context is a common reason users deny it permanently.
</Tip>

<Tabs>
  <Tab title="iOS">
    First, add usage strings to your `Info.plist`:

    ```xml
    <key>NSLocationWhenInUseUsageDescription</key>
    <string>We use your location to show you nearby stores and deals.</string>
    
    <key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
    <string>We use your location in the background to notify you when you arrive at a store.</string>
    ```

    Then request permissions — foreground first, then escalate to background:

    ```swift
    import CoreLocation
    import RadarSDK
    
    class AppDelegate: UIResponder, UIApplicationDelegate, CLLocationManagerDelegate {
    
        let locationManager = CLLocationManager()
    
        func application(
            _ application: UIApplication,
            didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
        ) -> Bool {
            Radar.initialize(publishableKey: "prj_test_pk_...")
            locationManager.delegate = self
            requestLocationPermissions()
            return true
        }
    
        func locationManager(
            _ manager: CLLocationManager,
            didChangeAuthorization status: CLAuthorizationStatus
        ) {
            requestLocationPermissions()
        }
    
        func requestLocationPermissions() {
            let status = locationManager.authorizationStatus
            if status == .notDetermined {
                locationManager.requestWhenInUseAuthorization()
            } else if status == .authorizedWhenInUse {
                // Foreground granted — now escalate to background
                locationManager.requestAlwaysAuthorization()
            }
        }
    }
    ```

    <Note>
      If you plan to use `presetResponsive` or `presetContinuous`, go to **Signing & Capabilities → Background Modes** and enable **Location updates** and **Background fetch**.
    </Note>
  </Tab>
  <Tab title="Android">
    Add permissions to your `AndroidManifest.xml`. Foreground permissions are added automatically by the SDK, but you must manually add `ACCESS_BACKGROUND_LOCATION` and `FOREGROUND_SERVICE_LOCATION`:

    ```xml
    <manifest xmlns:android="http://schemas.android.com/apk/res/android">
        {/*  Added automatically by the SDK  */}
        <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
        <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
        <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
        <uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
    
        {/*  Add manually for background tracking  */}
        <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
    
        {/*  Add manually if using the continuous preset  */}
        <uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
    </manifest>
    ```

    Then request permissions at runtime. On Android 11+, background permission must be requested in a separate step from foreground:

    ```kotlin
    import android.Manifest
    import android.content.pm.PackageManager
    import android.os.Build
    import androidx.core.app.ActivityCompat
    import androidx.appcompat.app.AlertDialog
    import androidx.appcompat.app.AppCompatActivity
    
    class MainActivity : AppCompatActivity() {
        private val FOREGROUND_CODE = 1
        private val BACKGROUND_CODE = 2
    
        override fun onCreate(savedInstanceState: Bundle?) {
            super.onCreate(savedInstanceState)
            requestLocationPermissions()
        }
    
        private fun requestLocationPermissions() {
            if (ActivityCompat.checkSelfPermission(this,
                    Manifest.permission.ACCESS_FINE_LOCATION) != PackageManager.PERMISSION_GRANTED) {
                ActivityCompat.requestPermissions(this,
                    arrayOf(
                        Manifest.permission.ACCESS_FINE_LOCATION,
                        Manifest.permission.ACCESS_COARSE_LOCATION
                    ),
                    FOREGROUND_CODE)
            }
        }
    
        override fun onRequestPermissionsResult(
            requestCode: Int,
            permissions: Array<String>,
            grantResults: IntArray
        ) {
            super.onRequestPermissionsResult(requestCode, permissions, grantResults)
            if (requestCode == FOREGROUND_CODE &&
                grantResults.isNotEmpty() &&
                grantResults[0] == PackageManager.PERMISSION_GRANTED &&
                Build.VERSION.SDK_INT >= Build.VERSION_CODES.R) {
                AlertDialog.Builder(this)
                    .setTitle("Background location needed")
                    .setMessage("Tap \"Allow all the time\" on the next screen to enable geofencing.")
                    .setPositiveButton("OK") { _, _ ->
                        ActivityCompat.requestPermissions(this,
                            arrayOf(Manifest.permission.ACCESS_BACKGROUND_LOCATION),
                            BACKGROUND_CODE)
                    }
                    .show()
            }
        }
    }
    ```
  </Tab>

## Step 4: One-time tracking (foreground)

`trackOnce` gets the user's current location, sends it to Radar, and returns any geofence events that match. Use this when you want to check location in response to a user action — like opening the app, tapping a button, or loading a screen.

<Tabs>
  <Tab title="iOS">
    ```swift
    Radar.trackOnce { (status, location, events, user) in
        if status == .success {
            // Check if the user is currently inside any geofences
            if let geofences = user?.geofences, !geofences.isEmpty {
                print("User is in \(geofences.count) geofence(s)")
            }
            // Handle any entry/exit events
            events?.forEach { event in
                switch event.type {
                case .userEnteredGeofence:
                    print("Entered: \(event.geofence?.description ?? "")")
                case .userExitedGeofence:
                    print("Exited: \(event.geofence?.description ?? "")")
                default:
                    break
                }
            }
        } else {
            print("trackOnce failed: \(status)")
        }
    }
    ```
  </Tab>
  <Tab title="Android">
    ```kotlin
    Radar.trackOnce { status, location, events, user ->
        if (status == Radar.RadarStatus.SUCCESS) {
            user?.geofences?.let { geofences ->
                println("User is in ${geofences.size} geofence(s)")
            }
            events?.forEach { event ->
                when (event.type) {
                    RadarEvent.RadarEventType.USER_ENTERED_GEOFENCE ->
                        println("Entered: ${event.geofence?.description}")
                    RadarEvent.RadarEventType.USER_EXITED_GEOFENCE ->
                        println("Exited: ${event.geofence?.description}")
                    else -> {}
                }
            }
        } else {
            println("trackOnce failed: $status")
        }
    }
    ```
  </Tab>
  <Tab title="Web (JS)">

## Step 5: Continuous background tracking

For real-time geofencing, you want the SDK to track location continuously in the background — even when the app is closed. Radar will wake your app and deliver events when the user enters or exits a geofence.

### Choose a tracking preset

Radar provides three presets. For most geofencing use cases, **Responsive** is the right choice:

| Preset       | Update frequency                  | Battery usage | Best for                                  |
| ------------ | --------------------------------- | ------------- | ----------------------------------------- |
| `EFFICIENT`  | Low                               | Lowest        | Broad region detection, passive use cases |
| `RESPONSIVE` | ~2–3 min moving, off when stopped | Low           | **Geofencing (recommended)**              |
| `CONTINUOUS` | ~30 sec always                    | Higher        | Delivery tracking, trip tracking          |

<Note>
  **Android background limits:** On Android, location updates with the responsive preset may arrive every 5–10 minutes in practice due to Doze Mode and Background Location Limits. This applies to all apps using location services on Android, not just Radar. Use the `CONTINUOUS` preset with a foreground service if you need faster updates.
</Note>

<Tabs>
  <Tab title="iOS">
    ```swift
    // Start background tracking for geofencing
    Radar.startTracking(trackingOptions: RadarTrackingOptions.presetResponsive)
    
    // Check if tracking is currently active
    let isTracking = Radar.isTracking()
    
    // Stop tracking (e.g., when the user logs out)
    Radar.stopTracking()
    ```

    You only need to call `startTracking` once — the setting persists across app restarts.
  </Tab>
  <Tab title="Android">
    ```kotlin
    // Start background tracking for geofencing
    Radar.startTracking(RadarTrackingOptions.RESPONSIVE)
    
    // Check if tracking is currently active
    val isTracking = Radar.isTracking()
    
    // Stop tracking (e.g., when the user logs out)
    Radar.stopTracking()
    ```

  <Tab title="Web (JS)">
    <Info>

  </Tab>
  <Tab title="React Native">

## Step 6: Handle geofence events

When a user enters or exits a geofence, Radar generates an event. You can receive events two ways: **client-side** (in-app listeners) and **server-side** (webhooks).

### Client-side listeners

Use client-side listeners to update your UI, show a notification, or trigger an in-app action in real time.

<Tabs>
  <Tab title="iOS">
    Make your `AppDelegate` implement `RadarDelegate`. Set the delegate before calling `startTracking` so no events are missed when the app is backgrounded or killed.

    ```swift
    import UIKit
    import RadarSDK
    import UserNotifications
    
    @UIApplicationMain
    class AppDelegate: UIResponder, UIApplicationDelegate, RadarDelegate {
    
        let locationManager = CLLocationManager()
    
        func application(
            _ application: UIApplication,
            didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
        ) -> Bool {
            Radar.initialize(publishableKey: "prj_test_pk_...")
            Radar.setDelegate(self)              // set before startTracking
            Radar.setUserId("user-123")
            locationManager.delegate = self
            locationManager.requestAlwaysAuthorization()
            Radar.startTracking(trackingOptions: .presetResponsive)
            return true
        }
    
        func didReceiveEvents(_ events: [RadarEvent], user: RadarUser) {
            for event in events {
                switch event.type {
                case .userEnteredGeofence:
                    showNotification("You entered \(event.geofence?.description ?? "a geofence")")
                case .userExitedGeofence:
                    showNotification("You exited \(event.geofence?.description ?? "a geofence")")
                default:
                    break
                }
            }
        }
    
        func didUpdateLocation(_ location: CLLocation, user: RadarUser) {
            print("Updated: \(location.coordinate.latitude), \(location.coordinate.longitude)")
        }
    
        func didFail(status: RadarStatus) {
            print("Radar error: \(status)")
        }
    
        private func showNotification(_ body: String) {
            let content = UNMutableNotificationContent()
            content.body = body
            content.sound = .default
            let request = UNNotificationRequest(
                identifier: UUID().uuidString, content: content, trigger: nil)
            UNUserNotificationCenter.current().add(request)
        }
    }
    ```
  </Tab>
  <Tab title="Android">

### Server-side webhooks

For backend workflows — updating databases, triggering fulfillment, sending push notifications via your own service — configure a webhook in the Radar dashboard under **Settings → Webhooks**. Radar will `POST` a JSON payload to your endpoint whenever an event fires.

```json
{
  "type": "user.entered_geofence",
  "createdAt": "2024-03-01T12:00:00.000Z",
```

## Troubleshooting

| Symptom                                   | Likely cause                                      | Fix                                                                                             |
| ----------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| User not appearing on Users page          | SDK not initialized or `trackOnce` not called     | Check `status` in callback — `ERROR_PUBLISHABLE_KEY` means `initialize` wasn't called           |
| Events not firing in background           | Missing background permission or background modes | Ensure `Always` permission is granted; enable Location updates background mode on iOS           |
| Android location delayed 5–10 min         | Doze Mode / Background Location Limits            | Expected Android behavior; use `CONTINUOUS` preset with a foreground service for faster updates |
| `ERROR_PERMISSIONS` on `trackOnce`        | Permissions not yet granted                       | Call permission request flow before `trackOnce`                                                 |
| No events despite being inside a geofence | Geofence not active or wrong tag/externalId       | Verify the geofence is active on the Geofences page and the tag/externalId match                |
