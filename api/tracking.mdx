title: "Tracking API"
description: "Reference for Radar's track and context endpoints, which send a location update and return the user, events, and location context."
---

Use the Tracking API to send a location update for a user and get back the user's current state and any events the update generated, or to get location context for a coordinate without creating a user.

| Operation | Endpoint | Authentication |
| --- | --- | --- |
| [Track](#track) | `POST /v1/track` | Publishable key |
| [Get context](#get-context) | `GET /v1/context` | Publishable key |

The base URL is `https://api.radar.io`. Send your API key in the `Authorization` header. For key types, the error format, and rate limits, see [Authentication, errors, and rate limits](/api/fundamentals).

On iOS and Android, use the [SDK](/sdk/sdk) to track users in the foreground or in the background. The SDK calls these endpoints for you and handles permissions, batching, and offline replay. Call the endpoints directly only when you can't use an SDK, for example from a device or backend that already has a location.

## Track

Tracks a location update. Returns the user and the events generated, depending on your project settings.

- **Endpoint**: `POST /v1/track`
- **Authentication**: Publishable key
- **Rate limit**: 1 request per second per device
- **Used by**: [Detect geofence events and place visits](/geofencing/geofences-and-places), [Track pickups, deliveries, and workers](/geofencing/trips)

`deviceId` identifies logged out users. `userId` and `deviceId` together identify logged in users. If a matching user exists, Radar updates it. If not, Radar creates a new user.

Don't send personally identifiable information, such as a name, an email address, or a publicly available ID, as `userId`.

### Body parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `deviceId` | string | Yes | A device ID for the user. Identifies logged out users. |
| `userId` | string | No | A stable unique ID for the user. Used with `deviceId` to identify logged in users. |
| `latitude` | number | Yes | The user's current latitude. A number between -90 and 90. |
| `longitude` | number | Yes | The user's current longitude. A number between -180 and 180. |
| `accuracy` | number | Yes | The accuracy of the location in meters. A number greater than 0 and at most 1000000. Radar uses it to evaluate the confidence of geofence events. |
| `foreground` | boolean | No | `true` if the client is in the foreground, `false` if the client is in the background. |
| `stopped` | boolean | No | `true` if the user is stopped, `false` if the user is moving. |
| `description` | string | No | A description for the user, displayed in the Radar dashboard. 1 to 256 characters. |
| `metadata` | object | No | Custom metadata for the user. Up to 16 keys, with values of type string, boolean, or number. See [Metadata](/api/fundamentals#metadata). |
| `deviceType` | string | No | The user's device type. One of `iOS`, `Android`, or `Web`. |
| `updatedAt` | ISO 8601 string | No | The client timestamp or historical timestamp of the location update. A date or valid ISO date string. Send historical data in chronological order. Defaults to the current server time if omitted or out of order. |
| `replayed` | boolean | No | `true` if the location is replayed after being stored on the device. Defaults to `false`. |
| `deviceOS` | string | No | The operating system of the device. |
| `deviceMake` | string | No | The manufacturer of the device. |
| `deviceModel` | string | No | The model of the device. |
| `altitude` | number | No | The altitude in meters. |
| `verticalAccuracy` | number | No | The vertical accuracy in meters. |

### Response

A `200` response contains:

| Field | Type | Description |
| --- | --- | --- |
| `meta` | object | The response metadata, including `code`. |
| `user` | object | The updated [user](/api/users#user-object), including location context such as `geofences`, `place`, `country`, `state`, `dma`, `postalCode`, `beacons`, `trip`, and `fraud` when the related features are enabled for your project. |
| `events` | array of objects | The [events](/api/events#event-object) generated by this location update. Empty when the update didn't change the user's state. |

Which context fields and event types you receive depends on your project settings. Region fields require Regions, `place` requires Places, and `fraud` requires Fraud. When user insights are enabled and Radar has inferred a home or work location, `user.locationInsights` is included. See [User object](/api/users#user-object).

To receive the same events on your backend without polling, use [webhooks](/integrations/webhooks).

### Example

This request sends a location update for `user-123` on `device-456`.

```bash
curl "https://api.radar.io/v1/track" \
  -H "Authorization: prj_live_pk_..." \
  -X POST \
  -d "deviceId=device-456" \
  -d "userId=user-123" \
  -d "latitude=40.78382" \
  -d "longitude=-73.97536" \
  -d "accuracy=65"
```

### Errors

| Status | Meaning | What to do |
| --- | --- | --- |
| `400` | A required parameter is missing or a value is out of range. `meta.param` names the parameter, for example `deviceId`, `latitude`, `longitude`, `accuracy`, or `metadata`. | Fix the parameter named in `meta.param`. |
| `401` | The API key is missing or invalid. | Send a valid API key in the `Authorization` header. |
| `429` | More than 1 request per second was sent for the same device, or the request was throttled. | Wait at least 1 second before you send the next update for that device. |
| `503` | Tracking is temporarily unavailable. | Retry with backoff. |

A `400` response looks like this:

```json
{
  "meta": {
    "code": 400,
    "param": "accuracy",
    "message": "accuracy: Param is required."
  }
}
```

## Get context

Gets location context for a coordinate: the geofences that contain it, and the place and regions when those features are enabled. This operation doesn't create or update a user and doesn't generate events.

- **Endpoint**: `GET /v1/context`
- **Authentication**: Publishable key
- **Rate limit**: 100 requests per second
- **Used by**: [Detect geofence events and place visits](/geofencing/geofences-and-places)

In the SDKs, this operation is `Radar.getContext()`.

### Query parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `coordinates` | string | Yes | The coordinates to get context for, in the format `latitude,longitude`. |

### Response

A `200` response contains `meta` and a `context` object:

| Field | Type | Description |
| --- | --- | --- |
| `live` | boolean | `true` if the request used a live key, `false` if it used a test key. |
| `geofences` | array of objects | The [geofences](/api/geofences#geofence-object) that contain the coordinates. Empty if there are none. |
| `place` | object | When Places is enabled, the place at the coordinates. Omitted if there is none. |
| `country` | object | When Regions is enabled, the country for the coordinates. |
| `state` | object | When Regions is enabled, the state for the coordinates. |
| `dma` | object | When Regions is enabled, the DMA (market area) for the coordinates. |
| `postalCode` | object | When Regions is enabled, the postal code for the coordinates. |

Fields for features that aren't enabled, or that have no match at the coordinates, are omitted.

### Example

This request gets context for a coordinate.

```bash
curl "https://api.radar.io/v1/context?coordinates=40.78382,-73.97536" \
  -H "Authorization: prj_live_pk_..."
```

Radar returns this response:


### Errors

| Status | Meaning | What to do |
| --- | --- | --- |
| `400` | `coordinates` is missing or isn't a valid `latitude,longitude` pair. | Fix the request before you retry. |
| `401` | The API key is missing or invalid. | Send a valid API key in the `Authorization` header. |
| `429` | The rate limit was exceeded. | Retry with backoff. See [Rate limits](/api/fundamentals#rate-limits). |
