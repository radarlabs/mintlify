A verified location check returns a geolocation token. Use this reference to verify how the token is signed, read the decoded payload, and interpret identity, product, and expiry. For the validation procedure, see [Validate the response on the backend](/geo-compliance/sportsbooks-and-casinos#validate-the-response-on-the-backend).

<Warning>
  Read fields from the payload only after your backend has verified the signature. A decoded token that isn't verified proves nothing about where the token came from.
</Warning>

## Envelope

The token is a JSON Web Token (JWT) in JWS compact serialization. It has three base64url segments separated by periods:

```text
<header>.<payload>.<signature>
```

The decoded header is:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

| Property | Value |
| --- | --- |
| Signature algorithm | `HS256` (HMAC with SHA-256) |
| Signing key | Your project's JWT secret key, shown under **Fraud** on the [Settings](https://dashboard.radar.com/settings#fraud-settings) page of the Radar dashboard |
| Key identifier (`kid`) | Not present |
| Encryption | None. The payload is signed and readable by anyone who holds the token. |

Reject any token whose header `alg` isn't `HS256`.

## Registered claims

The JWT library you use reads these claims. Both are in seconds since the Unix epoch.

| Claim | Type | Presence | Description |
| --- | --- | --- | --- |
| `iat` | number | Always | When Radar issued the token. |
| `exp` | number | Always | When the token expires. Equal to `iat` plus `expiresIn`. |

## Payload fields

Field names are case-sensitive. The payload can contain fields that aren't listed here, and new fields can be added, so ignore fields you don't use.

### Top-level fields

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `_id` | string | Always | Radar's ID for the location check. |
| `passed` | boolean | Always for a verified check | Whether the user passed all jurisdiction and fraud checks for the current product. |
| `failureReasons` | array of strings | Always for a verified check | Why the check failed. Empty when `passed` is `true`. See [Failure reasons](#failure-reasons). |
| `warningReasons` | array of strings | Always for a verified check | Signals reported without failing the check. See [Warning reasons](#warning-reasons). |
| `expiresIn` | number | Always | Token lifetime in seconds, measured from `iat`. |
| `expiresAt` | string | Always for a verified check | Expiry as an ISO 8601 datetime. See [Expiry](#expiry). |
| `product` | string | When set on the client | The product set with `Radar.setProduct()`. |
| `products` | object | Account-specific | One entry per product configured for your project, each with a `passed` boolean. Present only when per-product results are enabled for your project. |
| `reason` | string | When passed to the check | The check reason you supplied. |
| `transactionId` | string | When passed to the check | The transaction ID you supplied. Radar returns it unchanged and doesn't check it for uniqueness. |
| `user` | object | Always | The user and device the check ran for. See [User fields](#user-fields). |
| `events` | array of objects | Always | Events generated by the check, such as geofence entries. Can be empty. |

### User fields

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `user._id` | string | Always | Radar's ID for the user record. |
| `user.userId` | string | When set on the client | The ID set with `Radar.setUserId()`. Compare it to your authenticated user. |
| `user.deviceId` | string | Always | The device ID. |
| `user.installId` | string | Always | Radar's ID for the app install. |
| `user.live` | boolean | Always | `true` for the Live environment, `false` for the Test environment. |
| `user.location` | GeoJSON geometry | Always | The location of the check, a `Point` in [GeoJSON](https://geojson.org/) format. `coordinates` is `[longitude, latitude]`. |
| `user.locationAccuracy` | number | Always | Accuracy of the location in meters. |
| `user.updatedAt` | string | Always | When the check ran, as an ISO 8601 datetime. |
| `user.metadata` | object | When set on the client | Metadata set with `Radar.setMetadata()`. |
| `user.passed` | boolean | Always for a verified check | Same value as the top-level `passed`. |
| `user.failureReasons` | array of strings | Always for a verified check | Same values as the top-level `failureReasons`. |
| `user.warningReasons` | array of strings | Always for a verified check | Same values as the top-level `warningReasons`. |
| `user.failureReasonMessages` | object | Account-specific | Keyed by failure reason. Each entry can include a `message` to show the user and a `retry` boolean. Present only when failure reason messages are enabled for your project. |
| `user.fraud` | object | Always for a verified check | See [Fraud fields](#fraud-fields). |
| `user.country` | object | When the location is in a known country | See [Country and state fields](#country-and-state-fields). |
| `user.state` | object | When the location is in a known state or province | See [Country and state fields](#country-and-state-fields). |
| `user.geofences` | array of objects | When inside custom geofences | The custom geofences the location is inside, each with `description`, `tag`, and `externalId`. |
| `user.expectedAddress` | object | Account-specific | Result of an expected address comparison, when you call `Radar.setExpectedAddress()` and address verification is enabled. See [Expected address fields](#expected-address-fields). |

### Fraud fields

| Field | Type | Description |
| --- | --- | --- |
| `user.fraud.passed` | boolean | Whether all fraud checks passed. |
| `user.fraud.verified` | boolean | `true` when the request came from a verified location check. |
| `user.fraud.blocked` | boolean | `true` when a block rule matched. Forces `user.fraud.passed` to `false`. |
| `user.fraud.bypassed` | boolean | `true` when a bypass rule matched. Forces `user.fraud.passed` to `true`. Bypass rules are for internal testing only. |
| `user.fraud.mocked` | boolean | The location is mocked or spoofed. |
| `user.fraud.jumped` | boolean | The location moved too far too fast. |
| `user.fraud.compromised` | boolean | The device or app is compromised, for example rooted or jailbroken. |
| `user.fraud.inaccurate` | boolean | The location accuracy is too low to pass verification. |
| `user.fraud.proxy` | boolean | The IP address is a known proxy or VPN. |
| `user.fraud.sharing` | boolean | Screen sharing or remote control was detected. |
| `user.fraud.risk` | number | Risk score for the user and device. Present when risk scores are enabled for your project. See [Fraud overview](/fraud/overview#understand-risk-scores-and-decisions). |
| `user.fraud.usersForThisDevice` | number | Count of user IDs seen on this device. |
| `user.fraud.devicesForThisUser` | number | Count of devices seen for this user ID. |
| `user.fraud.lastMockedAt`, `lastJumpedAt`, `lastCompromisedAt`, `lastInaccurateAt`, `lastProxyAt`, `lastSharingAt` | string | The last time the user failed each fraud check, as an ISO 8601 datetime. Absent when the user hasn't failed that check. |
| `user.fraud.ipAddress` | object | IP geolocation for the request, including `countryCode`, `stateCode`, `city`, and `connectionType`. |
| `user.fraud.privacy` | object | Network privacy flags: `vpn`, `proxy`, `tor`, `relay`, `hosting`, and `service`. |
| `user.fraud.asn` | object | Network operator information: `asn`, `name`, `domain`, `country`, `network`, and `type`. |

Individual flags explain a result. The decision field is `passed`.

### Country and state fields

`user.country` and `user.state` share these fields.

| Field | Type | Description |
| --- | --- | --- |
| `code` | string | Two-letter country code, or state or province code. |
| `name` | string | Display name. |
| `type` | string | `country` or `state`. |
| `allowed` | boolean | Whether this region is allowed in your settings for the current product. |
| `passed` | boolean | Whether all jurisdiction checks for this region passed. |
| `expected` | boolean | Whether the region matches the jurisdiction set with `Radar.setExpectedJurisdiction()`. Can be absent. |

`user.state` also has:

| Field | Type | Description |
| --- | --- | --- |
| `distanceToBorder` | number | Distance to the nearest state or province border in meters. |
| `inBufferZone` | boolean | The location is too close to the border. |
| `inExclusionZone` | boolean | The location is in an exclusion zone, if enabled. |
| `inInclusionZone` | boolean | The location is in a custom inclusion zone, if configured. |

### Expected address fields

| Field | Type | Description |
| --- | --- | --- |
| `expectedAddress` | string | The address you passed to `Radar.setExpectedAddress()`. |
| `formattedAddress` | string | The address as geocoded by Radar. Absent when it could not be geocoded. |
| `latitude`, `longitude` | number | Coordinates of the geocoded address. |
| `atAddress` | boolean | Whether the user is within the distance threshold of the geocoded address. |
| `distance` | number | Distance in meters between the user's location and the geocoded address. |
| `confidence` | string | `high`, `medium`, `low`, or `unknown`. |

## Identity, product, and freshness

Check these four things in the verified payload before you act on `passed`.

- **Identity**: `user.userId` is the value your client set with `Radar.setUserId()`. Radar doesn't authenticate your users, so the token proves which user ID the check ran for, and your backend proves who is making the request. Compare the two on every request.
- **Product**: `passed` applies to the product named in `product`. A token issued for one product doesn't establish eligibility for another. If your project returns `products`, each entry holds the jurisdiction result for that product from the same check.
- **Environment**: `user.live` tells you whether the check ran in the Live or Test environment. In production, accept only tokens with `user.live` set to `true`.
- **Transaction**: `transactionId` is returned exactly as you passed it. Radar doesn't enforce single use. Your backend compares it to the action it is authorizing and records that it has been used.

## Expiry

Each token has its own lifetime. Radar sets it per check based on your product and jurisdiction configuration and the distance to the border, so tokens issued close to a border expire sooner. The default lifetime is 20 minutes, an `expiresIn` of `1200`.

- `exp` is the authoritative expiry for your backend. JWT libraries enforce it.
- `expiresAt` is the expiry as an ISO 8601 datetime, for scheduling and display.
- `expiresIn` is the lifetime in seconds, measured from `iat`. Add it to the time you received the response, not to the current time when you read it later.

Schedule the next check from the returned values. Don't hardcode an interval.

## Failure reasons

When `passed` is `false`, `failureReasons` lists why. Some sensitive or proprietary failure reasons aren't documented here, so handle values you don't recognize with a general message.

| Failure reason | Meaning | Platforms |
| --- | --- | --- |
| `country_not_allowed` | The location is in a country that isn't allowed in your settings. | All |
| `country_not_expected` | The location is in a country that doesn't match `Radar.setExpectedJurisdiction()`. | All |
| `country_in_buffer_zone` | The location is too close to a country border. | All |
| `country_in_exclusion_zone` | The location is in a country-specific exclusion zone, if enabled. | All |
| `state_not_allowed` | The location is in a state or province that isn't allowed in your settings. | All |
| `state_not_expected` | The location is in a state or province that doesn't match `Radar.setExpectedJurisdiction()`. | All |
| `state_in_buffer_zone` | The location is too close to a state or province border, based on a jurisdiction threshold or the accuracy reported by the device. | All |
| `state_in_exclusion_zone` | The location is in a state- or province-specific exclusion zone, if enabled. | All |
| `fraud_blocked_user_id` | The user ID is blocked. | All |
| `fraud_blocked_device_id` | The device ID is blocked. | All |
| `fraud_blocked_ip` | The IP address is blocked. | All |
| `fraud_blocked_mac_address` | The MAC address is blocked. | macOS, Windows |
| `fraud_blocked_risk_score_auto_block` | The user or device was automatically blocked based on a high risk score. | All |
| `fraud_compromised_jailbroken` | The iOS device is jailbroken. | iOS |
| `fraud_compromised_app_attest` | The iOS device failed App Attest checks. | iOS |
| `fraud_compromised_play_integrity_api` | The Android device failed Play Integrity API basic integrity checks. | Android |
| `fraud_mocked_from_mock_provider` | The operating system reports the location as mocked or spoofed. | All |
| `fraud_mocked_known_spoofing_app` | The device is running a known location spoofing app. | macOS, Windows |
| `fraud_mocked_inconsistent_ip_country` | The location is in a country inconsistent with the IP geolocation country. | All |
| `fraud_jumped_single_device` | The location moved too far too fast on one device. | All |
| `fraud_jumped_multiple_devices` | The location is inconsistent with another device using the same user ID. | All |
| `fraud_inaccurate_exceeded_accuracy_threshold` | The location accuracy reported by the device exceeds the allowed threshold. | All |
| `fraud_sharing_known_screen_sharing_app` | The device is running a known screen sharing or remote desktop app. | macOS, Windows |
| `fraud_sharing_multiple_displays` | The Android device has multiple displays. | Android |
| `fraud_sharing_virtual_input_device` | The Android device has a virtual input device. | Android |
| `fraud_proxy_known_proxy_ip` | The IP address is a known proxy or VPN. | All |
| `fraud_proxy_network_configuration` | The network configuration indicates a proxy or VPN. | macOS, Windows |

## Warning reasons

`warningReasons` lists signals that Radar reports without failing the check. A token with warnings can have `passed` set to `true`. Which signals are warnings and which are failures can depend on your project configuration.

| Warning reason | Meaning |
| --- | --- |
| `address_not_expected` | The user isn't at the address set with `Radar.setExpectedAddress()`. Read `user.expectedAddress.atAddress` and `user.expectedAddress.confidence` to decide how to handle it. |

## Fixtures for rejection tests

Two cases that your backend must reject use an authentic token with a passing payload, so they need no separate payload shape:

| Case | How to build the fixture | Expected backend result |
| --- | --- | --- |
| Wrong user | Sign the passed payload and present it in a session for `user-456`. | Deny, because `user.userId` is `user-123`. |
| Expired | Sign the passed payload with `exp` earlier than the current time. | Reject as expired and ask the client for a new check. |

Sign test fixtures with a test-only secret, never with your project's JWT secret key.
